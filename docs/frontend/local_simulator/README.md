# 本地模拟执行器

## 1. 定位

`App.tsx` 里有一套完全前端本地的、确定性的行为树单次执行器。这一块最容易被误读，因为它看起来像“行为树在跑”，但实际上只是浏览器里的演示逻辑。

它的职责是：

- 给查看模式提供可见的执行流演示。
- 驱动节点运行态、时间线和黑板变化。
- 让 UI 联调时能看到“播放中的行为树”。

它当前不承担：

- 真实机器人行为树运行时。
- ROS2 状态接入。
- 网络控制或在线调度。

## 2. 关键实现与行段导读

- `src/App.tsx:14-16`
  - 用 `isPlayingRef` 解决异步执行期间读取过期播放状态的问题。
- `src/App.tsx:18-33`
  - 进入模拟执行 `useEffect`，先检查播放状态、模拟模式和当前树根节点。
- `src/App.tsx:35-166`
  - `executeNode()` 是整个本地执行器的核心。
  - 它按节点类型递归执行 `action / condition / sequence / selector / decorator / subtree`，并在运行过程中更新节点状态、时间线和黑板。
- `src/App.tsx:51-52`
  - 每个节点人为插入约 `800ms` 延迟，只是为了让演示能看见执行过程。
- `src/App.tsx:68-89`
  - 动作节点默认成功，条件节点也默认成功，只有少数硬编码条件会失败，例如 `CheckR1Blocking`、`CheckExitCondition`。
- `src/App.tsx:145-159`
  - 会额外应用被 parser 挂到节点上的装饰器语义，例如 `Inverter`、`RetryUntilSuccessful`、`ForceSuccess`。
- `src/App.tsx:168-197`
  - `runTree()` 会先 `resetTreeState()`，再从当前活动树根节点开始跑，结束后追加“行为树执行完毕”日志并停播。
- `src/store/useStore.ts:104-116`
  - 时间线最多保留 `50` 条，黑板最多保留 `10` 条，这是前端展示裁剪，不是运行时契约。
- `src/App.tsx:205-209`
  - 所谓“实机模式”目前只是在浏览器控制台输出“等待接收真实行为状态”，没有任何网络接入或 ROS2 状态流接入。

## 3. 运行步骤拆解

从页面行为看，这条链路大致是：

1. 页面进入查看模式后，`App.tsx` 挂着当前查看态 store。
2. 用户点击播放，`useEffect` 检查当前是否允许进入模拟执行。
3. `executeNode()` 从当前树根节点递归向下跑。
4. 每执行一个节点，就更新节点状态，并视需要写入时间线和黑板。
5. 树执行结束后，前端写入“执行完毕”日志并停播。

## 4. 维护提示

- 这一块只能被描述为“本地模拟”“本地演示”“浏览器内执行演示”，不能改文档口径把它写成真实行为树执行器。
- 如果以后真要接入实时状态流，应该新增单独 adapter boundary，而不是继续在 `App.tsx` 这套演示逻辑上打补丁冒充在线系统。
- 如果修改了时间线、黑板或节点状态表现，也要同步检查查看态右侧面板是否仍然只是消费展示数据，而不是承担运行时权威。
