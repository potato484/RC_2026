# rc26_xhu_viewer 瘦身执行方案

## 文档定位

这份文档原本用于规划 `rc26_xhu_viewer` 的“默认 headless + status 拆包 + GUI/Web 可选化”路线。

截至当前 fork 的真实实现，这条路线已经结束，并进一步收口成：

- `rc26_xhu_viewer_status` 独立承接 headless 语义聚合
- 系统级魔改 `rviz2` 直接替换当前整机里的 GUI 入口
- `src/rc26_xhu_viewer/rc26_xhu_viewer/` 只保留为 `rviz2` 复用的源码资产 staging 区

本文档现在只记录这次最终收口的实施口径，不再继续维护旧阶段的拆包计划。

## 当前最终方案

### 1. 运行时分层

- `rc26_xhu_viewer_status`
  - 默认随 bringup 常驻
  - 继续发布 `r2/xhu_viewer/*`
  - 不承载 GUI、`.rviz` preset、Web adapter
- `rviz2`
  - 作为当前系统级 GUI 主入口
  - 默认进入 RC26 模式
  - 显式 `--classic` 时回到完整原生 RViz 体验
- `src/rc26_xhu_viewer/rc26_xhu_viewer/`
  - 不再作为 ROS2 包参与 `colcon`
  - 继续存放 RC26 壳层、preset、插件/Web 资产源码

### 2. 直接替换范围

当前这轮“覆盖式安装”的替换面是：

- `rviz2`
- `rviz_common`

其中：

- `rviz2` 负责默认 RC26 入口、`--classic` 兼容入口、RC26 preset 装配
- `rviz_common` 继续保留少量本地 patch，用于支撑壳层覆写和 Display allowlist 注入

以下组件继续沿用现有依赖，不在本轮替换面里继续拆：

- `rviz_default_plugins`
- `rviz_rendering`
- `rviz_ogre_vendor`
- `rviz_assimp_vendor`

## 已落地实现

### 1. `rviz2` 入口行为

- `ros2 run rviz2 rviz2` 默认进入 RC26 模式
- 支持 `--rc26-mode navigation|slam`
- 支持 `--rc26-layout operator|engineering|diagnostic`
- 支持 `--classic` 回切原生 RViz
- 继续兼容旧的 `--mode` / `--layout` 参数口径

### 2. RC26 资产并入方式

当前并入 `rviz2` 的 RC26 资产包括：

- 中文菜单/工具栏壳层
- Display allowlist
- 6 份 `.rviz` preset
- `resources/terminology.yaml`
- 可选 `rc26_xhu_viewer_plugins`
- 可选 Web adapter 与前端资源

这些资产的源码仍暂存于 `src/rc26_xhu_viewer/rc26_xhu_viewer/`，但该目录已添加 `COLCON_IGNORE`，不再作为独立可启动包参与工作区发现。

### 3. bringup / odometry 启动口径

- `rc26_bringup/launch/bringup.launch.py`
  - GUI profile 直接启动 `rviz2`
  - `visualization_backend` 正式收口为 `rviz2|none`
- `rc26_bringup/launch/odometry.launch.py`
  - `odometry_use_rviz:=true` 直接启动魔改 `rviz2`
  - 默认布局为 `diagnostic`
- `rc26_point_lio/launch/point_lio.launch.py`
  - 保留 `rviz` 兼容参数
  - 但当前入口已经固定为 pure headless，不再直接起 GUI

## 为什么不再保留独立 `rc26_xhu_viewer` 包

如果继续保留独立 GUI 包，会同时引入两类长期问题：

- 系统里既有 `rviz2` 又有 RC26 自己的 GUI 二进制，现场入口持续双轨并存
- 整机最终仍然要依赖 `rviz2` 生态，RC26 魔改无法真正退出系统主入口层

因此当前选择是：

1. 保留 `rc26_xhu_viewer_status` 的独立语义边界
2. 把 GUI 壳层和 GUI 资产直接收编进 `rviz2`
3. 让整机直接执行的 `rviz2` 就是 RC26 当前真实 GUI

## 当前维护口径

- 如果改的是 `r2/xhu_viewer/*` 的字段、阈值或聚合语义，改 `rc26_xhu_viewer_status`
- 如果改的是 RC26 GUI 默认行为、菜单、工具栏、Display allowlist、preset 或 `--classic` 兼容逻辑，改 `rviz2`
- 如果改的是 RC26 可选插件或 Web 工具源码，仍在 `src/rc26_xhu_viewer/rc26_xhu_viewer/` 里改，但要把它视作 `rviz2` 的 staging 资产，而不是独立包

## 当前验证建议

建议至少完成以下检查：

```bash
MAKEFLAGS='-j2 -l2' colcon build --executor sequential --parallel-workers 1 --packages-select rviz_common rviz2 rc26_xhu_viewer_status rc26_bringup
```

以及：

1. `colcon list --base-paths src/rc26_xhu_viewer` 中不再出现独立 `rc26_xhu_viewer` 包
2. `ros2 run rviz2 rviz2` 默认进入 RC26 模式
3. `ros2 run rviz2 rviz2 --classic` 保留完整原生 RViz 行为
4. `bringup.launch.py` 的 GUI profile 能直接拉起 `rviz2`
5. `odometry.launch.py odometry_use_rviz:=true` 能直接拉起 `rviz2`
