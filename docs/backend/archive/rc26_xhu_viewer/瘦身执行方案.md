# rc26_xhu_viewer 瘦身执行方案

## 文档定位

这份文档原本用于规划 `rc26_xhu_viewer` 的“默认 headless + status 拆包 + GUI/Web 可选化”路线。

截至当前 fork 的真实实现，这条路线已经结束，并最终收口成：

- `rc26_xhu_viewer_status` 独立承接 headless 语义聚合
- 系统级魔改 `rviz2` 直接替换当前整机里的 GUI 与本地 Web 工具入口
- `src/rc26_xhu_viewer/rc26_xhu_viewer/` 只保留退役包历史资料，不再承担 staging 职责

本文档现在只记录这次最终收口的实施口径，不再继续维护旧阶段的拆包计划。

## 当前最终方案

### 1. 运行时分层

- `rc26_xhu_viewer_status`
  - 默认随 bringup 常驻
  - 继续发布 `r2/xhu_viewer/*`
  - 不承载 GUI、`.rviz` preset、Web adapter
- `rviz2`
  - 作为当前系统级 GUI 主入口
  - 默认进入 RC26 模式
  - 显式 `--classic` 时回到完整原生 RViz 体验
  - 同目录下同时承载 RC26 Web adapter 与前端工程
- `src/rc26_xhu_viewer/rc26_xhu_viewer/`
  - 不再作为 ROS2 包参与 `colcon`
  - 不再存放当前真实 GUI / Web 源码
  - 只保留历史资料与退役 tombstone

### 2. 直接替换范围

当前这轮“覆盖式安装”的替换面是：

- `rviz2`
- `rviz_common`

同时因为 ABI 混装风险，验收构建应连同 `rviz_default_plugins` 一并重编。

## 已落地实现

### 1. `rviz2` 入口行为

- `ros2 run rviz2 rviz2` 默认进入 RC26 模式
- 支持 `--rc26-mode navigation|slam`
- 支持 `--rc26-layout operator|engineering|diagnostic`
- 支持 `--classic` 回切原生 RViz
- 继续兼容旧的 `--mode` / `--layout` 参数口径

### 2. RC26 资产收口方式

当前所有 RC26 GUI / Web 源码都已经并入 `src/rc26_xhu_viewer/rviz2/`，包括：

- 中文菜单/工具栏壳层
- Display allowlist
- 6 份 `.rviz` preset
- `resources/terminology.yaml`
- 可选 `rviz2_rc26_plugins`
- `rviz2_rc26_server.py` 与 `viewer/` 前端

其中这轮模块化还额外完成了两处结构收口：

- `rviz2/src/` 已拆成 `launch_mode`、`classic_mode`、`mode_utils` 和 `rc26/` 模块，不再把 RC26 模式和 classic 模式堆在一个 `main.cpp` 里
- `viewer/` 已拆出 `components/scene`、`features/trace`、`features/live`、`features/viewer`，不再把 Babylon 场景、trace 转换和 live bridge 全塞进 `App.tsx` / `SceneCanvas.tsx`

### 3. Web adapter 与 topo 真源边界

- 根目录本地入口脚本已切到 `start_rviz2_rc26_web.sh`
- adapter 已切到 `src/rc26_xhu_viewer/rviz2/scripts/rviz2_rc26_server.py`
- `render_graph_sim_html.py` 的真源固定在 `src/rc26_topo_nav/scripts/render_graph_sim_html.py`
- GUI / Web 继续消费 `rc26_topo_nav` 的 graph、surface graph、planner CLI 和 sim assets，不反向拥有规划权威

### 4. bringup / odometry 启动口径

- `rc26_bringup/launch/bringup.launch.py`
  - GUI profile 直接启动 `rviz2`
  - `visualization_backend` 正式收口为 `rviz2|none`
- `rc26_bringup/launch/odometry.launch.py`
  - `odometry_use_rviz:=true` 直接启动魔改 `rviz2`
  - 默认布局为 `diagnostic`

## 当前维护口径

- 如果改的是 `r2/xhu_viewer/*` 的字段、阈值或聚合语义，改 `rc26_xhu_viewer_status`
- 如果改的是 RC26 GUI 默认行为、菜单、工具栏、Display allowlist、preset 或 `--classic` 兼容逻辑，改 `rviz2/src/`
- 如果改的是 RC26 可选插件，改 `rviz2/src/rc26/`
- 如果改的是 Web adapter 或前端，改 `rviz2/scripts/` 与 `rviz2/viewer/`
- 不要再把任何新的真实实现塞回退役的 `rc26_xhu_viewer/` 目录

## 当前验证建议

建议至少完成以下检查：

```bash
MAKEFLAGS='-j2 -l2' colcon build --executor sequential --parallel-workers 1 \
  --packages-select rviz_common rviz_default_plugins rviz2 \
  --cmake-args -DBUILD_RVIZ2_RC26_PLUGINS=ON -DBUILD_RVIZ2_RC26_WEB_TOOLS=ON

npm --prefix src/rc26_xhu_viewer/rviz2/viewer test
npm --prefix src/rc26_xhu_viewer/rviz2/viewer run build
python3 -m py_compile \
  src/rc26_xhu_viewer/rviz2/scripts/rviz2_rc26_server.py \
  src/rc26_xhu_viewer/rviz2/scripts/visualization_algorithms.py \
  src/rc26_topo_nav/scripts/render_graph_sim_html.py
```

以及：

1. `colcon list --base-paths src/rc26_xhu_viewer` 中不再出现独立 `rc26_xhu_viewer` 包
2. `ros2 run rviz2 rviz2` 默认进入 RC26 模式
3. `ros2 run rviz2 rviz2 --classic` 保留完整原生 RViz 行为
4. `bash start_rviz2_rc26_web.sh --dry-run` 能解析到新的 `rviz2` 路径
5. `bash docs/test/release/package-release.sh --skip-build` 能产出 `release/rviz2_rc26_web/`
