# Mid-360 雷达驱动 (rc26_mid360_driver)

本模块是针对 RC_2026 赛季 R2 机器人专属定制的 Livox Mid-360 激光雷达驱动程序。该驱动针对高性能边缘计算平台（基于 Qualcomm® QCS8550，AidLux 融合环境）进行了深度的底层通信与数据重组优化，以确保雷达数据的高效、稳定与低延迟传输。

## 模块定位

在 R2 机器人的自动驾驶与位姿融合架构中，激光雷达是感知与建图定位（Point-LIO）的核心传感器。传统的雷达驱动通常存在基于定时器盲发、丢包不可见以及时间戳漂移等问题。本模块通过直接重构底层协议栈，提供了基于事件驱动的帧重组机制与高精度的时间同步保障，为下游算法提供了可靠的数据源。

## 核心特性

本模块在基础驱动之上，进行了以下深度的工程优化（具体实施细节见 MVP 技术方案）：

*   **事件驱动帧重组**：彻底摒弃传统驱动基于定时器的盲目点云聚合发布机制。本驱动优先通过解析底层协议栈中的帧内包裹计数与总帧计数，实现物理帧级别的精准重组；当部分设备固件未正确更新 `frame_cnt` 时，会自动回退到 `lidar_publish_time_interval` 的时间窗口分帧，确保 `/livox/lidar` 仍能稳定输出且不出现半帧抖动。
*   **高精度时序平滑与 PTP 支持**：内置了时间偏移滤波估计算法（NoSync 漂移补偿），在无硬件时间同步条件下也能保证数据时间戳的长期单调与连续。同时全面兼容系统的 gPTP（全局精准时间协议）硬件同步方案。
*   **内存与计算零冗余结构**：对点云内部的数据结构进行了重新排列，使其严格对齐 ROS 2 的标准线格式，消除了逐点拷贝时的计算开销。通过模板化缓存固定字段，消除了每帧数据的重复构建操作。
*   **高吞吐缓冲与溢出保护**：针对系统接收缓冲区进行了配置要求与检查，并在数据积压时提供点数上界保护机制，防止内存在异常网络抖动下发生无界增长。当前 AidLux / QTI 系统建议通过 `/etc/sysctl.conf` 持久化 `net.core.rmem_max=33554432`，避免被 `99-sysctl.conf` 回链配置覆盖。
*   **锁竞争抑制**：针对多线程并发的数据获取流程进行了调度优化，大幅降低了 IMU 等高频传感器的线程锁竞争概率，释放了更多的 CPU 算力给主控节点。

## 节点通信规范

本驱动节点严格遵循 ROS 2 话题通信标准：

*   **订阅的话题**：无（直接监听底层 UDP 网络端口接收硬件数据）。
*   **发布的话题**：提供标准的雷达三维点云话题以及高频的 IMU 惯性测量单元话题。点云话题严格包含空间坐标、反射强度以及逐点时间戳。
*   **参数配置**：支持通过配置文件动态指定本机接收网口地址（`host_ip`）、点云分帧时间窗口（`lidar_publish_time_interval`）以及坐标系等基础网络与变换参数。当前 R2 实机默认使用本机 `192.168.1.50` 接收来自 Mid-360 `192.168.1.140` 的 UDP 数据。
