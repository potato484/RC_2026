# RC26 梅林（MF）导航防“膨胀区陷阱”模式切换需求规格说明书（SRS）

版本：v0.1（草案）  
日期：2026-01-19  
适用范围：src（Nav2 + rc26_terrain + rc26_decision + MCU）  

---

## 1. 背景与核心问题

### 1.1 场景描述
根据主赛规则（`src/rc26_md/主赛规则.md`），梅林（MF）地形由 12 个 1200mm×1200mm 的方块拼成，高度分 200mm、400mm 和 600mm 三级。
机器人在这里面临两个硬性要求：
1. **只能跨，不能下**：在 MF 内部移动时，必须从一个方块跨到另一个方块，绝对不能掉到地上。
2. **有序撤离**：离开 MF 时，允许下 0.2m 或 0.4m 的台阶，但这得听上层决策的指挥。

### 1.2 现状与痛点
现在的配置有几个关键点（参考 `rc26_bringup` 和 `rc26_terrain` 的配置）：
- **混在一起订阅**：Nav2 的 `local_costmap` 把“障碍物”和“跌落风险”都喂给了同一个 `obstacle_layer`，并且都开了膨胀。
- **敏感的跌落检测**：`rc26_terrain` 把 0.15m 以上的落差都算作跌落风险。这意味着 0.2m 的台阶边缘也会被当成危险区域。
- **保守的控制器**：我们的全向控制器（`rc26_omni_controller`）很谨慎，只要碰到膨胀后的内切障碍物代价（INSCRIBED_INFLATED_OBSTACLE），就会立刻刹车。

### 1.3 问题定义：膨胀区陷阱（Inflation Trap）
问题来了：当机器人在方块上准备跨越时，需要贴近边缘。
但因为边缘有一圈 drop 风险点，经过 Costmap 膨胀后，在机器人周围形成了一堵“看不见的高代价墙”。
结果就是：
- **规划器**觉得“四面楚歌”，找不到路。
- **控制器**觉得“前面有墙”，直接刹车。
- 如果点云稍微抖一下，这堵墙还会瞬间变厚，让机器人彻底卡死。

本质上，这是因为**我们把“跨越时可忽略的边缘”当成了“绝对不能碰的硬墙”**。

## 2. 目标与非目标

### 2.1 目标（Goals）
我们需要做到：
1.  **G1. 跨越不卡死**：在该跨越的时候，不要被自己设的 drop 膨胀给吓停了。
2.  **G2. 平时防跌落**：在 MF 上正常溜达或者调整姿态时，边缘必须是禁区，防止真掉下去。
3.  **G3. 下台阶顺畅**：决定离开 MF 下台阶时，也不能被 drop 拦住。
4.  **G4. 兜底要稳**：不管什么模式，只要感知觉得不行（触发 fail-safe 虚拟围栏），必须能强制停车。
5.  **G5. 独立可测**：搞个单元测试，不用上真车也能验证这套逻辑通不通。

### 2.2 非目标（Non-goals）
- 具体的底盘怎么扭过去、电控怎么稳住姿态，不归这文档管（那是底盘/电控的事）。
- 全局地图（Global Costmap）不用太操心 MF 的立体细节，我们只关注局部的安全策略。
- 暂时不讨论怎么抓取矿石，只关注怎么在上面走且不掉下来。

## 3. 总体方案（方案 B：独立 Drop 层）

既然问题出在混在一起，那就把它们分开。

### 3.1 核心思想
**分层管理**：
- **障碍物（Obstacles）**：这是硬道理，什么时候都不能撞。
- **跌落（Drop）**：这是软约束，平时不能碰，但跨越的时候可以“暂时无视”。

**动态切换**：
- **平时（SAFE）**：开启 Drop 层，边缘即悬崖。
- **跨越中（TRAVERSE / EXIT）**：关闭 Drop 层，清理地图，大胆走。

### 3.2 决策与执行的分工
- **决策层**：负责喊口令（“切换到跨越模式”），并指明目标。
- **Nav2/控制器**：负责执行口令，关掉 Drop 层，让路通畅。
- **MCU**：负责闭眼执行具体的跨越动作，并保护机器人不翻车。

## 4. 改动范围

### 4.1 需要动的地方
1.  **Nav2 配置**：把 `local_costmap` 拆成三层：`obstacle_layer`（只看障碍）、`drop_layer`（只看跌落）、`inflation_layer`（膨胀）。
2.  **新节点 `rc26_nav_mode_manager`**：它是“守门员”，专门负责开关 `drop_layer` 和清理地图。
3.  **决策逻辑**：在发动作指令前，记得先呼叫守门员切模式。

### 4.2 不用动的地方
- `rc26_terrain` 算法本身不用改，它只管报风险，怎么用是下游的事。
- 全局规划层面保持原样。

---

## 5. 导航安全模式定义

我们需要定义几种状态，让大家说话在一个频道上：

- **M0: NORMAL（常规）**：不在 MF 上，该咋跑咋跑。
- **M1: MF_SAFE（MF 安全）**：在 MF 上，但没在跨越。这时候 Drop 层必须开着，防跌落。
- **M2: MF_TRAVERSE（MF 跨越）**：正在跨越方块。Drop 层关闭，且地图要清干净。
- **M3: MF_EXIT（MF 撤离）**：正在下台阶离开。Drop 层关闭，地图清干净。

**模式与行为对照表：**

| 模式 | Drop 层 | Obstacle 层 | 膨胀层 | 行为逻辑 |
| :--- | :--- | :--- | :--- | :--- |
| **NORMAL / MF_SAFE** | **开 (Enabled)** | 开 | 开 | 正常避障，边缘是墙 |
| **MF_TRAVERSE / MF_EXIT** | **关 (Disabled)** | 开 | 开 | **关掉 Drop 并清图**，无视边缘风险，但还得避开真实障碍 |

## 6. 功能需求（FR）

### 6.1 Costmap 配置改造
- **FR-01 (MUST) 层级分离**：`local_costmap` 必须明确拆分出 `obstacle_layer` 和 `drop_layer`。前者只看障碍，后者只看跌落。
- **FR-02 (MUST) 动态开关**：`drop_layer` 必须能通过 ROS 参数实时开关，反应要快（<200ms）。
- **FR-03 (MUST) 兜底不能丢**：`rc26_terrain` 发出的“虚拟围栏”（紧急障碍物）必须始终有效。不管 Drop 层开不开，只要有虚拟围栏，车必须停。

### 6.2 模式管理器（rc26_nav_mode_manager）
- **FR-04 (MUST) 提供切换接口**：提供一个 Service，让决策层告诉我要切什么模式（SAFE/TRAVERSE/EXIT）。
- **FR-05 (MUST) 自动清图**：一旦切入通行模式（TRAVERSE/EXIT），**必须自动调用 Nav2 的清图服务**。不清图，旧的膨胀代价还在，切了也没用。
    - *细节*：清图后最好等一次 Costmap 更新，确保地图真的干净了再返回“成功”。
- **FR-06 (MUST) 状态可见**：把当前模式发出来（Topic 或 Diagnostics），方便 RViz 监视和调试。
- **FR-07 (SHOULD) 超时保护**：在跨越模式待太久（比如超过 5 秒）如果还没切回来，强制切回 SAFE 并报警停车。防止决策层挂了，机器人一直处于“裸奔”状态。

### 6.3 决策集成（rc26_decision）
- **FR-09 (MUST) 先切模式，再动身**：绝对不能先发动作指令再切模式，顺序反了就撞墙了。
- **FR-10 (MUST) 完事立马切回**：动作一做完（底盘稳了），马上切回 SAFE。
- **FR-11 (MUST) 失败即急停**：切模式失败、清图失败、动作失败，任何一个环节掉链子，立刻急停并回退到安全模式。

## 7. 接口定义

### 7.1 Nav2 侧
- **参数控制**：`/<ns>/local_costmap/local_costmap/drop_layer.enabled`
- **清图服务**：`/<ns>/local_costmap/clear_entirely_local_costmap`

### 7.2 模式管理器侧（对外）
- **服务名**：`/rc26/nav_safety/set_mode`
    - Request: `mode` (uint8), `timeout` (float), `reason` (string)
    - Response: `success` (bool), `msg` (string)
- **状态话题**：`/rc26/nav_safety/state`

## 8. 实施细节建议

### 8.1 YAML 配置
`local_costmap` 的插件应该长这样：
```yaml
plugins: ["obstacle_layer", "drop_layer", "inflation_layer"]
obstacle_layer:
  plugin: "nav2_costmap_2d::ObstacleLayer"
  observation_sources: terrain_obs  # 只看障碍
drop_layer:
  plugin: "nav2_costmap_2d::ObstacleLayer"
  observation_sources: terrain_drop # 只看跌落
  marking: true
  clearing: false # 建议设为 false，靠清图服务来清理
  enabled: true   # 默认开启
```

### 8.2 决策流程示例（跨越）
1.  **算**：算出目标点。
2.  **切**：`set_mode(MF_TRAVERSE)` -> 等待成功。
3.  **动**：发 `NAV_STAIR_UP` 给 MCU。
4.  **等**：监控 MCU 说“好了”。
5.  **回**：`set_mode(MF_SAFE)`。

## 9. 怎么验证？（MVT 单元测试）

> 目标：不用真车，在电脑上把逻辑跑通。

**测试环境**：
搞个简单的节点，发虚拟的点云（`terrain_drop`），把机器人围一圈。

**测试用例**：
1.  **TC-01 (堵)**：模式设为 SAFE。发虚拟 drop 点云。
    -   *预期*：Costmap 上机器人被红圈包围，无路可走。
2.  **TC-02 (通)**：模式切为 TRAVERSE。
    -   *预期*：红圈消失，Costmap 变干净，路通了。
3.  **TC-03 (防)**：模式切回 SAFE。
    -   *预期*：红圈瞬间回来。
4.  **TC-04 (稳)**：在 TRAVERSE 模式下，发个虚拟**障碍物**（terrain_obstacles）。
    -   *预期*：虽然 drop 关了，但障碍物层还在，红圈必须出现。证明急停功能没丢。

## 10. 潜在风险

- **参数切换不稳定？**：如果 Nav2 动态改参数不灵，可能需要重启 Costmap 节点（下策）。先在集成测试里狂按开关试试。
- **清图瞬间的“致盲”**：清图会把所有层（包括障碍物）瞬间清空。所以切模式的时候，**车必须是停着的**，且切完要稍微等一下（等下一帧点云进来重建障碍物），再发车。
