# RC2026 模块递进测试指令总结

本文档总结从建图→自主导航→攀爬阶梯的递进测试流程和指令，暂不考虑决策部分。

## 测试流程概述

```
建图阶段 (SLAM) 
    ↓
自主导航阶段 (Navigation)
    ↓
攀爬阶梯阶段 (Stair Climbing)
```

---

## 0. 运行前准备（建议）

### 0.1 环境与工作空间
本文档默认你已完成编译并 `source` 了本工作空间（典型 ROS2 overlay）：

```bash
# 例：在新终端中
source /opt/ros/<distro>/setup.bash
source src/install/setup.bash
```

### 0.2 rosbag 回放（可选）
如果使用 rosbag 代替实机传感器输入，建议统一使用仿真时钟：

```bash
# 启动时带上 use_sim_time:=true（各 launch 基本都支持）
ros2 launch rc26_bringup bringup.launch.py use_sim_time:=true ...

# 回放时带 --clock
ros2 bag play <bag_path> --clock
```

## 0.5 模块级增量测试（推荐用于排查）

当你不想一次起全系统、或需要定位到底是哪个模块断链时，可优先用 `rc26_bringup/launch/test_*.launch.py` 做模块单测：

### A. 完整里程计链（驱动→Point-LIO→odom_interface→sensor_scan）
```bash
ros2 launch rc26_bringup test_odometry_chain.launch.py
```
验证要点：
```bash
ros2 topic list | grep -E "(livox|state_estimation|cloud_registered|odom|registered_scan|sensor_scan|odometry)"
ros2 run tf2_ros tf2_echo odom base_link
ros2 topic hz /odometry
```

### B. 仅 odom_interface（Point-LIO → Nav2 友好的 odom/registered_scan）
> 前置：需要已有 `state_estimation` + `cloud_registered`（Point-LIO 运行或 rosbag 回放）。
```bash
ros2 launch rc26_bringup test_odom_interface.launch.py
```
验证要点：
```bash
ros2 topic echo /odom --once
ros2 topic echo /registered_scan --once
```

### C. 仅 sensor_scan（registered_scan + odom → sensor_scan + odometry + TF）
> 前置：需要已有 `odom` + `registered_scan`（一般来自 `rc26_odom_interface`）。
```bash
ros2 launch rc26_bringup test_sensor_scan.launch.py
```
验证要点：
```bash
ros2 topic echo /sensor_scan --once
ros2 topic echo /odometry --once
ros2 run tf2_ros tf2_echo odom base_link
```

### D. 仅 localization（registered_scan → map->odom）
> 前置：需要先验点云（`.pcd`）+ `registered_scan`。
```bash
ros2 launch rc26_bringup test_localization.launch.py prior_pcd_file:=/path/to/map.pcd
```
验证要点：
```bash
ros2 run tf2_ros tf2_echo map odom
```

### E. 仅 omni_controller（Nav2 controller_server 插件）
> 说明：该测试会启动最小化 controller_server（需要正确的 `nav2_params.yaml` 控制器配置）。
```bash
ros2 launch rc26_bringup test_omni_controller.launch.py
```

### F. 手柄遥控（rc26_telecontrol）
> 前置：手柄已连接（通常为 `/dev/input/js0`）。
```bash
# 摇杆模式（默认）
ros2 launch rc26_telecontrol wheeltec_joy.launch.py

# 十字键模式
ros2 launch rc26_telecontrol wheeltec_joy.launch.py control_mode:=dpad
```
验证要点：
```bash
# 检查手柄数据
ros2 topic echo /joy --once

# 检查速度指令输出
ros2 topic echo /cmd_vel_teleop --once

# 推动摇杆，观察速度变化
ros2 topic hz /cmd_vel_teleop
```
**参数说明**：
- `v_linear`: 最大线速度（默认 0.7 m/s）
- `v_angular`: 最大角速度（默认 1.5 rad/s）
- `joy_deadzone`: 摇杆死区（默认 0.1）
- `smoothing_alpha`: 速度平滑系数（默认 0.2）

### G. 里程计融合（rc26_merge_odom）
> 说明：整合轮式里程计 + 达妙IMU + EKF 融合，输出 `/merge_odom`。

#### G.1 完整融合链路
```bash
ros2 launch rc26_merge_odom merge_odom.launch.py
```
验证要点：
```bash
# 检查融合里程计
ros2 topic echo /merge_odom --once
ros2 topic hz /merge_odom

# 检查IMU数据
ros2 topic echo /imu/data --once
ros2 topic hz /imu/data
```

#### G.2 仅 CAN 里程计
```bash
ros2 launch rc26_merge_odom can_odom_only.launch.py
```
验证要点：
```bash
ros2 topic echo /Can_Odom --once
```

#### G.3 仅达妙 IMU
```bash
ros2 launch rc26_merge_odom dm_imu_only.launch.py imu_port:=/dev/ttyACM0
```
验证要点：
```bash
ros2 topic echo /imu/data --once
```

#### G.4 仅轮式里程计（串口）
```bash
ros2 launch rc26_merge_odom wheel_odom_only.launch.py
```
验证要点：
```bash
ros2 topic echo /wheel_odom --once
```

### H. 视觉推理（rc26_vision）
> 前置：RealSense D455 相机已连接。
```bash
ros2 launch rc26_vision vision_test_with_camera.launch.py
```
验证要点：
```bash
# 检查相机图像话题
ros2 topic hz /camera/camera/color/image_raw

# 检查深度图像
ros2 topic hz /camera/camera/depth/image_rect_raw

# 观察终端输出的检测结果（[检测] attr=... dist=... score=...）
```
**参数说明**：
- `vision_config_file`: 模型配置文件路径（默认 `rc26_vision/config/vision_models.yaml`）

### I. 决策系统（rc26_decision）
> 说明：独立测试决策节点（行为树）。
```bash
# 基础启动（不启用视觉）
ros2 launch rc26_decision decision.launch.py

# 启用视觉推理
ros2 launch rc26_decision decision.launch.py enable_vision:=true
```
验证要点：
```bash
# 检查决策节点是否启动
ros2 node list | grep rc26_decision

# 检查行为树状态（如有相关话题）
ros2 topic list | grep decision
```
**参数说明**：
- `params_file`: 决策参数文件（默认 `rc26_decision/config/decision_params.yaml`）
- `tree_file`: 行为树 XML 文件名（默认 `main_tree.xml`）
- `enable_vision`: 是否启用视觉推理（默认 `false`）

## 第一阶段：建图测试 (SLAM)

### 目标
建立环境的点云地图，为后续导航提供先验地图。

### 启动指令

#### 方式一：完整建图启动（推荐）
```bash
ros2 launch rc26_bringup bringup.launch.py \
    slam:=true \
    use_rviz:=true
```
**启动的模块**：
- ✅ 里程计链路（mid360_driver + point_lio + rc26_odom_interface + rc26_sensor_scan）
- ✅ 定位模块（建图模式下发布静态 TF：map → odom）
- ✅ 地形分析模块（rc26_terrain）
- ❌ Nav2导航栈（建图模式下不启动）
- ❌ 导航模式管理器（建图模式下不启动）
- ❌ 决策系统（默认启动，可通过 `use_decision:=false` 关闭）

**适用场景**：完整的建图流程，需要地形分析等上层模块配合

#### 方式二：仅启动里程计链路（用于单独测试）
```bash
ros2 launch rc26_bringup odometry.launch.py \
    use_rviz:=true
```
**启动的模块**：
- ✅ 里程计链路（mid360_driver + point_lio + rc26_odom_interface + rc26_sensor_scan）
- ✅ 静态TF（base_link → livox_frame）
- ❌ 定位模块（不启动）
- ❌ 地形分析模块（不启动）
- ❌ Nav2导航栈（不启动）
- ❌ 其他上层模块（都不启动）

**适用场景**：单独测试里程计功能，调试传感器数据或坐标转换问题

**简单说**：`bringup.launch.py` = 完整系统；`odometry.launch.py` = 只有最基础的里程计部分

### 启动的模块
1. **硬件驱动层**
   - `mid360_driver`: 激光雷达驱动，发布 `/livox/lidar` 和 `/livox/imu`
2. **里程计链路**
   - `point_lio`: LiDAR-IMU里程计，输出 `/state_estimation` 和 `/cloud_registered`
   - `rc26_odom_interface`: 坐标转换（lidar_odom → odom），输出 `/odom` 和 `/registered_scan`
   - `rc26_sensor_scan`: 发布 TF变换（odom → base_link）和 `/sensor_scan`
3. **定位系统（建图模式）**
   - 发布静态 TF变换（map → odom），保持 TF树完整性

### 验证检查点

#### 1. 硬件驱动检查
```bash
# 检查激光雷达数据
ros2 topic hz /livox/lidar
ros2 topic echo /livox/lidar --once

# 检查IMU数据
ros2 topic hz /livox/imu
ros2 topic echo /livox/imu --once
```
**预期结果**: 有稳定的点云和IMU数据输出，频率正常（通常10Hz或更高）

#### 2. 里程计检查
```bash
# 检查里程计数据
ros2 topic hz /odometry
ros2 topic echo /odometry --once

# 检查配准点云
ros2 topic hz /registered_scan
ros2 topic echo /registered_scan --once

# 检查TF变换
ros2 run tf2_ros tf2_echo odom base_link
```
**预期结果**: 
- 里程计数据正常输出
- 点云数据正常
- TF变换存在且数值合理

#### 3. 建图过程检查
在RViz中查看：
- 实时点云扫描（`/livox/lidar`）
- 配准点云（`/cloud_registered`）
- 地图累积效果（如果Point-LIO发布了地图话题）

### 地图保存
建图完成后，需要保存点云地图（`.pcd`）供后续定位使用。

本项目 Point-LIO 配置项在 `src/point_lio/config/mid360.yaml`：
- `pcd_save.pcd_save_en`: 是否保存点云
- `pcd_save.interval`: 保存间隔（`-1` 表示全部帧写入同一个文件）

> 现实现中，PCD 默认输出目录为 `src/point_lio/PCD/`（由编译宏 `ROOT_DIR` 决定）。

Nav2 的二维地图（`.yaml` + `.pgm`）仍需用你们的地图生成流程产出（本仓库默认放在 `rc26_bringup/map/`，也可通过 `map:=...` 指定）。

## 第二阶段：自主导航测试 (Navigation)

### 目标
使用已建立的地图进行定位和路径规划，实现自主导航。

### 前置条件
- 已完成建图阶段，具备点云地图（`.pcd`）和二维地图（`.yaml` + `.pgm`）
- 地图文件路径已知

### 启动指令

```bash
ros2 launch rc26_bringup bringup.launch.py \
    slam:=false \
    prior_pcd_file:=/path/to/map.pcd \
    map:=/path/to/map.yaml \
    params_file:=/path/to/nav2_params.yaml \
    use_decision:=false \
    use_rviz:=true
```

**参数说明**:
- `slam:=false`: 启用导航模式（关闭建图模式）
- `prior_pcd_file`: 点云地图文件路径（用于定位）
- `map`: 二维地图文件路径（用于Nav2导航）
- `params_file`: Nav2 参数文件（不传则用 `rc26_bringup/config/nav2_params.yaml`）
- `use_decision:=false`: 暂时关闭决策系统（专注于导航测试）

### 启动的模块
1. **硬件驱动层**（同建图阶段）
2. **里程计链路**（同建图阶段）
3. **定位系统（导航模式）**
   - `rc26_localization`: 点云重定位，发布 map → odom 变换
4. **地形感知系统**
   - `rc26_terrain`: 地形分析，识别障碍物和跌落风险，发布 `/terrain_obstacles` 和 `/terrain_drop`
5. **导航系统**
   - `Nav2导航栈`: 路径规划和机器人控制
   - `rc26_omni_controller`: 自定义全向控制器（作为Nav2插件）
6. **导航模式管理器**
   - `rc26_nav_mode_manager`: 管理导航安全模式

### 验证检查点

#### 1. 定位系统检查
```bash
# 检查定位节点是否启动
ros2 node list | grep localization

# 检查map → odom变换
ros2 run tf2_ros tf2_echo map odom

# 在RViz中使用 "2D Pose Estimate" 工具设置初始位姿
# 观察定位是否收敛（查看定位节点日志）
```
**预期结果**:
- 定位节点正常运行
- TF变换正常
- 定位能够收敛（配准误差小）

#### 2. 地形感知检查
```bash
# 检查障碍物点云
ros2 topic hz /terrain_obstacles
ros2 topic echo /terrain_obstacles --once

# 检查跌落风险点云
ros2 topic hz /terrain_drop
ros2 topic echo /terrain_drop --once
```
**预期结果**: 
- 障碍物和跌落风险数据正常发布
- 在RViz中可视化，识别效果正常

#### 3. Nav2导航检查
```bash
# 检查 NavigateToPose action
ros2 action list | grep navigate_to_pose
ros2 action info /navigate_to_pose

# 检查 Nav2 相关节点
ros2 node list | grep -E "(bt_navigator|controller_server|planner_server|recoveries_server|local_costmap|global_costmap|map_server)"

# 检查代价地图（在RViz中可视化）
```
**预期结果**:
- `/navigate_to_pose` action server 可用
- 代价地图正常显示
- 全局和局部代价地图都有内容

#### 4. 路径规划测试
在RViz中：
1. 点击 "2D Nav Goal" 工具
2. 在地图上选择一个目标点
3. 观察是否有路径规划结果
4. 观察机器人是否开始移动
```bash
# 检查速度指令
ros2 topic echo /cmd_vel
```
**预期结果**:
- 能够成功规划路径
- 路径合理（避开障碍物）
- 速度指令正常发布

#### 5. 导航模式管理器检查
```bash
# 检查 profile 状态（rc26_nav_mode_manager）
ros2 topic echo /nav_safety_state

# 检查 profile 切换服务
ros2 service type /set_nav_mode
ros2 service list | grep set_nav_mode
```
**预期结果**:
- `nav_safety_state.current_profile` 有值（常用：`normal/safe/mf_traverse/mf_exit/stair_up/stair_down`）
- `set_nav_mode` 服务可用

## 第三阶段：攀爬阶梯测试 (Stair Climbing)

### 目标
测试机器人在需要攀爬阶梯或穿越有高度差地形时的导航能力。

### 前置条件
- 已完成自主导航测试，导航系统正常运行
- 机器人已到达需要攀爬的阶梯附近
- 确认阶梯位置和参数

### 测试流程

#### 步骤1: 确认当前导航状态
```bash
# 检查当前导航 profile
ros2 topic echo /nav_safety_state

# 确认机器人已停止（攀爬前必须静止）
ros2 topic echo /odom  # 检查速度（nav_mode_manager 默认用该话题做停稳判定）
```
**预期结果**: 
- 当前 profile 为 `normal`（或你们的默认 profile）
- 机器人处于静止状态（线速度和角速度接近0）

#### 步骤2: 切换到穿越/台阶 profile（例如 `mf_traverse`）

切换到 `mf_traverse`（或你们实际使用的 `stair_up/stair_down`），用于在关键地形中调整限速、清理 costmap 等策略。

```bash
# 切换到 mf_traverse，10 秒超时（要求机器人已停稳）
ros2 service call /set_nav_mode rc26_interfaces/srv/SetNavMode \
    "{profile: 'mf_traverse', timeout: 10.0, reason: 'test_stair_climbing'}"
```

**参数说明**:
- `profile`: 目标 profile 名称（见 `rc26_nav_mode_manager/config/nav_profiles.yaml`）
- `timeout`: 超时时间（秒）；`>0` 则到期触发回退（按 profile 的 `fallback_profile`）
- `reason`: 切换原因（可选）

**验证切换成功**:
```bash
# 检查 profile 是否切换成功
ros2 topic echo /nav_safety_state --once
```
**预期结果**:
- `current_profile` 变为 `mf_traverse`
- `stop_required=false`、`timed_out=false`（正常状态）

#### 步骤3:（可选）确认环境感知与 costmap 正常
如果切换 profile 会触发清图，建议简单确认障碍物点云在持续刷新：
```bash
ros2 topic hz /terrain_obstacles
```

#### 步骤4: 规划路径通过阶梯/高度差区域

在RViz中：
1. 点击 "2D Nav Goal" 工具
2. 将目标点设置在阶梯的另一侧
3. 观察路径规划结果

```bash
# 检查路径规划结果
ros2 topic echo /plan

# 检查速度指令
ros2 topic echo /cmd_vel
```

**预期结果**:
- 路径规划成功（路径可能经过阶梯）
- 速度指令正常发布
- 机器人开始移动

#### 步骤5: 监控攀爬过程

```bash
# 持续监控机器人状态
ros2 topic echo /odom      # 里程计（nav_mode_manager 停稳判定来源）
ros2 topic echo /odometry  # 下游里程计（含速度信息，供 Nav2/其他模块使用）
ros2 topic echo /nav_safety_state  # profile 状态

# 监控地面高度（如果有相关模块）
ros2 topic echo /base_ground/level  # 楼层信息
ros2 topic echo /base_ground/stair_delta  # 台阶变化
```

**预期结果**:
- 机器人能够移动通过阶梯
- 导航模式保持为穿越模式
- 地面高度信息有变化（如果有相关传感器）

#### 步骤6: 切换回安全模式

完成攀爬后，切回默认/更安全的 profile（恢复限速与相关策略）。

**方式一: 手动切换**
```bash
ros2 service call /set_nav_mode rc26_interfaces/srv/SetNavMode \
    "{profile: 'normal', timeout: 0.0, reason: 'stair_climbing_completed'}"
```
**参数说明**:
- `profile: 'normal'`: 回到默认导航 profile
- `timeout: 0.0`: 不启用额外超时（由 profile 自身 watchdog 配置决定）

**方式二: 等待超时自动切换**
如果设置了超时时间，系统会在超时后自动切换回安全模式。

**验证切换成功**:
```bash
ros2 topic echo /nav_safety_state --once
```
**预期结果**:
- `current_profile` 变为 `normal`（或回退到 `safe`，取决于你们的 profile 配置与超时回退链）

## 故障排查

### 建图阶段问题
- **激光雷达无数据**: 检查网络连接、IP配置
- **里程计漂移大**: 检查IMU标定、传感器同步
- **地图质量差**: 调整Point-LIO参数、增加扫描时间

### 导航阶段问题
- **定位不收敛**: 检查初始位姿设置、点云地图是否正确
- **路径规划失败**: 检查目标点是否可达、代价地图是否正常
- **机器人不动**: 检查速度指令是否发布、底盘驱动是否正常

### 攀爬阶段问题
- **profile 切换失败**: `set_nav_mode` 返回 `success=false` 时，检查 profile 名称是否存在、机器人是否停稳（某些 profile 要求停稳）、以及 Nav2 相关服务是否正常
- **代价地图恢复慢**: 若 profile 触发清图，检查 `terrain_obstacles` 是否在持续刷新，以及 RViz 中 local/global costmap 是否在更新
- **路径规划仍避开阶梯**: 检查代价地图/障碍物点云是否正确反映地形；必要时换用更合适的 profile（如 `stair_up/stair_down`）并降低速度上限

### 手柄遥控问题
- **手柄无响应**: 检查 `/dev/input/js0` 是否存在、`joy_node` 是否启动、手柄是否配对成功
- **速度不稳定**: 调整 `joy_deadzone` 和 `smoothing_alpha` 参数
- **方向错误**: 检查摇杆映射配置（axes 索引）

### 里程计融合问题
- **IMU 无数据**: 检查串口路径（`/dev/ttyACM0`）、波特率（921600）、串口权限
- **CAN 里程计无数据**: 检查 CAN 接口（`can0`）是否 up、电机编码器是否正常
- **融合里程计漂移**: 检查 EKF 参数配置、各传感器时间同步

### 视觉推理问题
- **相机无图像**: 检查 RealSense 连接、USB3.0 端口、`realsense-viewer` 是否能打开
- **推理无输出**: 检查模型路径是否正确、ONNX 文件是否存在、置信度阈值是否过高
- **推理延迟高**: 降低输入分辨率（`input_w`/`input_h`）、使用小模型

### 决策系统问题
- **行为树不执行**: 检查 `tree_file` 路径是否正确、XML 语法是否有误
- **串口通信失败**: 检查 `cmd_serial_port` 配置、串口权限、波特率

## 总结

### 测试流程递进关系
1. **模块级测试**: 单独验证各模块功能（0.5 节）
2. **建图阶段**: 建立环境地图，验证传感器和里程计功能
3. **自主导航阶段**: 验证定位和路径规划，实现基本导航能力
4. **攀爬阶梯阶段**: 验证 profile 切换和特殊地形导航，实现复杂地形通过能力

### 模块级测试索引

### 关键依赖关系
- 建图 → 导航: 需要地图文件
- 导航 → 攀爬: 需要在导航系统正常运行基础上进行 profile 切换
- profile 切换: 某些 profile 需要机器人停稳；若触发清图，需等待 costmap/障碍物数据恢复

### 注意事项
1. 每个阶段完成后要充分验证，确保功能正常再进行下一阶段
2. profile 切换前先确认机器人已停稳（以 `nav_profiles.yaml` 的 `precheck` 配置为准）
3. 攀爬测试需要谨慎，注意安全
4. 测试过程中持续监控系统状态和日志

## RealSense D455（可选：作为本项目传感器组件）

```bash
ros2 launch rc26_bringup realsense_d455.launch.py
```

```bash
ros2 launch rc26_bringup bringup.launch.py use_realsense:=true
```

```bash
ros2 launch rc26_bringup bringup.launch.py use_realsense:=true realsense_serial_no:=\"'YOUR_SERIAL'\"
```
