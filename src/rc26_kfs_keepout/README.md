# rc26_kfs_keepout 模块说明文档

## 1. 模块概述

`rc26_kfs_keepout` 是 R2 自动机器人导航系统中的核心安全与动态避障组件。它的主要职责是接收来自感知层的高频网格状态信息，利用概率模型对场地的离散网格进行阻挡状态估计，并生成代价地图掩码（Costmap Mask）来约束下游 Nav2 规划器的行为。通过动态生成“禁行区（Keepout Zones）”，该模块能有效防止机器人在复杂赛场环境中与动态障碍物或其他实体发生碰撞。

## 2. 核心机制设计

本模块采用了多项优化机制以确保高可靠性和低延迟，重点解决了传感器数据抖动、规划器频繁重规划以及过时信息残留等痛点：

### 2.1 贝叶斯 Log-Odds 状态估计
模块不直接将感知的瞬时结果作为真实状态，而是维护了一套 Log-Odds（对数几率）概率状态图。不同类型的观测结果具有差异化的置信权重：
- **真实阻挡 (R1/R2)**：提供强烈的正向阻挡证据，快速增加对应网格的阻挡概率。
- **疑似阻挡 (FAKE)**：提供较弱的正向证据，较易被后续观测推翻。
- **明确空闲 (NONE)**：提供负向证据，能够主动、快速地降低阻挡概率。

通过这套机制，模块能够在感知噪声中保持稳定，避免错误避障。

### 2.2 状态去抖与按需发布
为了避免网格状态在阈值附近频繁闪烁导致 Nav2 规划器反复重规划：
- **状态驻留去抖**：新的状态变化必须在指定的周期数内保持稳定才会被确认为有效变化，有效过滤掉短时间内的误检瞬态闪烁。
- **脏标志按需发布**：当代价掩码的实际内容发生改变时，模块才会向下游发送更新数据。这种按需发布的策略极大地减少了系统总线上的无意义冗余通信开销。

### 2.3 心跳解耦架构
为了同时满足“按需发布”的低通信开销要求与下游“安全守门员（Gate）”的心跳检测需求，模块将健康状态的通报与实质业务数据的传递进行了解耦。
模块会以固定高频发布独立的心跳信号证明自身健康及模块开关状态；而在业务层面，代价地图掩码则彻底变为事件驱动，仅在必要时才下发。这使得下游决策模块可以在确保链路存活的前提下，无需忍受由于强制高频重发相同掩码而带来的计算浪费。

### 2.4 渐进式软衰减 (Soft TTL)
对于长时间未被更新的网格，模块采用了平滑的渐进式时间衰减机制，取代了直接重置状态的硬性跳变做法。随着无更新时间的延长，历史阻挡状态的衰减速度呈现动态加速曲线。这确保了在信息老化时，代价地图能以平稳柔和的方式释放对应区域，大幅减轻了因状态突变造成的底层轨迹抖动问题。

## 3. 系统交互边界

### 3.1 上游输入
- **感知网络状态**：接收由视觉/雷达融合处理后的特定格式网格检测数据流，包含网格编号、检测类型及基本置信度。

### 3.2 下游输出
- **Costmap Mask**：向 Nav2 的代价地图服务器按需下发格式化的 Keepout Mask，用于设置硬约束不可行区域。
- **模块心跳**：向下游 Decision 决策模块提供固定频率的存活及启用状态证明。
- **系统诊断**：通过标准的 ROS2 Diagnostics 接口定期发布内部的 Log-Odds 阵列数值、衰减时间及工作状态，便于上位机及调试工具进行深度观测。

### 3.3 外部控制接口
模块暴露了一系列服务接口，允许上层决策机进行强制干预：
- **启用/禁用控制**：能够在赛程中动态关闭 Keepout 功能。
- **网格强制释放**：允许在已知安全的情况下，绕过所有的概率推算和去抖动逻辑，立即清空指定网格的阻挡状态，应对极端角点。

## 4. 落地应用场景
本模块作为比赛运行期间的底层保险杠机制，尤其适用于以下场景：
- 复杂拥挤环境下的安全通行保障。
- 有可能引发定位和建图漂移的动态障碍物的即时响应。
- 通过引入历史状态平滑衰减，解决局部视野丢失带来的短期“盲目”风险。
