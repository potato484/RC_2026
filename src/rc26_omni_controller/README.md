# rc26_omni_controller

`rc26_omni_controller` 是一个专为四驱麦克纳姆轮底盘设计的全向局部路径跟踪控制器。该控制器基于纯跟踪（Pure Pursuit）算法的框架进行扩展，并结合了物理运动学模型与动态避障策略，旨在提高机器人在复杂路线下的循迹精度以及在动态环境中的安全性。此模块完全遵循 ROS 2 的标准设计，并作为 Nav2 导航栈中的一个局部规划器（Controller）插件来运行。

## 模块背景与目标平台

此模块主要针对 R2 自动机器人（基于 Qualcomm QCS8550 平台，运行在 Android 13 与 Ubuntu 22.04 深度融合环境）设计。R2 机器人使用麦克纳姆轮以获得全向移动能力，为了充分发挥这种硬件优势并克服传统纯跟踪在转弯时的内切/外甩缺陷，该控制器引入了多轴独立的矢量加速度控制以及基于切线追踪的修正策略。

## 核心特性

本控制器在经典的跟踪控制基础上做了如下几项重要的改进与特性增强：

### 1. 矢量加速度独立限幅
与传统的将线加速度和角加速度混合统一限幅的做法不同，此控制器对 X 轴（纵向）和 Y 轴（横向）的加速度进行独立的限幅控制。这充分兼顾了麦克纳姆轮在纵向推进与横向平移时的摩擦力差异，允许机器人在不同轴向上发挥最佳动态性能而不易打滑。

### 2. 切线跟踪与横向误差修正
为了解决纯跟踪算法在应对大曲率弯道时存在的内切问题，本算法引入了路径切线跟踪模型。控制器在找寻前视目标点（Carrot Pose）的同时，会计算出目标点的切向向量并测量当前位置到切线的法向误差（横向偏差）。通过针对横向误差的比例增益控制进行修正，极大提高了全速圆弧路径上的循迹紧密度，并有效抑制了转弯外甩情况。

### 3. 曲率前馈角速度控制
为了解决控制器在弯道时的角速度欠补偿问题，本控制器对路径前方范围进行了曲率预测。它基于预估曲率与当前线速度计算前馈角速度，并叠加到原有的航向 PID 调整结果上，使底盘能够更积极且平滑地响应转向命令，减少控制延迟和滞后。

### 4. 连续渐进制动模型
控制器的碰撞检测采用了更具物理含义的渐进制动模型取代了以往在全速与紧急抱死间的二元跳变策略。控制器会在每一个周期查询地图快照并计算到最近障碍物的物理距离。一旦障碍物进入特定区域，便根据给定的安全余量和允许制动加速度，动态计算出当前所能允许的“安全速度上限”（v_safe）。当距离进一步缩小触及安全底线时，才会抛出异常让 Nav2 触发行为树恢复。此设计可大幅减小由动态障碍引起的底盘抖停现象。

### 5. 单次持锁全量地图快照
考虑到在碰撞检测中频繁读写地图数据可能引发死锁和增加计算耗时，本设计在一个控制周期内对 Costmap 进行一次原子化的高速全图快照拷贝。周期内的后续所有防碰撞查询与计算全部基于此快照的顺序内存访问执行。这极大地优化了内存 cache 命中率，使得复杂的路径离散验证单帧耗时能严格控制在低延迟标准内。

### 6. 单帧 TF 矩阵批量变换
为减少逐点遍历带来的高额坐标系转换开销，控制器每一帧只执行一次 TF 查表获取全局坐标系到机体坐标系的变换矩阵。然后通过单纯的矩阵乘法将其批量应用到前视路径所有离散点上，大大降低了局部规划的总体耗时。

## 模块结构与使用

`rc26_omni_controller` 本质上提供了一个遵守 `nav2_core::Controller` 接口的动态链接库，使用时需通过 `nav2_params.yaml` 中的参数进行注册与调用。相关参数配置（包括独立加速度上限、横向误差修正增益、制动安全参数等）全面支持在线动态调节（Dynamic Parameters），方便工程师针对具体的比赛现场地面材质进行快速的实车标定。

如果需要了解关于本模块的具体编译、运行测试以及实时调试等技术细节，请参阅本模块 `docs/` 目录下的调试指南文档。
