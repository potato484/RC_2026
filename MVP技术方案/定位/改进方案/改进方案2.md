# RC_2026 R2 定位系统改进方案 2

**基于**: claude-思考1.md + codex-思考1.md 综合分析
**日期**: 2026-02-18
**前提**: 改进方案1（I1冻结门控、I2重试区快速通道、I3亚克力过滤）已落地
**聚焦**: 全局重定位链路冗余消除（参数级 + 架构级）

---

## 核心判定

> **全局重定位链路的根本矛盾**：ISS+FPFH+SAC-IA 是为"完全未知位置"场景设计的通用全局搜索算法，而 ROBOCON 2026 的实际重定位场景高度确定——启动位置已知（init_pose），重试位置已知（I2 快速通道）。"完全未知位置"在规则框架内几乎不会发生，当前链路的冗余与高耗时源于此根本错配。

---

## 1. 新增诊断（改进方案1 未覆盖）

### 1.1 ISS 关键点：必然 fallback，纯浪费

**代码位置**: `localization.cpp:763-800`

ISS（Intrinsic Shape Signatures）通过协方差矩阵特征值比筛选显著点。在 0.5m 降采样 + 12m×12m 平整室内场地下：

| 几何元素 | ISS 响应 | 原因 |
|---------|---------|------|
| 方块顶面 | 无（平面）| `λ₂/λ₁ ≈ 1, λ₃/λ₂ ≈ 0`，不满足显著性阈值 |
| 方块垂直边缘 | 几乎无 | 4 条边完全相同，0.5m 降采样后每条边仅余 0~1 点 |
| 地面 | 无（平面）| ISS 无输出 |

代码已有 fallback（`localization.cpp:796`：关键点 <30 则回退全点云 FPFH）。**此 fallback 在实战中将必然触发**，ISS 步骤成为纯计算开销：

```
ISS 计算（~200ms）→ 关键点 < 30 → fallback 到全点云 → FPFH 计算（~300ms）
```

关闭 ISS，直接使用全点云 FPFH，节省 ~200ms，行为完全等价。

---

### 1.2 NDT 中间层：与 ICP 功能重叠，串行放大代价

**代码位置**: `localization.cpp:875-914`

当前链路对每个候选执行：`SAC-IA → NDT(50iter) → ICP(100iter)`。

NDT（1.0m 体素分辨率）和 ICP（point-to-point）在 0.5m 降采样稀疏点云上功能高度重叠：
- SAC-IA 质量好（误差 <1m）→ 单轮 ICP 可收敛，NDT 多余
- SAC-IA 质量差（误差 >2m）→ 1.0m 体素 NDT 无法区分 1.2m 间距方块，无法挽救

**当前 `num_yaw_hypotheses=8` 下的串行代价（QCS8550 保守估计）**：

| 步骤 | 单次耗时 | ×8 候选 | 合计 |
|------|---------|--------|------|
| ISS（必然 fallback） | ~200ms | ×1（非候选循环） | ~200ms |
| 法向量 + FPFH（全点云）| ~450ms | ×1 | ~450ms |
| SAC-IA（randomness=50）| 1~5s | ×1 | 1~5s |
| NDT（50iter each）| ~250-500ms | ×8 | 2~4s |
| ICP（100iter each）| ~250-500ms | ×8 | 2~4s |
| **总计最坏情况** | | | **~6~14s** |

15s 重试窗口约束下，最坏情况已临界。关闭 NDT 并将候选数从 8 降至 4，可将此段从 ~6~14s 压缩至 ~3~5s。

---

### 1.3 FPFH 在重复纹理下的固有可靠性上限

赛场几何结构高度重复：
- 12 个方块，水平截面完全一致，仅高度差异（200/400/600mm）
- 红蓝半场存在镜像对称
- 动态遮挡（对方机器人、KFS）随机改变局部几何

FPFH 是局部法向量直方图描述子，在此场景中：
- 所有方块垂直面：相同 FPFH 分布（平面点）
- SAC-IA `correspondence_randomness=50`：随机采样内部50次，高错误匹配率
- 粗配准结果误差 >2m 的概率非可忽略

这是算法层面的固有上限，无法通过调参根本解决，中期须以全局场景描述子替换。

---

### 1.4 `join()` 阻塞配准定时器（已知风险，记录监控）

`performRegistration()` 在 2Hz 定时器中调用 `global_reloc_thread_.join()`（`localization.cpp:495, 567`），阻塞定时器线程直至重定位完成。重定位期间（最坏情况 ~14s），配准定时器完全停止，仅靠 20Hz 的 `publishTransform()`（旧值）维持 TF。

此为当前设计的已知妥协，改进方案2 不引入大规模重构，但在验收指标中纳入监控。P0 优化后该风险窗口从 ~14s 缩短至 ~3~5s。

## 2. P0：立即参数优化（无需改代码，< 30 分钟）

**目标**：将全局重定位最坏情况从 ~14s 压缩至 ~3s，不影响 I2 快速通道（I2 优先于全局链路执行，不受候选数影响）。

### 2.1 前置硬门槛：I2 必须可用

若 `retry_zone_enable=false` 或重试区坐标未标定，P0 的大部分收益在比赛中无法兑现（强制重试后仍会落到慢路径）。

**赛前硬校验清单（必须全部满足）**：

| 项目 | 目标值 | 判定标准 |
|------|--------|---------|
| `retry_zone_enable` | `true` | 启动日志出现“尝试重试区快速通道” |
| `retry_zone_x/y` | 标定实测值 | 与地图坐标系一致，误差 < 0.3m |
| `retry_zone_yaw_candidates_deg` | 2~4 个候选 | 含实际入场朝向，避免无意义穷举 |
| `retry_zone_fast_accept_th` | `0.10~0.18` | bag 回放中误接受率可控 |

**建议补充（代码层 fail-fast）**：
- 比赛模式下，若 `retry_zone_enable=false`，节点启动直接报错退出，避免“带病参赛”。
- 比赛模式下，若 `retry_zone_x/y` 仍为默认占位值，节点启动报错并拒绝进入 READY。

### 2.2 参数改动

**修改文件**：`src/rc26_bringup/config/localization.yaml`

```yaml
# 关闭 ISS：必然 fallback，纯计算浪费，节省 ~200ms
use_iss_keypoints: false            # true → false

# 关闭 NDT 中间层：与 ICP 功能重叠，节省 2~4s
use_ndt_refinement: false           # true → false

# 减少候选数：串行耗时线性减半
num_yaw_hypotheses: 4               # 8 → 4

# 减少 ICP 迭代：平衡精度与耗时（初值好时 50 iter 足够收敛）
global_icp_max_iterations: 50       # 100 → 50

# 降低 FPFH 和 SAC-IA 计算负担
sac_ia_fpfh_ksearch: 30             # 50 → 30
sac_ia_correspondence_randomness: 20 # 50 → 20
```

**预期效果**：

| 场景 | 改前（最坏）| 改后（预估）|
|------|-----------|-----------|
| I2 重试区快速通道 | ~1~2s | ~0.5~1s（ICP 迭代减半）|
| 全局搜索（ISS+FPFH+SAC-IA 路径）| ~6~14s | ~3~5s |
| join() 阻塞窗口最坏情况 | ~14s | ~5s |

**注意**：`sac_ia_correspondence_randomness` 和 `sac_ia_fpfh_ksearch` 的降低会同步降低 SAC-IA 粗配准质量，但由于 FPFH 在重复纹理下本就可靠性有限（1.3节），此折中可接受。

## 3. P1：三层恢复架构重构（中期，~1~2周）

### 3.1 架构设计

将当前五级串行链路（ISS→FPFH→SAC-IA→NDT→ICP）重构为三层：

```
L0: 正常跟踪（small_gicp 局部配准，2Hz，保留不变）
         │
         │ freeze_update_err / min_inliers 冻结门控（改进方案1已落地）
         │ 连续高误差 → L1
         ▼
L1: 快速恢复（重试区先验 ICP，改进方案1已落地）
    先验位姿 (x_retry, y_retry, yaw_k) × 2~4 候选
    → small_gicp ICP 精配准（直接复用 register_ 对象，无 NDT）
    → score < fast_accept_th → 回 L0
    → 失败 → L2
         ▼
L2: 全局恢复（Scan Context 检索 + small_gicp 精配准）
    [离线] 节点启动时从先验地图构建 Scan Context 数据库
    [在线] 当前扫描查询 TopK 候选（K=3~5，含偏航角估计）
    → 对 TopK 逐个 small_gicp ICP 精配准（直接复用 register_ 对象）
    → 成功 → 回 L0
    → 全失败 → RELOC_FAILED（等待外部 initialpose）
```

当前 ISS+FPFH+SAC-IA 链路退出主路径，可作为最终兜底保留（参数关闭状态）或完全移除。

---

### 3.2 Scan Context 替换 ISS+FPFH+SAC-IA

**选择理由**：Scan Context 将 LiDAR 扫描投影为极坐标 BEV 高度矩阵，描述的是场景全局布局而非局部法向量，对重复纹理的鲁棒性优于 FPFH。

| 指标 | ISS+FPFH+SAC-IA | Scan Context |
|------|-----------------|--------------|
| 在线查询耗时 | 1~5s（SAC-IA 为主）| <50ms（ring-key 哈希）|
| 旋转歧义处理 | 多假设穷举（昂贵）| 列移位内置（O(N)）|
| 对重复纹理鲁棒性 | 差（局部描述子歧义）| 中等（全局 BEV 布局）|
| 偏航角估计 | 无（依赖多假设枚举）| 内置（列移位恢复）|
| 外部依赖 | 无 | `scan_context` 头文件库（MIT），ROS2 化版本已有 |

**实现要点**：

```
节点启动（prepareTargetMap() 完成后，离线一次性）：
  → 将先验地图点云分块，模拟多个机器人视角的虚拟扫描
  → 每帧计算 SC 描述子 + ring-key（列均值向量）
  → 构建 ring-key KD-Tree 索引（O(1) 候选检索）

L2 触发时（在线，<50ms）：
  → 对当前扫描计算 SC 描述子
  → ring-key 检索 TopK 候选位置
  → 列移位计算偏航角偏差（无需多假设枚举）
  → TopK 候选送入 small_gicp ICP（直接复用现有 register_ 对象）
```

**复用现有代码**：精配准阶段直接调用已初始化的 `small_gicp::Registration` 对象，无需引入 PCL ICP，与 L1 快速通道共用相同精配准路径。

---

### 3.3 NDT 条件触发（替代当前默认开启）

若保留 NDT 作为精配准补充（而非默认开启），触发条件：

```
after_sac_ia():
  if sac_ia_fitness > ndt_trigger_threshold:    # 粗配准残差高
    run NDT(init=sac_transform)                  # 扩大收敛域后再 ICP
  else:
    skip NDT, run ICP directly
```

典型门槛：`ndt_trigger_threshold ≈ 0.5`（fitness_score 单位）。此策略避免"每个候选都跑 NDT+ICP"的串行爆炸。

---

### 3.4 候选统一打分函数（补充）

为避免“只按 ICP fitness 选最优”导致误收敛，建议统一代价函数：

```text
J = wf * (fitness / fitness_th)
  + wxy * (Δxy / xy_th)^2
  + wyaw * (Δyaw / yaw_th)^2
```

建议初值：
- `wf=0.5, wxy=0.3, wyaw=0.2`
- `fitness_th=global_fitness_threshold`
- `xy_th=retry_zone_max_xy_offset`
- `yaw_th=retry_zone_max_yaw_offset_deg`

接受条件建议：
- `J < 1.0` 且 `fitness < fitness_th`
- 若 `0.9 <= J <= 1.2`，进入“条件 NDT + 二次 ICP”复核

该策略可统一 L1 与 L2 的候选筛选规则，减少策略分叉。

---

### 3.5 非阻塞重定位执行模型（替代 join 阻塞）

当前 `performRegistration()` 内 `join()` 会阻塞 2Hz 定时器。建议改为“请求-队列-工作线程”：

```text
performRegistration():
  if detectKidnapping() or timeout():
    requestReloc(reason)   # 仅置位/入队，不阻塞
    return

relocWorker():
  while running:
    wait(request)
    run L1/L2
    publish result + metrics
```

关键约束：
- 同时最多 1 个重定位任务（后续请求只更新 reason，不重复并发）。
- 主线程永不 `join()`，保持 2Hz 健康监控和冻结门控持续运行。
- 完成后统一回写 `last_successful_registration_time` 和状态机状态。

## 4. P1：统一状态机

将当前分散的 3 个 `atomic bool`（`is_kidnapped_`、`global_reloc_running_`、`map_to_odom_reliable_`）整合为单一枚举状态：

```cpp
enum class LocalizationState {
    TRACKING,         // 正常配准，TF 可信
    SUSPECT,          // 误差升高，TF 冻结更新，计数中
    FAST_RECOVERY,    // L1 重试区快速恢复进行中
    GLOBAL_RECOVERY,  // L2 全局检索恢复进行中
    RELOC_FAILED,     // 全链路失败，等待外部 initialpose
};
```

**状态转换输入（统一）**：
- `normalized_error`（每帧局部配准）
- `num_inliers`（每帧局部配准）
- `time_since_last_success`
- `retry_zone_available`（是否配置有效重试区坐标）

**收益**：
- 消除 3 个 atomic bool 之间的竞态可能（`is_kidnapped_` 为 true 但 `global_reloc_running_` 已完成等竞态）
- 绑架检测、超时恢复、I1/I2/L2 路径从分散 if-else 升级为状态行为
- 状态转换图可以完整描述、测试和调试

## 5. QCS8550 平台参数基线

基于 QCS8550（1+4+3 Kryo CPU、Adreno 740、48 TOPS NPU，PCL+OpenMP，无 GPU/NPU 加速接入）：

| 参数 | 当前值 | P0 基线 | 说明 |
|------|-------|--------|------|
| `num_threads` | 4 | 4（可试 5）| 锁定大核预算，避免调度到小核引入抖动 |
| `use_iss_keypoints` | true | **false** | P0 立即关闭 |
| `use_ndt_refinement` | true | **false** | P0 立即关闭 |
| `num_yaw_hypotheses` | 8 | **4** | 候选减半，耗时线性压缩 |
| `global_icp_max_iterations` | 100 | **50** | 平衡时延与精度 |
| `ndt_max_iterations` | 50 | 20~30（仅条件触发时）| 保留为条件触发兜底 |
| `sac_ia_fpfh_ksearch` | 50 | **30** | 降低 FPFH 计算负担 |
| `sac_ia_correspondence_randomness` | 50 | **20** | 控制 SAC-IA 随机开销 |

**工程建议**：
- launch 层做 CPU 亲和性控制：将 `rc26_localization` 固定到大核，视觉线程走 NPU/GPU（AidLite），避免抢 CPU 大核
- 赛前监控热降频：重定位尾延迟突然增大通常是热降频的前兆信号

### 6.1 验收执行细则（补充）

每次重定位必须输出统一日志字段（CSV 或结构化日志）：
- `trigger_reason`（kidnap/timeout/manual）
- `path_used`（L1/L2/fallback）
- `t_total_ms`
- `t_l1_ms`、`t_global_ms`
- `candidate_count`
- `best_fitness`
- `best_J`
- `accepted`（0/1）

bag 回放至少覆盖 3 类场景：
1. 正常跟踪 + 短时动态遮挡（不应误触发）
2. 强制重试回 RZ（应优先命中 L1）
3. RZ 初始化偏差 + 遮挡（L1 失败后应稳定降级 L2）

通过门槛：
- L1 命中场景：`P95(t_total_ms) < 800ms`
- 全局场景：`P95(t_total_ms) < 5000ms`
- 误触发率：每 10 分钟回放 `<= 1 次`

## 7. 明确不做

| 方案 | 拒绝理由 |
|------|---------|
| 保留 NDT 作为默认开启 | 与 ICP 功能重叠，0.5m 降采样下收益不明确，时延代价确定 |
| ISS 调参（而非关闭）| 0.5m 降采样 + 重复纹理下调参无法改变 fallback 必然性 |
| 粒子滤波（MCL）替代状态机 | 实现复杂度高，"已知位置"先验使得粒子滤波收益有限 |
| 在 P0 阶段完成异步队列重构 | P0 目标是参数止血；异步改造纳入 P1，与状态机合并落地 |
| BEVPlace++/神经网络描述子 | 需预训练模型，部署门槛高，当前赛季风险不值 |
