## 1. 参考源 A/B 必采纳亮点清单

### 1.1 来自 A（`claude-思考3.md`）

1. KFS 占位禁行必须闭环到 Nav2（仅几何地形不够）。
2. `h_obstacle_m=0.33m` 形成“入口需经 200H 中转”的隐式约束，必须现场量测验证。
3. `h_above` 会导致 KFS 侧面格误标，需附加抑制条件。
4. 跨台阶 EMA 迟滞应做跳变快速收敛。

### 1.2 来自 B（`codex-思考3.md`）

1. 邻域应由 8 邻域改为 4 邻域以匹配“公共边相邻”。
2. 需要对象级噪点抑制（最小连通域过滤）。
3. 性能瓶颈在全量遍历和点云拷贝链，需 active cells + 拷贝链瘦身。
4. `unknown_policy` 与模式联动必须落地。
5. 需显式延迟诊断字段，形成可验收的性能证据。

         +------+------+
         | local_costmap |

         +------+------+
                ^
                |
+---------------+------------------------------+
| KfsBlockFuser (新增)                          |
| 输入: KFS 检测结果                            |
| 输出: keepout_filter map / KFS mask           |
+---------------+------------------------------+
                ^
                |
+---------------+------------------------------+
| TerrainModeAdapter (新增)                     |
| 订阅 nav_safety_state                         |
| 调用 terrain 动态参数接口                     |
| (unknown_policy / drop_forward_sector_deg)    |

                ^

设计原则：
1. `nav_mode_manager` 只做 profile 切换与看门狗，不直接耦合 terrain 细节。
2. `TerrainModeAdapter` 承担模式到参数映射，避免双向硬编码。
3. KFS 禁行由 `keepout_filter` 主链路承载；terrain 虚拟点注入仅作为备用。

## 3. 规则闭环的数学化定义

### 3.1 邻域与障碍归属（修正规则冲突）

规则要求“公共边相邻”，定义 4 邻域：

\[
\mathcal{N}_4(i)=\{j\mid |x_j-x_i|+|y_j-y_i|=1\}
\]

地面高差：

\[
\Delta z_{i\rightarrow j}=z_g(j)-z_g(i)
\]

障碍判定与归属：

\[
\text{if } \Delta z_{i\rightarrow j}>h_{obs},\; \text{mark}(j)=\text{obstacle}
\]

说明：标记高侧单元 `j`，而不是低侧 `i`，避免把可接近通道误封死。

### 3.2 跌落判定（安全优先可保持 8 邻域）

\[
\Delta z^-_i = \min_{j\in\mathcal{N}_{drop}(i)}\Delta z_{i\rightarrow j}
\]

\[
\text{drop}(i)=\mathbb{I}[\Delta z^-_i < -h_{drop}]
\]

其中 \(\mathcal{N}_{drop}\in\{\mathcal{N}_4,\mathcal{N}_8\}\) 可配置，MF 高风险阶段推荐 `edge8`。

### 3.3 坡道干扰补偿（新增）

进入/离开 MF 坡道时，地面估计受俯仰影响。对每个点做一阶姿态补偿：

\[
z_{comp}=z_{raw}-x_{rel}\tan(\theta_{pitch})-y_{rel}\tan(\theta_{roll})
\]

当 \(|\theta_{pitch}|>\theta_{ramp}\) 或 \(|\theta_{roll}|>\theta_{ramp}\) 时启用（建议 \(\theta_{ramp}=4^\circ\)）。

### 3.4 KFS 占位概率融合（新增）

对每个方块 \(b\) 维护 log-odds：

\[
L_t(b)=L_{t-1}(b)+\log\frac{P(d_t\mid KFS)}{P(d_t\mid\neg KFS)}
\]

\[
P_t(b)=\sigma(L_t(b))=\frac{1}{1+e^{-L_t(b)}}
\]

决策门限：

\[
\text{forbidden}(b)=\mathbb{I}[P_t(b)>\tau_{kfs}],\; \tau_{kfs}=0.7
\]

作用：把“规则禁踩”从硬编码条件升级为可抗抖的概率状态。

### 3.5 动态遮挡鲁棒项（R1 视作干扰体）

对时变目标采用时间窗抑制：

\[
\text{stable}(c)=\mathbb{I}\left[\sum_{k=t-K+1}^{t} \mathbb{I}[c\in\text{obs}_k] \ge m\right]
\]

推荐 `K=5, m=3`，仅稳定出现的格子进入障碍输出，短时穿越遮挡不触发路径重规划风暴。

## 4. 20ms 时延预算与复杂度

### 4.1 硬约束

\[
T_{e2e}=T_{tf}+T_{transform}+T_{voxel}+T_{grid}+T_{class}+T_{publish}+T_{ros}
\]

终审指标：

\[
\mathrm{P95}(T_{e2e}) \le 20\text{ ms}
\]

### 4.2 分阶段预算（QCS8550）

| 阶段 | 预算(ms) | 关键动作 |
|---|---:|---|
| TF 查询 + 位姿解算 | 1.5 | `lookupTransform` + yaw 提取 |
| 点云变换/下采样 | 4.0 | transform + voxel |
| 栅格投影 | 4.0 | 点到 cell 映射 |
| 分类与迟滞 | 5.0 | 4 邻域 obstacle + 8 邻域 drop |
| 输出与发布 | 3.0 | `toROSMsg` + publish |
| ROS 调度余量 | 2.5 | 回调排队和抖动缓冲 |
| **总计** | **20.0** | **满足硬约束** |

### 4.3 复杂度对比

当前（近似）：

\[
\mathcal{O}(N_p)+\mathcal{O}(8N_c)+\mathcal{O}(8N_c)
\]

优化后（active cells）：

\[
\mathcal{O}(N_p)+\mathcal{O}(4N_a)+\mathcal{O}(4N_a),\; N_a\approx0.35N_c
\]

当 \(N_a/N_c=0.35\) 时，分类相关计算量约下降 65%。

## 5. 接口契约与解耦（按现实现校正）

### 5.1 真实接口（必须与代码一致）

| 模块 | 接口名 | 类型 | 约束 |
|---|---|---|---|
| nav_mode_manager | `set_nav_mode` | `rc26_interfaces/srv/SetNavMode` | 请求字段为 `profile/timeout/reason` |
| nav_mode_manager | `nav_safety_state` | `rc26_interfaces/msg/NavSafetyState` | 1Hz 发布 `current_profile/stop_required/timed_out` |
| rc26_terrain | `terrain_obstacles` | `sensor_msgs/msg/PointCloud2` | 供 `obstacle_layer` |
| rc26_terrain | `terrain_drop` | `sensor_msgs/msg/PointCloud2` | 供 `drop_layer` |
| rc26_terrain | 参数服务 | `rcl_interfaces/srv/SetParameters` | 动态切换 `unknown_policy`/`drop_forward_sector_deg` |

### 5.2 模式-参数映射（由 TerrainModeAdapter 执行）

| `current_profile` | `unknown_policy` | `drop_forward_sector_deg` | 说明 |
|---|---|---:|---|
| `normal` | `aggressive` | 180 | 巡航效率优先 |
| `safe` | `conservative` | 360 | 安全优先 |
| `mf_traverse` | `conservative` | 360 | 梅林穿越 |
| `mf_exit` | `conservative` | 270 | 出林过渡 |
| `mf_approach`(新增) | `aggressive` | 180 | 方块侧向接近抓取 |

### 5.3 伪代码（接口闭环）

```pseudo
on nav_safety_state(msg):
  profile = msg.current_profile
  params = map_profile_to_terrain_params(profile)
  call set_parameters(/terrain_semantic_node, params)

on kfs_detection(block_id, confidence):
  L[block_id] += logit_update(confidence)
  if sigmoid(L[block_id]) > 0.7:
    mark_keepout(block_id)

terrain_frame_callback(cloud, odom, tf):
  cloud' = transform_and_voxel(cloud)
  cloud'' = slope_compensate(cloud', roll, pitch)
  grid = project_to_grid(cloud'')
  estimate_ground_top(grid)
  classify_obstacle_drop(grid, neighbor_obstacle=4, neighbor_drop=8)
  apply_connected_component_filter(min_cells=2)
  fuse_kfs_keepout_mask()
  publish(terrain_obstacles, terrain_drop)
  publish_latency_diag()
```

1. 坡道补偿上线并实车标定 `slope_ramp_deg`。
2. `h_above` 条件细化，消除 KFS 侧面误标。

## 10. 结论

v4.0 的主干方向正确，但在终审标准下卡在三点：
1. 缺少 `20ms` 硬时延分解；
2. 坡道与动态干扰未公式化；
3. 接口命名与实现存在漂移。

v4.1 已补齐以上缺口，并将 A/B 亮点落到“可配置参数 + 伪代码 + 验收指标”层面。按本版实施后，方案可达到比赛级可用性与可审计性。
