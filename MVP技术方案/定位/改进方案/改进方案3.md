## 1. QCS8550 约束与分工原则（必须执行）

### 1.1 处理器分层

按本项目约束使用如下拓扑建模：

- Prime: `1 x 3.2GHz`，用于低延迟关键线程。
- Gold: `4 x 2.8GHz`，用于 `small_gicp` 主并行负载。
- Silver: `3 x 2.0GHz`，仅放低优先级线程，禁止放重计算配准线程。

### 1.2 线程职责映射

| 线程/模块 | 绑定建议 | 调度建议 | 原因 |
|---|---|---|---|
| Point-LIO 主滤波线程 | Prime + 1 个 Gold | `SCHED_FIFO`(70) | 保障 IMU 紧耦合低抖动 |
| `small_gicp` 配准主线程 | 2 个 Gold | `SCHED_FIFO`(60) | 防止掉到 Silver 造成配准掉帧 |
| OMP 工作线程 | 其余 Gold | `SCHED_OTHER` + `OMP_PROC_BIND=true` | 保证吞吐并降低线程迁移 |
| ROS2 executor/Nav2 规划 | Silver | `SCHED_OTHER` | 与重计算解耦，避免抢占关键链路 |
| 日志/可视化/录包 | Silver | `nice +5` | 降低干扰 |

## 2. 必须落地的线程亲和补丁（代码片段）

### 2.1 C++ 线程绑定（放到 `rc26_localization` 初始化）

```cpp
#include <algorithm>
#include <fstream>
#include <pthread.h>
#include <sched.h>
#include <string>
#include <tuple>
#include <vector>

namespace {
struct CpuBuckets {
  std::vector<int> prime;
  std::vector<int> gold;
  std::vector<int> silver;
};

CpuBuckets detect_qcs8550_buckets() {
  std::vector<std::pair<int, int>> freq_cpu;  // {max_khz, cpu_id}
  for (int cpu = 0; cpu < 8; ++cpu) {
    std::ifstream ifs("/sys/devices/system/cpu/cpu" + std::to_string(cpu) + "/cpufreq/cpuinfo_max_freq");
    int khz = 0;
    if (ifs >> khz) freq_cpu.emplace_back(khz, cpu);
  }
  std::sort(freq_cpu.begin(), freq_cpu.end(), std::greater<>());

  CpuBuckets out;
  if (freq_cpu.size() >= 8) {
    out.prime.push_back(freq_cpu[0].second);
    for (size_t i = 1; i <= 4; ++i) out.gold.push_back(freq_cpu[i].second);
    for (size_t i = 5; i < freq_cpu.size(); ++i) out.silver.push_back(freq_cpu[i].second);
  }
  return out;
}

bool bind_current_thread(const std::vector<int>& cpus, int policy, int priority) {
  if (cpus.empty()) return false;
  cpu_set_t set;
  CPU_ZERO(&set);
  for (int c : cpus) CPU_SET(c, &set);
  if (pthread_setaffinity_np(pthread_self(), sizeof(set), &set) != 0) return false;

  sched_param sp{};
  sp.sched_priority = priority;
  if (pthread_setschedparam(pthread_self(), policy, &sp) != 0) return false;
  return true;
}
}  // namespace

void Localization::configure_thread_affinity_qcs8550() {
  const auto cpu = detect_qcs8550_buckets();
  // 当前线程假设为 small_gicp 主循环线程：绑定 Gold，避免 Silver。
  bind_current_thread(cpu.gold, SCHED_FIFO, 60);

  // OMP 线程只在 Gold 跑，减少迁移。
  setenv("OMP_NUM_THREADS", "4", 1);
  setenv("OMP_PROC_BIND", "true", 1);
  setenv("OMP_PLACES", "{0},{1},{2},{3}", 0);  // 若运行时支持编号替换，启动时注入真实 Gold ID
}
```

### 2.2 OMP 线程映射建议


## 3. NEON/SVE2 优化路径（small_gicp 专项）

### 3.1 编译配置

在 `CMakeLists.txt` 对 ARM 目标增加：

```cmake
if(CMAKE_SYSTEM_PROCESSOR MATCHES "aarch64|ARM64|arm64")
  add_compile_options(-O3 -ffast-math -funsafe-math-optimizations)
  add_compile_options(-fopenmp)
  add_compile_options(-march=armv9-a+simd)
  # 若工具链与芯片确认支持，再启用：-march=armv9-a+sve2
endif()
```

### 3.2 距离核 NEON 片段（用于 KDTree 最近邻热路径）

```cpp
#if defined(__ARM_NEON)
#include <arm_neon.h>

inline float sq_dist3_neon(const float* a, const float* b) {
  float32x4_t va = {a[0], a[1], a[2], 0.0f};
  float32x4_t vb = {b[0], b[1], b[2], 0.0f};
  float32x4_t d = vsubq_f32(va, vb);
  float32x4_t m = vmulq_f32(d, d);
  float32x2_t s = vadd_f32(vget_low_f32(m), vget_high_f32(m));
  s = vpadd_f32(s, s);
  return vget_lane_f32(s, 0);
}
#endif
```

### 3.3 优化边界

- 优先 NEON，不在首赛季强上 SVE2。
- 仅替换热路径内核，不改 `small_gicp` 接口层。
- 必须保留标量 fallback 与 A/B 开关：
  - `gicp_kernel_mode: scalar | neon`
  - 失败可回滚到 `scalar`。

## 4. AidLux 实时性补丁（必须给运维脚本）

### 4.1 启动脚本（`scripts/setup_realtime_aidlux.sh`）

```bash
#!/usr/bin/env bash
set -euo pipefail

NODE_BIN=${1:-rc26_localization_node}
PID=$(pidof "${NODE_BIN}" || true)
if [ -z "${PID}" ]; then
  echo "node not running: ${NODE_BIN}" >&2
  exit 1
fi

# 1) 进程级：优先绑 Prime+Gold，避免 Silver
taskset -cp 0-4 "${PID}"

# 2) 线程级：按线程名分配
for T in /proc/"${PID}"/task/*; do
  TID=$(basename "${T}")
  COMM=$(cat "${T}/comm" 2>/dev/null || true)
  case "${COMM}" in
    *gicp*|*omp*|*registration*)
      taskset -cp 1-4 "${TID}" >/dev/null 2>&1 || true
      ;;
    *lio*|*imu*|*filter*)
      taskset -cp 0-4 "${TID}" >/dev/null 2>&1 || true
      ;;
    *)
      taskset -cp 5-7 "${TID}" >/dev/null 2>&1 || true
      ;;
  esac
done

# 3) 尝试实时优先级（无权限时静默退化）
chrt -f -p 60 "${PID}" >/dev/null 2>&1 || true

echo "[ok] aidlux realtime policy applied to PID ${PID}"
```

### 4.2 有 root 权限时的 cpuset 方案


## 5. 赛场鲁棒性补强（丘陵地形 + 碰撞）

保留并强化 S1/S2/S3：

1. `S1` IMU Spike 门控：碰撞窗口冻结配准种子，避免双层漂移叠加。
2. `S2` 退化轴识别：按 Hessian 最小特征值做方向性拒绝更新。
3. `S3` SC 对称歧义拒绝：`top2` fitness 过近直接拒绝，避免镜像重定位。

新增丘陵地形约束：

- 维护 `roll/pitch` 主信号来自 IMU，`small_gicp` 对姿态只做小幅修正。
- 在坡面工况引入 `z_weight` 与 `normal_consistency` 门控，防止把坡面局部平面误匹配为全局平面。
- 当 `S2` 连续触发超过阈值（如 10 帧）时，强制进入 `GLOBAL_RECOVERY`。

## 6. QCS8550 下 16/32 线时延预算（用于 50Hz 评估）

> 置信度说明：以下为工程估算（中置信），需以实机 profiling 校准。

### 6.1 16 线雷达（约 18k points/帧，降采样后 1.2k~1.8k）

| 阶段 | 无亲和+标量 | 亲和+NEON | 说明 |
|---|---:|---:|---|
| 降采样 + 法向估计 | 4.0~6.0ms | 2.5~4.0ms | OMP 固定 Gold |
| KDTree 查询 + GICP 迭代 | 10.0~16.0ms | 6.0~10.0ms | NEON 热路径收益 |
| 结果门控/S2/S3 判定 | 1.0~2.0ms | 1.0~2.0ms | 逻辑开销固定 |
| 合计 | 15.0~24.0ms | **9.5~16.0ms** | 可覆盖 50Hz（20ms）预算 |

### 6.2 32 线雷达（约 35k points/帧，降采样后 2.2k~3.2k）

| 阶段 | 无亲和+标量 | 亲和+NEON | 说明 |
|---|---:|---:|---|
| 降采样 + 法向估计 | 7.0~10.0ms | 4.0~6.5ms | 点数翻倍影响明显 |
| KDTree 查询 + GICP 迭代 | 16.0~25.0ms | 9.0~15.0ms | 迭代可压到 15~20 次 |
| 结果门控/S2/S3 判定 | 1.0~2.5ms | 1.0~2.5ms | 同上 |
| 合计 | 24.0~37.5ms | **14.0~24.0ms** | 需配合异步后端与输出解耦 |

结论：

- `small_gicp` 仍定位为低频修正层（建议 `8~15Hz`）。
- 控制链 `50Hz+` 由 Point-LIO 主导，`map->odom` 修正异步注入。
- 若 32 线高密度导致超 20ms，优先降采样而非增线程到 Silver。

## 7. GPU / DSP / NPU 卸载策略（不再一刀切否定）

### 7.1 可做（中期）

1. OpenCL 卸载点云预处理（voxel/filter/normal 预计算）。
2. OpenCL 做候选对应初筛（粗距离矩阵）。

### 7.2 暂不做（首赛季）

1. 全量 ICP/GICP 主循环搬到 GPU（分支重、内存访问离散，改造风险高）。
2. 用 SNPE/QNN 替代几何配准主链路（训练和部署链条太长）。

### 7.3 决策门槛

- 若 CPU 温控下仍无法稳定 `Point-LIO 50Hz + small_gicp 8Hz`，才启动 OpenCL 路线。
- 启动前必须给出 `>20%` 端到端时延收益的离线证据。
