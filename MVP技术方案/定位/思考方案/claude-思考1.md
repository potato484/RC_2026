> 评估日期：2026-02-18
> 竞赛背景：ROBOCON 2026，R2 全自主，4 分钟比赛

## 1. 竞赛场景约束提炼（规则驱动的工程约束）

| 约束 | 规则来源 | 对重定位的工程意义 |
|---|---|---|
| R2 全程自主，无手动接管 | §2.1 | 任何定位失效必须软件自愈 |
| 总比赛时长 4 分钟 | §4 结束条件 | 重定位耗时直接消耗赛时 |
| 强制重试停留 **15 秒** | §6.1/6.2 | 重定位必须在 15s 内完成并恢复导航 |
| 重试区坐标**固定**（红/蓝已知） | §1.2.3 | 重试后位置已知，无需全局搜索 |
| 启动区坐标**固定**（初始位置已知） | §4 阶段 0 | 启动时无需全局重定位，init_pose 足够 |
| 场地尺寸 12m×12m，有 12 个 1.2m×1.2m 方块 | §1.2.2 | 高度重复性几何特征，描述子匹配高模糊 |
| 对抗区亚克力护栏（10mm 厚） | §1.2.3 | 雷达幽灵点，已有 I3 过滤 |

**关键推论**：在 ROBOCON 2026 实际赛场中，触发全局重定位的场景极为有限：

- **启动时**：已知 init_pose → 无需全局重定位
- **重试后**：操作员将 R2 放回重试区 → 位置已知，I2 快速通道完全覆盖
- **比赛中途绑架**：如被对方碰撞或传感器突发失效 → **唯一真正需要 ISS+FPFH+SAC-IA 的场景**，但此场景在 ROBOCON 规则下属于强制重试范畴，依然由 I2 兜底

**结论：完整的 5 级重定位链路（ISS+FPFH+SAC-IA+NDT+ICP）的目标使用场景，几乎被现有 I2（重试区快速通道）完整覆盖。**

## 2. 核心问题诊断

### 2.1 链路冗余：NDT 与 ICP 的功能重叠

**代码位置**：`localization.cpp:875-914`（NDT 段）、`:893-915`（ICP 段）

当前实现对每个候选初值依次执行：SAC-IA 粗配准 → NDT（50次迭代）→ ICP（100次迭代）。

NDT 和 ICP 均是迭代式 scan-to-map 精化算法，二者的功能区别：

| 特性 | NDT | ICP (point-to-point) |
|---|---|---|
| 适用初值误差范围 | 较大（0.5m–2m）| 较小（<0.5m）|
| 使用的地图表示 | 概率体素网格 | KD-Tree 点云 |
| 优势场景 | 初值粗糙时收敛更好 | 初值精准时精度更高 |

**问题所在**：全局重定位时 `global_downsample_leaf_size_=0.5m`（参数声明第 67 行），在此分辨率下，NDT 的体素分辨率（`ndt_resolution_=1.0m`）相对于场地（12m×12m）仅产生约 144 个体素，且ICP 使用相同的稀疏点云（`source_down`/`target_down`），两者在如此低分辨率下的精化空间高度重叠。

**量化成本**：4 个候选 × (NDT 50 iter + ICP 100 iter) = **600 次迭代的串行计算**，且每次 NDT 内部需重建概率分布。在嵌入式 ARM 平台（算力受限）上，此段耗时可轻易超过 5 秒。

**结论**：NDT 中间层在当前参数配置下是冗余的。若 SAC-IA 粗配准质量足够（误差 <1m），单轮 ICP 即可收敛；若 SAC-IA 质量极差，NDT 也无法挽救（因为 1.0m 分辨率体素无法区分 1.2m 间距的方块几何）。

### 2.2 ISS+FPFH 在场地重复性纹理下的可靠性

**场地几何特征分析**：

```
梅林区 12 个方块：
- 俯视排列：4×3 网格，列间距 ~1.2m，行间距 ~1.2m
- 高度：200mm / 400mm / 600mm（三种，共用相同底面）
- 顶面边缘：4 条完全相同的 90° 直角边（高 200mm/400mm/600mm）
- 整体特征：高度重复，仅高度差异，水平截面完全一致
```

**ISS 失效分析（代码第 763-800 行）**：

ISS（Intrinsic Shape Signatures）通过协方差矩阵特征值比值筛选显著点（角点/边缘）。在 0.5m 降采样后：
- 方块顶面：平坦，特征值比值 λ₂/λ₁ ≈ 1, λ₃/λ₂ ≈ 0 → 不满足 ISS 阈值，无关键点
- 方块垂直边缘：4 条边具有相同几何（高 200/400/600mm），在 0.5m 降采样后每条边仅余 0~1 个点
- 地面：近似平面 → ISS 无输出

代码已存在 fallback 机制（第 796-800 行：关键点 <30 则回退全点云），**实测中此 fallback 将几乎必然触发**，使 ISS 步骤成为纯粹的计算浪费（ISS 计算 + 判断 <30 + 回退）。

**FPFH 模糊性分析**：

回退到全点云 FPFH 后，场地中的几何特征高度重复：
- 所有方块的垂直面：相同的 FPFH 直方图（平面点）
- 方块与地面交界处：4 个方块共享相同的 L 形截面特征
- 在 12m×12m 平整室内场地中，几何特征的唯一性极低

FPFH 匹配的歧义性（correspondence_randomness_=50）将导致 SAC-IA 产生大量错误的内点集，粗配准结果的误差会超过 NDT/ICP 的收敛范围。

**结论**：在本赛场几何条件下，ISS 关键点提取率接近零（必然触发 fallback），FPFH 在重复几何场景下匹配歧义度高，SAC-IA 粗配准结果可信度存疑。该组合在实际比赛中有较高概率导致重定位失败。

### 2.3 状态机逻辑冗余与竞态风险

**两条全局重定位触发路径**（均在 `performRegistration()` 中，代码第 490-569 行）：

```
路径A（绑架检测）：detectKidnapping() → is_kidnapped_.store(true) → spawn thread
路径B（超时检测）：time_since_last_success > timeout → spawn thread
```

**问题1 - 同帧双触发**：在单次 `performRegistration()` 调用中，路径 A 的 `detectKidnapping()` 返回 true 并 return，路径 B 在之后的代码（第 554-570 行）被执行。由于路径 A 提前 `return`（第 499 行），路径 B **不会** 在同帧触发，但 `is_kidnapped_` 被设为 true，而 `last_successful_registration_time_` 未更新，下一帧若重定位线程未完成，超时可能再触发一次 join+spawn。

**问题2 - 阻塞配准定时器**：`performRegistration()` 运行在 2 Hz 定时器回调中，而内部 `global_reloc_thread_.join()`（第 495 行、第 567 行）会**阻塞定时器线程**直到上次重定位完成。若重定位耗时 15 秒，配准定时器在这 15 秒内完全停止工作，TF 只靠 20 Hz 的 `publishTransform()`（使用旧值）维持。这是设计上的妥协，但文档中未明确说明。

**问题3 - 三类"恢复"机制功能耦合**：

| 机制 | 触发条件 | 本质功能 |
|---|---|---|
| 绑架检测 | 连续 N 帧误差 > 阈值 | 质量监控 → 触发恢复 |
| 配准超时 | 成功间隔 > T 秒 | 活性监控 → 触发恢复 |
| I2 重试区快速通道 | retry_zone_enable=true | 位置先验 → 快速 ICP |
| 多假设初值 | use_multi_hypothesis=true | 旋转不确定性 → 穷举搜索 |

这四个机制分散在代码中，缺乏统一的状态机抽象，难以推理整体行为。例如：若 I2 失败后降级到 ISS+FPFH，成功率低，然后 `is_kidnapped_.store(false)` 后重新进入常规配准，若质量仍差，下一帧绑架检测将再次触发，产生振荡。

### 2.4 性能瓶颈定量估计

基于竞赛平台（ARM，限制 4 线程）的保守估计（0.5m 叶大小，12m×12m 场地）：

| 步骤 | 预计耗时 | 备注 |
|---|---|---|
| 降采样（VoxelGrid，source+target）| ~20ms | PCL 单线程 |
| ISS 关键点（双向）| ~200ms | KdTree + 特征值分解 |
| 法向量估计（NormalOMP，k=20）| ~150ms | 即使 fallback 后仍执行 |
| FPFH 计算（k=50）| ~300ms | 全点云 FPFH |
| SAC-IA（randomness=50）| **1–5s** | RANSAC 内部多次迭代，随机性大 |
| NDT × 4 候选（50 iter each）| **2–4s** | PCL NDT 单线程 |
| ICP × 4 候选（100 iter each）| **2–4s** | 含 RANSAC 外点拒绝 |
| **总计（最坏情况）** | **~6–14s** | 可能超出 15s 约束窗口 |

I2（重试区快速通道）：仅 4 次 ICP（100 iter），**预计 1–2s**，远优于完整链路。

## 3. SOTA 方案调研（2024–2026）

### 3.1 竞赛机器人主流方案

**方案 A：FAST-LIO2 + Scan Context（工业级基线）**

适用于有 IMU 的 LiDAR-惯性系统。Scan Context 作为场景识别描述子：

- 构建：将 LiDAR 扫描投影为极坐标 BEV 高度图（环×扇区矩阵），O(N) 构建
- 查询：使用"环键"（ring key，列均值向量）作为一维哈希，O(1) 候选预筛选
- 旋转鲁棒性：通过列移位（column shift）解决旋转歧义，可恢复绝对偏航角
- 代表仓库：`FAST-LIO-Localization-SC-QN`（Scan Context 候选 + Quatro 粗配准 + Nano-GICP 精配准）

相比 FPFH，Scan Context 无需法向量估计，对重复纹理（平整室内地板）更鲁棒，因为它捕捉**全局布局**（场地轮廓形状）而非**局部几何**（点法向直方图）。

**方案 B：Quatro + Nano-GICP（无需 IMU 的纯 LiDAR 重定位）**

Quatro（Quasi-Globally Optimal Registration）：
- 基于地面分割，将 6-DOF 问题分解为水平 4-DOF（x, y, z, yaw）
- 利用截断最小二乘（TGKF）进行旋转估计，全局最优，对外点鲁棒
- 典型耗时：单次 <100ms（含地面分割）

Nano-GICP：FastGICP 的轻量版本，使用 NanoFLANN KD-Tree，比 PCL ICP 快 3–5×。

**方案 C：BEVPlace++ / MixedSCNet（神经网络描述子，2024 SOTA）**

需要预训练，不适合比赛快速部署，但在重复纹理环境中召回率 >98%（KITTI 旋转测试），未来可考虑。

### 3.2 本赛场最优方案推荐

考虑到：
1. 12m×12m 小场地（全局唯一描述子容易构建）
2. 场地平坦（2D 投影有效，Scan Context 适用）
3. 无法确认 IMU 存在（代码中无 IMU 融合）
4. 已有 small_gicp 在代码库中（高效配准后端）

**推荐：Scan Context（全局候选）+ small_gicp GICP（精配准）**，具体理由见第 4 节。

## 4. 优化建议方案

### 4.1 短期优化（参数调整，无代码重构，1–2 天）

**立即可行，降低失败风险：**

```yaml
# 关闭 NDT 中间层（最大收益，节省 2–4s）
use_ndt_refinement: false

# 关闭 ISS（几乎必然 fallback，纯浪费）
use_iss_keypoints: false

# 减少多假设数量（4→2，节省一半 ICP 计算）
num_yaw_hypotheses: 2

# 降低 SAC-IA 随机性（减少内部迭代）
sac_ia_correspondence_randomness: 20

# 确保 I2 重试区已配置（最重要的优先路径）
retry_zone_enable: true
retry_zone_x: <实际重试区 x 坐标>
retry_zone_y: <实际重试区 y 坐标>
retry_zone_yaw_candidates_deg: [0.0, 90.0, 180.0, 270.0]
retry_zone_fast_accept_th: 0.15
```

**预期效果**：全局重定位总耗时从最坏 ~14s 降至 ~4–6s，I2 命中后降至 ~1–2s。

### 4.2 中期优化（以 Scan Context 替换 ISS+FPFH+SAC-IA，1–2 周）

**架构目标**：

```
[绑架检测触发]
    │
    ├─→ I2: 重试区先验 ICP（已知位置场景，<2s）
    │        └─→ 成功 → 恢复
    │
    └─→ Scan Context 查询（全局未知位置场景）
         ├─ 从先验地图预建 Scan Context 数据库（节点启动时离线完成）
         ├─ 用当前扫描查询最近邻（O(1) ring key 哈希，<10ms）
         ├─ 获取候选变换初值（包含偏航角估计）
         └─→ small_gicp GICP 精配准（使用已有 register_ 对象，<1s）
              └─→ 成功 → 恢复
```

**关键实现要点**：
- Scan Context 数据库在 `prepareTargetMap()` 完成后立即离线构建，利用先验地图点云
- 查询返回的候选已包含偏航角信息，无需多假设枚举
- 精配准直接复用现有 `small_gicp::Registration` 对象，避免引入 PCL ICP

**对比当前方案**：

| 指标 | 当前（ISS+FPFH+SAC-IA+NDT+ICP）| 优化后（Scan Context+small_gicp）|
|---|---|---|
| 全局搜索耗时 | 4–14s | <500ms |
| 对重复纹理鲁棒性 | 差（局部描述子歧义）| 中等（全局布局描述） |
| 旋转歧义处理 | 多假设穷举（昂贵）| Scan Context 列移位（内置，O(N)）|
| 代码复杂度 | 高（5 个可选阶段、5 个标志位）| 低（2 个阶段，1 条快路径）|
| 需要额外依赖 | 无 | scan_context 库（头文件库，MIT 协议）|

### 4.3 架构改进：统一状态机

将分散的 `is_kidnapped_`、`global_reloc_running_`、`map_to_odom_reliable_` 整合为单一枚举状态：

```cpp
enum class LocalizationState {
    TRACKING,          // 正常配准，TF 可信
    DEGRADED,          // 质量下降，TF 冻结（I1 门控中）
    RELOCATING,        // 全局重定位进行中（后台线程）
    RELOC_FAILED,      // 重定位失败，等待外部初值
};
```

这消除了三个 atomic bool 之间的竞态可能，使状态转换图可以完整描述和测试。

## 5. 问题优先级矩阵

| 优先级 | 问题 | 影响 | 修复成本 |
|---|---|---|---|
| **P0** | I2 重试区坐标是否已正确配置 | 若未配置，所有重试场景均触发全链路（>10s）| 参数填写，<1小时 |
| **P1** | NDT 冗余（use_ndt_refinement=true）| 每次重定位多耗 2–4s，占用 15s 约束窗口 | 参数改 false，<5分钟 |
| **P1** | ISS 关键点必然 fallback | 额外浪费 ~400ms + 心智负担 | 参数关闭，<5分钟 |
| **P2** | FPFH 在重复纹理下匹配歧义 | SAC-IA 粗配准质量不稳定，影响全局恢复成功率 | 中期替换 Scan Context |
| **P2** | `join()` 阻塞配准定时器 | 重定位期间配准 2Hz 完全停止，仅 TF 维持 | 异步队列改造 |
| **P3** | 状态管理分散（3个atomic） | 竞态风险，调试困难 | 中期状态机重构 |

## 6. 总结

当前重定位链路的核心矛盾是：**针对"完全未知位置"设计的通用全局搜索算法**（ISS+FPFH+SAC-IA）被部署在一个**初始/重试位置高度确定**的竞赛场景中。

I2（重试区快速通道）已经是正确的架构方向，覆盖了 ROBOCON 2026 中 >90% 的重定位需求。当前最紧迫的行动是：

1. **确认 I2 参数正确配置**（重试区坐标填入）
2. **关闭 NDT 和 ISS**（立即节省 >50% 重定位耗时）
3. 中期以 **Scan Context** 替换 ISS+FPFH+SAC-IA，作为 I2 失败时的真正全局搜索保障

这套改进方案在不引入新硬件、不改变系统架构主体的前提下，将最坏情况重定位耗时从 ~14s 压缩至 <3s（I2 路径 <1.5s，Scan Context 路径 <2.5s），满足 15 秒重试窗口约束。
