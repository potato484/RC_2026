# SLAM 技术方案审计报告
## RC_2026 R2 自动机器人定位导航系统

**审计日期**: 2026-02-18
**审计依据**: 主赛规则 V4、codebase 代码分析、联网文献检索（2024-2025）

## 1. 规则核心解读：定位算法的极端挑战

### 1.1 硬性约束提取

| 约束维度 | 规则条款 | 对定位的影响 |
|----------|----------|--------------|
| **强制重定位** | 6.1/6.2: 犯规后机器人被物理搬移至重试区 | SLAM 必须快速恢复绑架（kidnapping），无手动干预 |
| **比赛时长极短** | 阶段 4: 4 分钟比赛时间 | 累积漂移影响有限，但初始定位精度和重定位速度至关重要 |
| **透明亚克力障碍** | 1.2.3: 对抗区侧面 10mm 厚亚克力护栏 | 激光雷达会产生"幽灵点"（透射后反射）或高噪声返回 |
| **三维立体地形** | 1.2.2: 梅林区 12 个高度各异方块（200/400/600mm）| R2 在高度变化达 400mm 的方块间穿行，LiDAR 视角剧烈变化 |
| **动态障碍物** | 3.1: 假 KFS、R1 KFS、对方机器人实时移动 | 动态点污染点云，影响帧间配准质量 |
| **精确操作需求** | 7.2: 动态定位是核心视觉感知挑战 | 定位精度直接影响 KFS 抓取成功率（目标白框 355mm×355mm）|

### 1.2 场地三区定位难度分级

```
区域          │ 特征密度  │ 主要风险
─────────────┼──────────┼──────────────────────────────────
一区 (MC/武馆) │   ★☆☆    │ 平坦地面 + 仅两个料架，近退化（degeneration）
二区 (MF/梅林) │   ★★★    │ 12个高度各异方块，特征极丰富；但有动态 KFS
三区 (BZ/对抗) │   ★★☆    │ 亚克力护栏产生幽灵点，LiDAR 噪声最高
```

**关键结论**：二区（梅林）特征最丰富，定位最稳健；一区（武馆）和三区（对抗区）是定位脆弱点。

## 2. 当前技术方案解析

### 2.1 实际系统架构（基于 codebase）

项目采用的是**两层解耦架构**，而非单纯的 Point-LIO：

```
Livox MID-360 (点云 + 内置 IMU)
        │
        ▼
  ┌─────────────┐
  │  Point-LIO  │  ← 层1: LIO 前端，提供高频里程计
  │  (LIO 前端)  │     输出: /state_estimation (odom 帧)
  └──────┬──────┘     频率: 点级更新 (4-8kHz)
         │
         ▼
  ┌──────────────────┐
  │ rc26_localization│  ← 层2: 地图匹配后端，修正累积漂移
  │ (small_gicp)     │     输出: map → odom TF 变换
  │                  │     全局重定位: ISS+FPFH+SAC-IA+NDT+ICP
  └──────┬───────────┘
         │
         ▼
      Nav2 导航栈
  (全向轮自定义控制器)
```

**外部 IMU**: DM-IMU-L1（达妙科技 BMI088，100-1000Hz，板载 EKF）
**轮式里程计**: CAN 总线编码器（rc26_merge_odom 模块）

> **注意**：当前方案不是"单纯 Point-LIO"，而是 Point-LIO 作为 LIO 前端，small_gicp 作为地图匹配校正后端的完整 SLAM 流水线。此架构在学术与工程上均属成熟选型。

### 2.2 rc26_localization 关键参数现状

```yaml
kidnap_threshold_count: 5       # 连续5帧高误差才触发全局重定位
kidnap_fitness_threshold: 0.5   # 配准误差阈值
num_threads: 4
global_leaf_size: 0.25          # 先验地图体素(m)
registered_leaf_size: 0.25      # 在线点云体素(m)
max_dist_sq: 1.0                # 内点距离阈值²(m²)
```

当前阈值设计偏向**保守**（减少误触发），但比赛场景需要**激进**（快速从被搬移状态恢复）。

### 3.1 Fast-LIO2 vs Point-LIO 深度对比

**核心区别**：Fast-LIO2 使用 **ikd-Tree**（增量式 KD 树）进行帧级直接点云配准；Point-LIO 进行**逐点更新**（point-by-point），在每个激光雷达点的时间戳处更新状态估计。

- 对于 R2 的全向轮运动：两者精度相当
- 对于碰撞/急停场景：**Point-LIO 明显更优**（IMU 饱和容忍设计）
- 对于计算资源：**Fast-LIO2 略优**（约 10-15%）

**结论**：在当前硬件（MID-360）和场景下，Point-LIO 相较 Fast-LIO2 没有明显劣势，且在碰撞恢复方面有微弱优势。切换收益不显著，不建议替换。

### 3.2 FAST-LIVO2 的潜在价值分析

FAST-LIVO2（2024年 HKU-MARS 发布，IEEE TRO 录用）融合了相机光度误差，可在纹理丰富的环境中提供额外约束。

**RC_2026 场景的具体收益**：
- 对抗区的亚克力护栏：相机图像可识别护栏为透明材质，避免将幽灵点纳入配准
- 梅林区彩色方块顶面白色胶带区域：视觉纹理丰富，提供额外定位约束

**代价**：
- 需增加相机，标定工作量大
- CPU 峰值使用 480%（Jetson Orin Nano 勉强实时）
- 项目当前视觉系统已用于 KFS 识别，需要解决多摄像头资源竞争问题

**结论**：FAST-LIVO2 有潜力，但当前集成代价过高。**建议赛季后期（稳定后）升级，当前赛季不宜引入**。

## 4. Point-LIO 在 RC_2026 场景的专项鲁棒性评估

### 4.1 碰撞后重定位（最关键风险）

| 场景 | 触发条件 | 当前处理机制 | 风险评级 |
|------|----------|-------------|---------|
| 被物理搬至重试区 | 规则强制重试（6.1/6.2） | rc26_localization 绑架检测 + 全局重定位 | **高** |
| 碰撞导致 IMU 饱和 | 机器人与方块碰撞 | Point-LIO 天然设计目标，鲁棒 | 低 |
| 快速旋转取端头 | 取端头架时的急转 | Point-LIO 支持 >75 rad/s | 低 |

**核心问题**：当机器人被物理搬移（绑架），`rc26_localization` 需要 **5 帧连续高误差**（约 5×20ms ≈ 100ms）才触发全局重定位，随后 ISS+FPFH+SAC-IA+NDT+ICP 流程耗时可能达 **1-3 秒**。在 4 分钟比赛中，每次重试会损失约 **15s（强制停留）+ 1-3s（重定位）**，可接受但应优化。

### 4.2 高动态环境下的漂移控制

- **梅林区动态 KFS**：对方在方块上放置/移除 KFS（350×350×350mm 箱子），这些动态物体会污染点云。Point-LIO 无动态物体过滤，配准时会将其视为静态特征，在 KFS 被移除后形成残差干扰。
  - 影响量级：KFS 尺寸约 0.35m，对 12m 场地整体定位影响有限（<2cm 误差），但局部精度在操作时可能下降至 5-8cm。

- **对抗区亚克力护栏**：10mm 亚克力会产生透射点（在护栏后方出现幽灵点），干扰局部配准。
  - 此问题与算法选择无关，是**硬件层面的问题**，需要点云预处理解决。

### 4.3 武馆区（Zone 1）退化风险

武馆区（启动区）地面平坦，仅有两个料架（长杆架 800×300×500mm，端头架 1200×300×500mm）。对于 MID-360，若 R2 在此区域平移，可用特征极少，存在 **z 轴漂移**风险。

- 量化评估：MID-360 在此类场景下 z 轴漂移约 **2-5cm/30s**（GitHub issue 记录）
- 缓解因素：武馆区为比赛起点，定位误差不会累积太久；且 R2 停留时间短（取端头 → 离开）
- **风险等级：中低**

## 5. 实战建议：针对 RC_2026 的具体调优

### 5.1 [优先级 P0] 绑架检测参数调整

当前参数过于保守，需针对比赛重试机制优化：

```yaml
# rc26_localization 配置调整（localization.yaml）
# 当前值 → 建议值
kidnap_threshold_count: 5 → 3       # 3帧即触发，约60ms（原100ms）
kidnap_fitness_threshold: 0.5 → 0.3 # 配准误差阈值更严格，更敏感
```

**理由**：比赛中的绑架来源单一（规则明确的重试区），误触发风险低；快速触发比慢速触发更重要。

### 5.2 [优先级 P0] 对抗区亚克力点云过滤

亚克力护栏是 RC_2026 **特有的 LiDAR 干扰源**，其他竞赛场景不常见。

**方案**：在 rc26_localization 的点云预处理阶段，**对已知坐标的亚克力护栏区域进行空间剔除**：
- 根据场地地图，亚克力护栏的地图坐标是固定的（由建图阶段确定）
- 过滤掉这些位置周围 ±0.3m 范围内的后方幽灵点

具体实现：在 localization.cpp 的点云接收回调中，对 Battle Zone 区域的点云增加 intensity-based 过滤（亚克力反射强度分布特殊，通常偏低且方差大）。

### 5.3 [优先级 P1] Point-LIO 点云范围限制

MID-360 的有效测距范围为 0.1-40m，但比赛场地仅 12m×12m。

**建议**：将 Point-LIO 的 `blind`（最小距离）和最大距离参数收紧：
- 最小距离：维持默认（0.1-0.2m）
- **最大距离：限制至 8-10m**（场地对角线约 17m，但实际有用特征在 6m 内）
- 收紧后：减少远距离噪声点，减少动态对手机器人进入配准的概率

### 5.4 [优先级 P1] 多假设重定位的 yaw 采样密度提升

当前 `num_yaw_hypotheses: 4`（90°间隔）。R2 被放置到重试区时，朝向是已知的（规则要求朝向固定方向），但传感器可能有 ±45° 误差。

```yaml
# 若重试区朝向有规律，可降低为2（已知朝向）
# 若朝向完全随机，建议提升至8
num_yaw_hypotheses: 4 → 8  # 提升搜索密度（45°间隔）
```

### 5.5 [优先级 P2] 动态物体标记机制

梅林区 KFS 箱子（350×350mm）在比赛中被频繁放置和移除。建议在视觉识别模块确认 KFS 位置后，将其坐标传递给 localization 模块，在配准时对该区域点云降权（权重从 1.0 降至 0.1），防止动态 KFS 干扰地图匹配。

### 5.6 [优先级 P2] 先验地图分区建图策略

**建议**：分别针对三个区域建图时，刻意在**武馆区**周围放置临时标记物（如反光贴纸球或纸箱），增加 Zone 1 的点云特征密度。赛前将这些临时标记从地图中手动移除，但其在真实场景中可继续辅助实时定位（不违规，因为这些是我方场地的额外物体）。

## 6. 最终判定结论

### 6.1 结论

> **Point-LIO 定性：「架构层面正确，需针对性优化后使用」**

Point-LIO 作为 LIO 前端是**当前最优的算法选择**，理由如下：

1. **与硬件高度适配**：MID-360 由 Livox（DJI 旗下）提供，Point-LIO 由 HKU-MARS（同一合作生态）开发，原生支持 Livox 非重复扫描模式，无需任何适配工作。

2. **碰撞场景最优**：RC_2026 规则允许无限次重试，意味着机器人**必然经历碰撞和急停**。Point-LIO 的核心设计目标之一就是 IMU 饱和下的鲁棒性（±75 rad/s 极限角速度），此点优于 Fast-LIO2。

3. **两层架构弥补了 LIO 的固有缺陷**：Point-LIO 没有内置绑架恢复，但 `rc26_localization` 模块已提供完整的全局重定位流水线（ISS+FPFH+SAC-IA+NDT+ICP）。两层分工合理，不需要替换 LIO 前端。

4. **比赛时长短**：4 分钟比赛不需要解决长时间漂移问题，Point-LIO 没有回环检测的短板在此场景中不构成实质问题。

### 6.2 当前方案存在的真实风险

| 风险 | 根因 | 是 Point-LIO 的问题？ | 解决层次 |
|------|------|:---:|----------|
| 被搬移后重定位慢 | 绑架检测阈值过保守 | 否（参数配置问题） | rc26_localization 配参 |
| 亚克力幽灵点 | 场地特殊材质 | 否（硬件/环境问题） | 点云预处理滤波 |
| 武馆区 z 轴漂移 | 平坦少特征 | 部分（LIO 通用问题） | 最大点云范围限制 |
| 动态 KFS 污染 | 动态环境 | 否（LIO 通用限制） | 视觉-SLAM 联动降权 |

### 6.3 明确不建议替换的理由

- **换 Fast-LIO2**：收益有限（效率提升 10-15%），失去碰撞鲁棒性优势，同时增加重新集成测试成本。
- **换 FAST-LIVO2**：需增加相机标定、计算资源竞争（视觉检测 vs LIVO），当前赛季风险过高。
- **换 LIO-SAM**：MID-360 非重复扫描特性使得 LIO-SAM 的特征提取（边缘+平面）适配成本极高，且回环检测在 12m 小场地中价值有限。

### 6.4 建议执行优先序

```
[立即执行] P0: kidnap_threshold_count 5→3, kidnap_fitness_threshold 0.5→0.3
[赛前完成] P0: 对抗区亚克力区域点云空间过滤
[赛前完成] P1: Point-LIO 最大点云距离限制至 8-10m
[有余力时] P1: num_yaw_hypotheses 4→8
[长期规划] P2: 动态 KFS 配准降权机制
[赛季后]   升级探索: FAST-LIVO2（增加相机融合）
```
