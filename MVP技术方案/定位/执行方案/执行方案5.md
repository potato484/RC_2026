## 3. Phase A — P0（赛前必须，严格顺序）

> 目标：先把所有 P0 从“否决项”清零，再谈加分项。每一步都要带验收与回滚。

### Step 1 · 启动时序消窗 + 决策放行门控（评分 3.1）

文件：
- `src/rc26_bringup/launch/bringup.launch.py`
- `src/rc26_decision/include/rc26_decision/navigation/smart_waypoint_navigator.hpp`
- `src/rc26_decision/src/navigation/smart_waypoint_navigator.cpp`

**1a. bringup 启动顺序（Keepout 先于 Nav2）**

目标：确保 Nav2 的 keepout filter 初始化时就能拿到 `/costmap_filter_info` 与 `/kfs_filter_mask`（transient_local）。

推荐顺序（以 `LaunchDescription([...])` 列表为准）：
1) `map_server_node`  
2) `costmap_filter_info_server`  
3) `map_server_lifecycle_manager`（node_names 必含 `costmap_filter_info_server`）  
4) `kfs_block_fuser_node`  
5) `nav_mode_manager_node`  
6) `nav2_launch`  
7) `decision_node`（或 decision 更早也可，但必须有 gate）

**1b. SmartWaypointNavigator 增加 Keepout Ready Gate（硬约束）**

新增订阅：
- `/costmap_filter_info`（`nav2_msgs/msg/CostmapFilterInfo`）
- `/kfs_filter_mask`（`nav_msgs/msg/OccupancyGrid`）

放行条件（I-KFS-1）：
- 两 topic 均收到；
- `mask_age_ms <= 300`（建议同时统计 P95 ≤ 200ms）。

未满足行为：
- 不发送任何 Nav2 goal；
- 主动 `set_nav_mode safe`（reason=`keepout_gate`）或保持 safe；
- 超时（建议 3.0s）触发 fallback：原地等待/重新扫描/虚拟围栏（至少落地一种）。

**验收（必须闭环）**
- bringup 后立刻触发一次导航：若 keepout 未就绪，导航动作必须被拒绝且处于 safe/stop；就绪后才允许 goal。
- 复盘日志能定位：是 gate 未通过、还是 Nav2 未 ready。

**回滚**
- gate 保留 `keepout_gate_enable=false` 仅用于调试；比赛配置强制 true。

### Step 2 · KfsBlockFuser：修复释放死锁 + TTL + 强制释放 + 几何/标定防错（评分 2.2/2.1/2.4）

文件：
- `src/rc26_kfs_keepout/include/rc26_kfs_keepout/kfs_block_fuser.hpp`
- `src/rc26_kfs_keepout/src/kfs_block_fuser.cpp`
- `src/rc26_kfs_keepout/config/mf_grid_layout.yaml`
- `src/rc26_bringup/launch/bringup.launch.py`（参数落位）

**2a. 修复“永不释放”两种可选方案（必须二选一落地）**

方案 A（推荐，结构性正确）：
- 新增参数 `decay_target_prob`（建议 0.05），衰减目标从 `P=0.5` 改为低概率；确保无新命中时能穿越 `free_thresh`；
- `decay_rate` 语义调整为“log-odds 每秒衰减量”（建议 P0 先用 2.0，目标释放 2~3s）。

方案 B（赛前快速止血）：
- 保持向 `P=0.5` 衰减，但把 `free_thresh` 调到略高于 0.5（如 0.55），形成滞回带：`block_thresh(0.70)` / `free_thresh(0.55)`；
- 仍需引入 `ttl_sec` 兜底（见 2b）。

> 说明：方案 A 更可控、更符合阈值语义；方案 B 适合赛前快速救火，但需要更谨慎的误释放验证。

**2b. 引入 TTL 兜底（必做）**

- 新增参数：`ttl_sec`（建议 10.0；0 表示关闭）  
- 维护每格 `last_hit_time`：收到高置信度命中时更新；  
- `decayTimer()` 中若 `now - last_hit_time > ttl_sec`：强制释放该格（log-odds 拉到 `decay_target_prob` 或更低）。

**2c. 拾取强制释放（必做）**

目的：避免“已夹取但禁区仍残留”导致后续路径被幽灵禁区阻塞。

- 约定 topic：`/kfs_force_release_grid`（`std_msgs/msg/UInt8`，payload 为 `grid_id`）  
- `kfs_block_fuser` 订阅：收到 grid_id → 立即将该格释放并立刻 `publishMask()`  
- 验收指标：Grab 完成到 mask 解除 **P95 ≤ 0.5s**。

**2d. Keepout 几何与分辨率对齐（加分但强烈建议）**

- `map_resolution: 0.05 → 0.10`（对齐 `src/rc26_bringup/config/nav2_params.yaml` 的 costmap resolution=0.1）  
- 新增参数：
  - `keepout_shape: circle|square`（默认 square）
  - `block_half_size_m`（建议 0.60）
  - `keepout_margin_m`（建议 0.03）
- `publishMask()`：square 模式用“方块外接几何 + margin”，避免圆形膨胀覆盖相邻空块站位造成规划死锁。

**2e. 标定/队伍强校验 + 1.2m 自检（必做，评分 2.4）**

`mf_grid_layout.yaml` 增加元信息：
- `meta.team` / `meta.layout_version` / `meta.validated` / `meta.grid_spacing_m`

启动时校验：
- `validated=false` → `keepout_enabled=false`（硬约束，防止占位坐标上场）；
- 几何自检：按网格编号邻接关系（±1 / ±3）检查中心距是否接近 `grid_spacing_m=1.2 ± 0.05`；
- team 校验：`MfKfsState.team` 必须与 layout team 一致，否则 keepout 禁用并触发 safe/stop（至少做到 safe）。

**验收（必须闭环）**
- 概率释放：单格命中后停止命中，keepout 必须在 ≤3s 内释放（按 decay_rate 目标）；不得出现永久幽灵禁区。
- TTL：模拟上游停更，超时后必须释放。
- 强制释放：发布 `/kfs_force_release_grid` 后 mask 解除 P95≤0.5s。
- 自检：layout 占位/错配时必须禁用 keepout 并打 ERROR diagnostics（且 gate 不放行）。

**回滚**
- 保留 `keepout_shape=circle` 开关；几何不适配时可回滚形状，但**释放修复/TTL/强制释放不可回滚**。

### Step 3 · terrain_semantic：台阶 EMA 不冻结 + 姿态急停补偿 + 冻结上限（评分 1.1）

文件：
- `src/rc26_terrain/include/rc26_terrain/terrain_semantic_node.hpp`
- `src/rc26_terrain/src/terrain_semantic_node.cpp`
- `src/rc26_terrain/config/terrain_semantic.yaml`

**3a. jump guard 从“无限 continue”改为“可控冻结 + 台阶工况门控”**

必须满足评分表三点：
- `jump_thresh_m` 调整（建议 0.23）
- 台阶工况门控（不冻结）
- 冻结上限（冻结帧数≤3 或冻结≤300ms）

推荐实现（组合拳，最小闭环）：
1) 引入 `freeze_max_frames` + `freeze_count_`：跳变时计数，超过上限强制更新一次（慢 EMA），清零计数；
2) 引入 `ground_ema_alpha_slow`：台阶工况使用慢 EMA 逼近新地面高度；
3) 台阶工况判定信号（任选其二）：
   - 里程计线速度 `v > stair_gate_speed_mps`（建议 0.25）；
   - `base_ground/stable` 为 false（急停/姿态不稳窗口）；
   - nav profile 属于 `mf_traverse/stair_*`（若能在 terrain_semantic 侧拿到）。

**3b. 姿态/急停补偿（pitch compensation，评分表明确要求）**

在点云投影入桶（`bucket.push_back(...)`）前，对 Z 做俯仰补偿（开关参数 `enable_pitch_compensation`）：
- `pitch` 来源：`TF(map -> base_link)` 的 roll/pitch/yaw（已在 `cloudCallback()` 内解析）
- 修正：`z_corr = z_raw - x_rel * tan(pitch)`（仅对前方 x_rel 生效即可）

**3c. 参数落位（yaml）**

`src/rc26_terrain/config/terrain_semantic.yaml` 建议新增/修改：
- `jump_thresh_m: 0.23`
- `freeze_max_frames: 3`
- `ground_ema_alpha_slow: 0.25`
- `enable_pitch_compensation: true`
- `stair_gate_speed_mps: 0.25`（若实现速度门控）

**验收（必须闭环）**
- 200mm 台阶：`ground_z_filtered` ≤300ms 收敛，误差≤50mm；冻结帧数≤3；急停 10 次无长期冻结。

**回滚**
- `enable_pitch_compensation` 可关闭（仅用于定位异常）；冻结上限逻辑不可回滚。

## 4. Phase B — P1（强烈建议：把 70 分变成 90+）

### 4.1 近场盲区与强反光（评分 1.3）

建议补齐两条机制：
- near-zone（0.6m）自适应：对 `min_points_per_cell` / `rel_z` 过滤阈值做半径相关放宽，抑制“近场点稀疏导致的伪障碍闪烁”；
- `top_z` 上限保护：强制 `top_z <= ground_z + top_z_max_delta_m`（建议 0.7）避免反光尖峰。

验收：0.2~1.0m 近场无大面积闪烁；`top_z` 无异常尖峰。

### 4.2 对角盲区兜底 + 防切角（评分 1.4）

文件：
- `src/rc26_nav_mode_manager/src/terrain_mode_adapter.cpp`（MF profile：360° drop、unknown conservative、edge8）
- `src/rc26_decision/src/navigation/waypoint_manager.cpp` / MF 行为树（防对角直连）

推荐实现：
- MF profile drop 前向扇区放宽到 360°（或按动作阶段放宽）；
- 决策侧将 MF 网格移动限制为 4 邻接；对角移动必须拆成两段并插入中继 waypoint，避免 Nav2 平滑切角穿越角点高差。

验收：路线不出现对角切角进入禁区风险；角点场景可复现验证。

### 4.3 动态更新与端到端延迟（评分 3.2）

文件：`src/rc26_decision/src/decision_node.cpp`

- `/mf_kfs_state` 定时发布：500ms → 200ms（5Hz），QoS 深度 10 → 3（最新优先）；保留“状态变化立即发布”。
- e2e SLA：KFS 状态变化 → `/kfs_filter_mask` 更新 P95 ≤100ms；mask → costmap 生效 P95 ≤300ms。

### 5.2 延迟超限硬干预（评分 4.2）

文件：`src/rc26_terrain/src/terrain_semantic_node.cpp` + `src/rc26_terrain/config/terrain_semantic.yaml`

把 `latency_error_ms` 从 diagnostics 升级为动作触发器：
- 条件：`last_latency_ms_ > latency_error_ms_` 连续 N 帧（建议 N=3）

## 6. 验收用例（逐条对应评分表，必须可量化）

> 默认基准：R2（QCS8550）全负载 4 分钟跑圈日志；统计 P95。

### 6.1 评分 1.1（P0）— EMA 台阶过渡

- 场景：200mm 台阶跨越 + 急停重复 10 次
- 指标：`ground_z_filtered` ≤300ms 收敛（误差≤50mm）；冻结帧数≤3；无长期冻结
- 证据：terrain diagnostics + 日志计数（冻结计数/最大冻结时长）

### 6.2 评分 1.2（P0）— BFS 去噪与稀疏边界

- 场景：正常模式反光噪点 + MF 斜向接近台阶
- 指标：MF 单格保留率≥90%；正常模式单格噪点渗入≤5%
- 证据：切 profile 前后对比（参数读回 + 点云/栅格统计脚本）

### 6.3 评分 1.3（P1）— 近场盲区与强反光

- 场景：0.2~1.0m 近场停走 60s
- 指标：无大面积伪障碍闪烁；`top_z` 无 > ground+0.7m 尖峰

### 6.4 评分 1.4（P1）— 防切角

- 场景：角点路径（高差角点附近）
- 指标：路线不穿越角点禁区；对角移动被拆分为轴向移动

### 6.5 评分 3.1/2.1（P0/P1）— 启动门控 + Keepout 几何

- bringup 后 10s 内必须可观测 `/costmap_filter_info` 与 `/kfs_filter_mask`（transient_local）
- gate 未通过不得发 goal；通过后可发 goal
- keepout：紧邻 KFS 空块站位规划成功率 100%（不贴边）

### 6.6 评分 2.2（P0）— 释放死锁 + 强制释放

- 无新命中释放：≤3s
- TTL：通信/上游停更后在 TTL 内释放
- 强制释放：P95 ≤0.5s

### 6.7 评分 2.3/2.4（P0/P1）— 冷启动溯源 + 标定防错

- 启动即创建 `merlin_map`；`/mf_kfs_state` topic 存在
- layout validated/team 错配：必须禁用 keepout 并触发 safe/stop

### 6.8 评分 3.2（P1）— 端到端延迟

- `/mf_kfs_state` ≥5Hz；KFS 状态变化→mask 更新 P95≤100ms；mask→costmap 生效 P95≤300ms

### 6.9 评分 3.3（P0）— IPC 抖动与参数确认

- profile 连续切换 100 次：成功≥99%；失败触发 safe/stop_required

### 6.10 评分 4.1（P2）— 热降频 fallback

- 4 分钟降频压测不崩溃；fallback 下 terrain 延迟 P95≤22ms；keepout/跌落功能存活

### 6.11 评分 4.2（P2）— 延迟超限硬干预

- 超限连续 N 帧在 ≤350ms 内触发干预动作，且恢复后可解除
