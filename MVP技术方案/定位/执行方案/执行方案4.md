1. rc26_terrain 规则一致性修复 + 可观测性

**2c. cpp — classifyAndUpdate() 邻域循环替换**（lines 574–588）

将单一 8邻域循环拆分为两个独立循环：

```cpp
// obstacle dz_up — 4邻域
float dz_up = 0.0f;
for (auto [dx, dy] : std::array<std::pair<int,int>,4>{{{1,0},{-1,0},{0,1},{0,-1}}}) {
    const int nx = ix + dx, ny = iy + dy;
    if (nx < 0 || nx >= width_ || ny < 0 || ny >= width_) continue;
    const size_t nidx = static_cast<size_t>(nx * width_ + ny);
    if (last_seen_sec_[nidx] < 0.0 || (stamp_sec - last_seen_sec_[nidx]) > stale_time_sec_) continue;
    dz_up = std::max(dz_up, ground_z_filtered_[nidx] - ground_z_filtered_[idx]);
}
// drop dz_down — 8邻域
float dz_down = 0.0f;
for (int dx = -1; dx <= 1; dx++) {
    for (int dy = -1; dy <= 1; dy++) {
        if (dx == 0 && dy == 0) continue;
        const int nx = ix + dx, ny = iy + dy;
        if (nx < 0 || nx >= width_ || ny < 0 || ny >= width_) continue;
        const size_t nidx = static_cast<size_t>(nx * width_ + ny);
        if (last_seen_sec_[nidx] < 0.0 || (stamp_sec - last_seen_sec_[nidx]) > stale_time_sec_) continue;
        dz_down = std::min(dz_down, ground_z_filtered_[nidx] - ground_z_filtered_[idx]);
    }
}
```

若 `obstacle_neighbor_mode_ == "edge8"` 可配置回退，用 if 分支选择。

```cpp
if (min_obstacle_area_cells_ > 1) {

    for (int seed = 0; seed < num_cells_; seed++) {
        if (!obstacle_state_[static_cast<size_t>(seed)] || visited[static_cast<size_t>(seed)]) continue;

            for (auto [ddx, ddy] : std::array<std::pair<int,int>,4>{{{1,0},{-1,0},{0,1},{0,-1}}}) {
```

| 参数 | 值 |
|------|----|

| 释放阈值 | P=0.35（log-odds −0.619） |

```cpp
// 每次 /mf_kfs_state 到达：
for each cell in msg.cells where confidence >= min_confidence_:
    log_odds_[cell.grid_id] = clamp(log_odds_[...] + LO_HIT, -4.0, 4.0);

// 5Hz 衰减定时器：
for each cell: log_odds_[cell] = clamp(log_odds_[cell] - decay_rate_ * dt, -4.0, 4.0);

// 发布 OccupancyGrid /kfs_filter_mask：
cell prob > 0.70 → 100 (lethal) + inflate 0.60m
cell prob < 0.35 → 0 (free)
```

## 终审评审报告（Robocon 2026）

### 审计结论

当前《执行方案4》在地形语义与 KFS 禁行链路上具备较强可执行性，但尚未覆盖本次终审任务要求的定位主问题（高动态工况漂移 + 绑架重定位），暂不满足“终审可上线”标准。

### 3 个核心亮点

1. KFS 主链路从“待定接口”收敛为确定契约：`rc26_decision -> /mf_kfs_state -> kfs_block_fuser -> Nav2 KeepoutFilter`，落地路径完整。
2. TerrainModeAdapter 引入了幂等更新、参数异步下发与 `<120ms` 时延预算，模式联动工程化程度较高。
3. `rc26_terrain` 的邻域修复、连通域去噪、EMA 跳变保护与验收矩阵形成了明确闭环。

### 3 个严重不足

1. 方案明确排除了 `rc26_localization`，导致“频繁加减速位姿漂移、绑架后重定位恢复”未进入执行主线。
2. 融合深度不足：对 A/B 的合并偏执行清单，缺少对定位主链（LIO + 重定位状态机）的参数联调与验收绑定。
3. ROS2 契约不完整：新增链路对 `frame_id`、QoS、Hz、线程预算未做硬约束，跨模块联调风险偏高。

### 量化评分（100 分制）

| 维度 | 满分 | 得分 | 扣分理由 |
|------|------|------|----------|
| 融合深度 | 30 | 22 | 吸收了 A 的工程流程和 B 的部分实现细节，但定位主链缺位、关键细节落地不全。 |

| 工程鲁棒性 | 20 | 14 | 有超时和过滤策略，但缺少传感器失效状态机与跨传感器一致性门控。 |

| **总分** | **100** | **63** | **未达到终审通过阈值（80）** |

### 强制补充（低于 80 分，直接可交付开发）

#### 补充 A：新增漂移评分触发重定位（P0，必须）

目标：在 `rc26_localization` 内将“配准误差 + 运动不一致”合成单一触发量，替代仅靠 fitness 的滞后触发。

定义：

\[
S_k = 0.55\frac{e_k}{\tau_e} + 0.30\frac{\|v^{lio}_k-v^{odom}_k\|}{\tau_v} + 0.15\frac{|\omega^{lio}_k-\omega^{imu}_k|}{\tau_\omega}
\]

- `e_k`：当前配准归一化误差（沿用现有 normalized_error）
- `v^{lio}_k`：LIO 速度（`/state_estimation`）
- `v^{odom}_k`：底盘里程计速度（`/Can_Odom`，`use_can_odom=true`；或 `/wheel_odom`，`use_can_odom=false`）
- `\omega^{imu}_k`：IMU 角速度（默认 `/livox/imu`，与 Point-LIO 同源）
- 若改用外置 IMU（`/DM_IMU`），必须先完成外参旋转补偿与时间同步，再启用该项硬阈值判定。

触发策略：
- 当 `S_k > 1.0` 连续 `N=3` 帧时触发 `requestRelocalization("drift_score")`
- 或 `registration_timeout_sec` 到期时直接触发

建议修改文件：
- `src/rc26_localization/include/rc26_localization/localization.hpp`
- `src/rc26_localization/src/localization.cpp`
- `src/rc26_bringup/config/localization.yaml`

```cpp
// localization.cpp 伪代码
double S = 0.55 * (norm_err / drift_fitness_th_) +
           0.30 * (dv / drift_dv_th_) +
           0.15 * (domega / drift_dw_th_);

if (S > drift_score_trigger_) {
  drift_bad_count_++;
} else {
  drift_bad_count_ = std::max(0, drift_bad_count_ - 1);
}

if (drift_bad_count_ >= drift_bad_count_th_ || registrationTimedOut()) {
  setLocalizationState(LocalizationState::SUSPECT, "drift_score");
  requestRelocalization("drift_score");
  drift_bad_count_ = 0;
}
```

```yaml
# src/rc26_bringup/config/localization.yaml 追加
drift_score_enable: true
drift_ref_odom_topic: "/Can_Odom"     # use_can_odom=true
# drift_ref_odom_topic: "/wheel_odom" # use_can_odom=false
drift_ref_imu_topic: "/livox/imu"     # 默认；若改 /DM_IMU 需先做外参与时序标定
drift_fitness_th: 0.28
drift_dv_th: 0.45
drift_dw_th: 0.60
drift_score_trigger: 1.0
drift_bad_count_th: 3
```

#### 补充 B：新增传感器失效状态机（P0，必须）

定义每个传感器新鲜度：

\[
age_i = t_{now} - t_{last,i}
\]

- `T_warn < age_i <= T_fail` 标记 `WARN`
- `age_i > T_fail` 标记 `FAIL`

建议阈值：

| 传感器/话题 | `T_warn` | `T_fail` | 失效动作 |
|------------|----------|----------|----------|
| LiDAR `/livox/lidar` | 0.10s | 0.20s | 冻结 `map->odom` 更新，强制 `safe` 模式 |
| IMU `/livox/imu`（可选 `/DM_IMU`） | 0.04s | 0.08s | 关闭坡道补偿，保留平面策略 |
| Odom `/Can_Odom` / `/wheel_odom` | 0.06s | 0.12s | 漂移评分降级为仅误差项 |
| KFS `/mf_kfs_state` | 0.60s | 1.20s | 2s 内逐步释放 keepout |

```cpp
// watchdog 伪代码
if (lidar_fail) {
  freeze_map_to_odom_ = true;
  force_nav_mode_safe();
}
if (imu_fail) {
  slope_comp_enable_ = false;
}
if (odom_fail) {
  drift_velocity_term_enable_ = false;
}
if (kfs_fail) {
  scheduleKeepoutRelease(2.0);
}
publishHealthDiagnostics();
```

### 落地验收追加项（必须并入 M1）

1. 漂移触发重定位：急加速/急减速 20 组回放，重定位触发成功率 `>= 95%`，误触发率 `<= 5%`。
2. 绑架恢复：重试区搬移后 10 次测试，`map->odom` 恢复时间 P95 `< 2.0s`。
3. 失效降级：分别断开 LiDAR/IMU/Odom，系统不崩溃且发布 `WARN/ERROR` 诊断，导航进入安全策略。

### 说明

当前仓库未发现 UWB 相关实现接口，本强制补充按 LiDAR/IMU/Encoder 先闭环。若后续接入 UWB，应在漂移评分中追加 UWB 残差门控项并单独验收。
