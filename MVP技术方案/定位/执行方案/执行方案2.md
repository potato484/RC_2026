# R2 定位执行方案 2（实施版）

- 更新日期: 2026-02-18
- 适用对象: `RC_2026` 项目中的 `R2` 自动机器人（不含 R1）
- 文档目的: 记录当前代码已落地的执行方案与验收口径

## 1. 最终目标

定位恢复主链路收敛为：

`L1 重试区先验快速恢复` → `L2 Scan Context 全局检索恢复`

目标指标：

- `L1 P95 < 0.6s`
- `L2 P95 < 2.0s`
- `performRegistration()` 不再被重定位流程阻塞
- 具备结构化重定位日志，支持 bag 回放量化验收

## 3. 已落地代码变更

### 3.1 关键文件

- `src/rc26_localization/include/rc26_localization/localization.hpp`
- `src/rc26_localization/src/localization.cpp`
- `src/rc26_bringup/config/localization.yaml`

### 3.2 状态机与异步模型

- 主线程仅负责常规配准与重定位请求提交
- `requestRelocalization(reason, cloud)` 只入队
- `relocWorkerLoop()` 后台串行执行重定位（single-flight）
- 状态机统一管理可靠性与恢复阶段

### 3.3 L1/L2 主链路

- `L1`: `tryRetryZoneFastChannel()`
  - 使用重试区 `(x,y,yaw candidates)` 作为种子
  - 通过统一代价函数 `J` 挑选候选并判定接受

- `L2`: `tryScanContextGlobalChannel()`
  - 启动后离线构建 Scan Context 数据库
  - 在线阶段执行 ring-key 检索、列移位估计 yaw、`small_gicp` 精配准

### 3.4 结构化指标日志

每次重定位输出：

`RELOC_METRIC,trigger_reason,path_used,t_total_ms,t_l1_ms,t_l2_ms,candidate_count,best_fitness,best_J,accepted`

## 6. 验收执行指引（下一步）

### 6.1 赛前强约束检查

`competition_mode=true` 时，以下未满足将导致节点拒绝启动：

- `retry_zone_enable == true`
- `retry_zone_x/y` 不能为占位值 `(0.0, 0.0)`

### 6.2 bag 回放验收场景

1. 正常跟踪 + 短时遮挡（不应误触发）
2. 强制重试回 RZ（应优先命中 L1）
3. RZ 偏差 + 遮挡（L1 失败后稳定降级到 L2）

### 6.3 指标提取建议

从 ROS 日志中提取结构化指标行：

```bash
grep "RELOC_METRIC" <ros_log_file> > reloc_metrics.log
```

然后按项目常用统计方式计算 `P50/P95` 与误触发率。

### 6.4 通过门槛

- `L1 场景: P95(t_total_ms) < 600ms`
- `L2 场景: P95(t_total_ms) < 2000ms`
- `误触发率 <= 1 次 / 10 分钟`
- `恢复后 2 秒内 TF 无肉眼可见跳变`
