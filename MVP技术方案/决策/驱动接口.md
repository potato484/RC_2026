# 第一部分：模块接口速查

## 1. 串口驱动 (SerialDriver)

> 本仓库里 `SerialDriver` 是“**与 MCU 通信的串口驱动**”。它既可用于发送动作类指令（如抓取、旋转），也可被 `PoseSender` 用来下发速度闭环目标（`POSE_TARGET(0x22)`）。

### 配置参数

```yaml
rc26_decision:
  ros__parameters:
    enable_cmd_serial: true        # 是否启用“命令串口”（发动作/模式等）
    cmd_serial_port: "/dev/ttyUSB1" # 命令串口设备
    cmd_baudrate: 115200           # 命令串口波特率（注意与协议/硬件保持一致）
    enable_heartbeat: true         # 是否启用心跳保活
    heartbeat_rate_hz: 1           # 心跳频率（Hz）
```

### 黑板键值

| 键名 | 类型 | 说明 |
|:-----|:-----|:-----|
| `cmd_serial` | `shared_ptr<SerialDriver>` | 指令串口句柄 |
| `cmd_serial_reconnecting` | `bool` | 串口是否正在重连 |
| `grab_tip_done` | `bool` | 抓取矛头完成 (反馈自动映射) |

### C++ 接口

```cpp
// 发送指令（示例：抓取矛头）
std::shared_ptr<SerialDriver> serial;
if (!config().blackboard->get("cmd_serial", serial) || !serial) {
  return BT::NodeStatus::FAILURE;
}
serial->sendCommand(CommandID::GRAB_TIP);

// 检查反馈
bool done = false;
(void)config().blackboard->get("grab_tip_done", done);
```

## 2. 速度下发 (PoseSender：/cmd_vel -> POSE_TARGET)

> 作用：订阅 `/cmd_vel`（或 `/cmd_vel_teleop`），将 `(vx, vy, wz)` 通过串口协议下发到 MCU：`POSE_TARGET(0x22)`。

### ROS 接口说明

**订阅（Subscribe）**
- `cmd_vel_topic`：`geometry_msgs/msg/Twist`（默认 `cmd_vel`）
- `odom_topic`：`nav_msgs/msg/Odometry`（用于反馈速度上报，默认 `merge_odom`）

**串口下发（TX to MCU）**
- `POSE_TARGET(0x22)`：12B payload（3×float：vx, vy, wz）

### 参数示例（merge_odom_params.yaml）

```yaml
pose_sender_node:
  ros__parameters:
    feedback_serial_port: "/dev/ttyUSB0"  # 反馈串口（上报 POSE_FEEDBACK）
    target_serial_port: "/dev/ttyUSB1"    # 目标串口（下发 POSE_TARGET）
    baudrate: 1000000                     # 串口协议波特率（协议默认 1Mbps）
    cmd_vel_topic: "cmd_vel"              # 订阅速度指令话题（导航通常是 cmd_vel）
    odom_topic: "merge_odom"              # 订阅里程计（用于反馈速度上报）
    feedback_send_rate_hz: 50             # POSE_FEEDBACK 发送频率
    target_send_rate_hz: 25               # POSE_TARGET 发送频率
```

> 遥控模式切换：叠加参数文件 `src/rc26_merge_odom/config/pose_sender_cmd_vel_teleop.yaml`，将 `cmd_vel_topic` 改为 `cmd_vel_teleop`。

## 3. 智能导航 (SmartWaypointNavigator)

> 支持语义航点、参数热切换、安全模式联动。

### 配置参数 (waypoints.yaml)

```yaml
static_points:
  combat_entry:
    pose: {x: 1.5, y: 2.0, yaw: 1.57}
    speed_profile: "FAST"        # 速度档：FAST/SLOW/CREEP（用于缩放控制器限速）
    nav_profile: "normal"        # profile 名：对应 nav_profiles.yaml 里的键（normal/safe/stair_up/...）
    tolerance: {xy: 0.15, yaw: 0.1} # 到点容差：位置/角度
```

### 字段说明：哪些是“直接定义”，哪些会“映射/转换”

**直接定义（写什么就基本按什么用）**
- `pose.(x,y,yaw)`：直接作为 Nav2 `NavigateToPose` 的 goal pose
- `timeout_sec`：直接作为本次导航超时（超时会取消 goal 并进入失败清理）
- `nav_profile`：直接作为 profile 字符串传给 `set_nav_mode`（例如 `"normal"`, `"stair_up"`）
- `strategy_tag`：直接作为 `set_nav_mode` 的 `reason`（用于记录切换原因/日志）

**映射/转换（写的是“语义”，运行时会变成别的参数/指令）**
- `speed_profile`：会映射成“控制器限速缩放”，最终转成 controller_server 动态参数：
  - `FollowPath.v_linear_max`
  - `FollowPath.v_angular_max`
  - FAST/SLOW/CREEP 的比例可通过全局参数配置：`speed_profile_scales.fast/slow/creep`
- `tolerance.{xy,yaw}`：会映射成 goal checker 动态参数：
  - `general_goal_checker.xy_goal_tolerance`
  - `general_goal_checker.yaw_goal_tolerance`
- `payload.{v_linear_max,v_angular_max}`：如果提供，会覆盖 `speed_profile` 的缩放结果，直接指定上述控制器参数的最终值

### 全局参数：speed_profile 比例配置（rc26_decision）

> `speed_profile` 的 FAST/SLOW/CREEP 比例不写在点位里，而是全局参数（对所有点位生效）。

```yaml
rc26_decision:
  ros__parameters:
    # speed_profile 全局缩放系数（用于点位里的 speed_profile: FAST/SLOW/CREEP）
    # 最终会缩放 controller_server 的 FollowPath.v_linear_max / FollowPath.v_angular_max
    speed_profile_scales.fast: 1.0   # FAST 档缩放（默认 1.0）
    speed_profile_scales.slow: 0.4   # SLOW 档缩放（默认 0.4）
    speed_profile_scales.creep: 0.2  # CREEP 档缩放（默认 0.2）
```

### ROS 接口说明

**Action（发给 Nav2）**
- action 名：`navigate_to_pose`
- action 类型：`nav2_msgs/action/NavigateToPose`

**Service（安全/模式切换）**
- service 名：`set_nav_mode`
- service 类型：`rc26_interfaces/srv/SetNavMode`（字段：`profile`, `timeout`, `reason`）

**Topic（安全状态）**
- topic 名：`nav_safety_state`
- topic 类型：`rc26_interfaces/msg/NavSafetyState`（字段：`current_profile`, `stop_required`, `timed_out` 等）

### Profile 配置示例（nav_profiles.yaml）

```yaml
# src/rc26_nav_mode_manager/config/nav_profiles.yaml
profiles:
  safe:
    fallback_profile: safe                 # 回退 profile（一般 safe 自己回退自己）
    watchdog: {timeout_sec: 0, stop_required_on_timeout: false}  # 超时保护：0 表示不启用
    precheck: {require_stopped: false}     # 切换到该 profile 前是否要求机器人停稳
    costmap: {clear_on_switch: false}      # 切换时是否清 local costmap
    controller: {v_linear_max: 0.3, v_angular_max: 0.5}          # 控制器限速（动态参数）

  normal:
    fallback_profile: safe                 # normal 出问题时回退到 safe
    watchdog: {timeout_sec: 0, stop_required_on_timeout: false}  # 0：不启用超时
    precheck: {require_stopped: false}     # normal 通常不要求停稳再切
    costmap: {clear_on_switch: false}      # normal 通常不清图
    controller: {v_linear_max: 0.8, v_angular_max: 1.0}          # normal 的速度上限
```

### 实现原理：watchdog / precheck / costmap

这三个字段都由 `rc26_nav_mode_manager` 在处理 `set_nav_mode(profile)` 时执行，核心逻辑是“**ProfileExecutor 执行切换步骤 + WatchdogTimer 超时回退**”。

### 数据来源：precheck 与 costmap 用到的输入来自哪里？

**precheck（停稳判定）的数据来源**
- 来源：`nav_msgs/msg/Odometry`（里程计话题）
- 使用字段：
  - `twist.twist.linear.x / linear.y` 计算线速度模长 `sqrt(vx^2 + vy^2)`
  - `twist.twist.angular.z` 取绝对值作为角速度 `abs(wz)`
- 订阅话题名由 `nav_mode_manager` 参数 `odom_topic` 决定（默认 `odom`）

**costmap（清图）的“输入/依赖”来源**
- 来源：不是传感器 topic，而是 Nav2 的服务接口
- 调用服务类型：`nav2_msgs/srv/ClearEntireCostmap`
- 清 local costmap 的服务名由参数 `costmap_node_name` 推导（典型 `local_costmap/local_costmap` → `local_costmap/clear_entirely_local_costmap`）

**1) `precheck.require_stopped`（切换前停稳校验）**
- 实现：`ProfileExecutor` 订阅 `odom_topic`（默认 `odom`），计算
  - `sqrt(vx^2 + vy^2)` 作为线速度
  - `abs(wz)` 作为角速度
- 当 `require_stopped: true` 时，若未收到里程计或速度未低于阈值，会拒绝切换（服务返回失败）。
- 阈值由参数控制：
  - `stop_linear_eps_mps`（默认 0.05）
  - `stop_angular_eps_rps`（默认 0.05）

**2) `costmap.clear_on_switch`（切换时清 local costmap）**
- 实现：若 `clear_on_switch: true`，调用 Nav2 的 `ClearEntireCostmap` 服务清空 local costmap。
- 服务名由参数 `costmap_node_name` 推导：取其最后一个 `/` 之前的前缀作为命名空间，拼接 `clear_entirely_local_costmap`。
  - 典型配置：`costmap_node_name: "local_costmap/local_costmap"`
  - 对应服务：`local_costmap/clear_entirely_local_costmap`
- 超时由参数控制：`clear_timeout_sec`（默认 2.0）

**3) `watchdog.timeout_sec` + `fallback_profile`（超时回退）**
- 实现：profile 切换成功后，`NavModeManager` 会启动一个定时器：
  - 超时时间取 `set_nav_mode` 请求里的 `timeout`（>0 时）优先生效，否则使用 profile 的 `watchdog.timeout_sec`
- 一旦超时：
  - 设置 `nav_safety_state.timed_out=true`
  - 若 profile 配置 `watchdog.stop_required_on_timeout=true`，则同时设置 `stop_required=true`（提示上层取消导航/停机）
  - 按 `fallback_profile` 递归回退，直到成功或回退到终止点（通常 `safe -> safe`）

**nav_mode_manager 相关参数示例**

```yaml
nav_mode_manager:
  ros__parameters:
    odom_topic: "odom"                          # 给 precheck 用的里程计话题
    controller_server_node: "controller_server" # 给 controller 参数服务用
    costmap_node_name: "local_costmap/local_costmap" # 推导 clear 服务名
    stop_linear_eps_mps: 0.05
    stop_angular_eps_rps: 0.05
    clear_timeout_sec: 2.0
    param_timeout_sec: 2.0
```

**参数动态切换（controller_server）**
- 通过参数服务修改（典型）：
  - `FollowPath.v_linear_max`
  - `FollowPath.v_angular_max`
  - `general_goal_checker.xy_goal_tolerance`
  - `general_goal_checker.yaw_goal_tolerance`

|:-----|:-----|:-----|
| `waypoint_manager` | `shared_ptr<WaypointManager>` | 航点管理器 |
| `smart_waypoint_navigator` | `shared_ptr<SmartWaypointNavigator>` | 智能导航器 |

### 从行为树到 MCU 的完整数据流（含代码示例）

下面以行为树里调用：

```xml
<NavToSmartPoint target_name="combat_entry"/>
```

为例，说明“点位触发后，最终有哪些东西会下发到 MCU”。

#### Step A：行为树触发导航（按点名取点）

`NavToSmartPoint` 会从黑板拿到 `WaypointManager` 和 `SmartWaypointNavigator`，并按点名启动：

```cpp
// src/rc26_decision/src/navigation/bt_nav_to_smart_point.cpp（简化示例）
std::shared_ptr<WaypointManager> waypoint_manager;
config().blackboard->get("waypoint_manager", waypoint_manager);

std::shared_ptr<SmartWaypointNavigator> navigator;
config().blackboard->get("smart_waypoint_navigator", navigator);

const SmartWaypointSpec* wp = waypoint_manager->find(target_name);
return navigator->start(*wp) ? BT::NodeStatus::RUNNING : BT::NodeStatus::FAILURE;
```

#### Step B：切 profile（安全/清图/限速策略）

`SmartWaypointNavigator::tick()` 的第一阶段会调用 `set_nav_mode(profile)`，用于切换安全/清图/限速等策略：

```cpp
// src/rc26_decision/src/navigation/smart_waypoint_navigator.cpp（简化示例）
requestSetMode(profile, active_.timeout_sec, active_.strategy_tag, ...);
if (pollSetMode(...)) {
  exec_state_ = ExecState::ApplyParams;
}
```

#### Step C：Nav2 输出 `/cmd_vel`，PoseSender 把速度闭环目标持续下发到 MCU

当 Nav2 开始导航后，会持续在 `/cmd_vel` 输出速度；`PoseSender` 订阅该话题并周期性下发 `POSE_TARGET(0x22)`：

```cpp
// src/rc26_merge_odom/src/pose/pose_sender.cpp（简化示例）
// 收到 /cmd_vel 更新目标速度
void PoseSender::cmdVelCallback(const geometry_msgs::msg::Twist::SharedPtr msg) {
  target_vel_.vx = msg->linear.x;
  target_vel_.vy = msg->linear.y;
  target_vel_.wz = msg->angular.z;
  last_cmd_vel_time_ = now;
}

// 定时器：通过串口协议下发 POSE_TARGET(0x22)，payload = 3×float(vx,vy,wz)
void PoseSender::targetTimerCallback() {
  target_serial_->sendPose(CommandID::POSE_TARGET, target.vx, target.vy, target.wz);
}
```

最终 MCU 侧能“看到”的下发数据是：
- **高频的速度闭环目标**：`POSE_TARGET(0x22)`（12B，3×float：vx, vy, wz）

## 4. 台阶层级 (base_ground)

> 计算机器人当前台阶层级，供行为树判断上/下台阶完成。

### ROS 话题

| 话题 | 类型 | 说明 |
|:-----|:-----|:-----|
| `base_ground/level` | `Int32` | 当前绝对层级 (0, 1, 2...) |
| `base_ground/stair_delta` | `Int8` | 层级变化脉冲 (+1/-1) |
| `base_ground/stable` | `Bool` | 是否稳定 |

### 黑板键值

| 键名 | 类型 | 说明 |
|:-----|:-----|:-----|
| `current_level` | `int32` | 当前层级 |
| `stair_delta` | `int8` | 层级变化脉冲 |
| `base_ground_stable` | `bool` | 是否稳定 |
| `stair_climb_done` | `bool` | 上台阶完成 |
| `stair_descend_done` | `bool` | 下台阶完成 |

### 行为树节点

| 节点名 | 说明 |
|:-------|:-----|
| `StairClimb` | 等待上台阶完成 (level >= start + 3) |
| `StairDescend` | 等待下台阶完成 (level <= start - 3) |

## 5. 视觉推理 (rc26_vision)

> 基于 YOLO 的目标检测，支持多模型切换。

### 配置参数

**多模型模式**（推荐，`vision_models.yaml`）：
```yaml
rc26_decision:
  ros__parameters:
    enable_vision: true
    # 例：/home/potato/RC_2026/src/install/rc26_vision/share/rc26_vision/config/vision_models.yaml
    vision_config_file: "/path/to/vision_models.yaml"

vision:
  default_model: "yolo_default"
  models:
    yolo_default:
      engine: onnxruntime
      model_path: "/path/to/yolo.onnx"
      conf_thresh: 0.5
      labels: ["R_R1", "B_R1", "T_03"]
    yolo_small:
      engine: onnxruntime
      model_path: "/path/to/yolo_small.onnx"
      conf_thresh: 0.6
      input_w: 320
      input_h: 320
```

### 黑板键值

| 键名 | 类型 | 说明 |
|:-----|:-----|:-----|
| `vision_manager` | `shared_ptr<VisionInferenceManager>` | Manager 句柄 |
| `vision_running` | `bool` | 推理是否运行中 |
| `vision_ok` | `bool` | 系统健康状态 |
| `vision_has_target` | `bool` | 是否检测到目标 |
| `vision_attr_kind` | `int` | 目标属性 (3=Truth, 4=False) |
| `vision_distance_m` | `double` | 目标距离 (米) |
| `vision_current_model` | `string` | 当前模型 ID |

### 行为树节点

| 节点名 | 端口 | 说明 |
|:-------|:-----|:-----|
| `VisionStart` | `model_id` (可选) | 启动推理 |
| `VisionStop` | 无 | 停止推理 |
| `VisionSetModel` | `model_id` | 切换模型 |
| `WaitVisionTarget` | `target_attr`, `max_dist`, `timeout` | 等待目标 |

**WaitVisionTarget 端口**：
- `target_attr`: `Truth` / `False` / 空 (任意)
- `max_dist`: 最大距离 (米)，<=0 不限制
- `timeout`: 超时 (ms)，默认 1000

### C++ 接口

```cpp
auto manager = config().blackboard->get<
    std::shared_ptr<rc26_vision::VisionInferenceManager>>("vision_manager");

manager->switchModel("yolo_small");  // 切换模型
manager->start();                     // 启动推理
manager->stop();                      // 停止推理
```

```cpp
BT::NodeStatus GrabTipAction::onStart() {
    auto serial = config().blackboard->get<std::shared_ptr<SerialDriver>>("cmd_serial");
    serial->sendCommand(CommandID::GRAB_TIP);
    return BT::NodeStatus::RUNNING;

BT::NodeStatus GrabTipAction::onRunning() {

    return BT::NodeStatus::RUNNING;
}
```

```xml
        <!-- 假目标 → 跳过 -->

            <WaitVisionTarget target_attr="False" timeout="2000"/>
        </Sequence>
        <!-- 超时 → 下一点 -->
        <NavToSmartPoint target_name="next_point"/>
    </Fallback>
    <VisionStop/>
</Sequence>
```

## C++ 自定义节点模板

```cpp
#include "rc26_serial/serial_driver.hpp"
#include "rc26_serial/protocol.hpp"

class MyAction : public BT::StatefulActionNode {
public:
    BT::NodeStatus onStart() override {
        // 发送指令
        auto serial = config().blackboard->get<
            std::shared_ptr<SerialDriver>>("cmd_serial");
        serial->sendCommand(CommandID::MY_COMMAND);
        return BT::NodeStatus::RUNNING;
    }

    BT::NodeStatus onRunning() override {
        // 检查串口重连
        if (config().blackboard->get<bool>("cmd_serial_reconnecting")) {
            return BT::NodeStatus::RUNNING;
        }

        // 检查视觉结果
        bool has_target = false;
        double distance_m = 0.0;
        int attr_kind = 0;
        config().blackboard->get("vision_has_target", has_target);
        config().blackboard->get("vision_distance_m", distance_m);
        config().blackboard->get("vision_attr_kind", attr_kind);

        if (has_target && attr_kind == 3 && distance_m < 1.5) {
            return BT::NodeStatus::SUCCESS;
        }

        // 检查台阶层级
        int32_t level = 0;
        config().blackboard->get("current_level", level);

        return BT::NodeStatus::RUNNING;
    }

    void onHalted() override {}
};
```
