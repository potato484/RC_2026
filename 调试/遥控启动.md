# 遥控启动

当前仓库的人工遥控正式入口只有根目录 `start_r2_teleop.sh`。旧的最小 MCU 遥控入口已经并入统一脚本，当前以 `./start_r2_teleop.sh --stack minimal-mcu` 为准，不再单独维护独立正式入口。

当前已知状态是：可以通过遥控器发送指令并控制机器人移动。因此整车联调默认从“遥控已通过”继续向后推进建图、定位、重定位、回环和导航。

默认遥控输出话题为 `cmd_vel`，默认最大线速度为 `0.3 m/s`，可通过 `--v-linear` 覆盖。当前运行时已经删除 `terrain_speed_limit` 全链路；无论测试 `stick` 还是 `dpad`，teleop 都不会再受到 terrain 限速影响。

相关模块：
- [rc26_telecontrol调试](./rc26_telecontrol调试.md)
- [rc26_merge_odom调试](./rc26_merge_odom调试.md)
- [rc26_mechanism调试](./rc26_mechanism调试.md)
- [rc26_serial调试](./rc26_serial调试.md)

## 使用前提

- 当前工作目录位于仓库根目录 `RC_2026`
- 已完成编译，并存在 `install/setup.bash`
- 手柄已连接，默认设备名为 `Xbox 360 Controller`

建议编译命令：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
MAKEFLAGS='-j2 -l2' colcon build --executor sequential --parallel-workers 1 --packages-select rc26_merge_odom rc26_telecontrol rc26_mechanism
source "${RC26_WS:-$HOME/RC_2026}/install/setup.bash"
```

## 启动栈

- `--stack full`：
  - 启动 `rc26_merge_odom`
  - 启动 `joy/joy_node`
  - 启动 `rc26_telecontrol` 或 `rc26_telecontrol_dpad`
  - 启动 `rc26_telecontrol_pushrod_dpad`
  - 启动 `rc26_telecontrol_front_track_test`
  - 不再自动启动 `rc26_mechanism`
- `--stack minimal-mcu`：
  - 启动 `pose_sender_node + joy_node + telecontrol + rc26_telecontrol_pushrod_dpad`
  - 用于“最小 MCU 串口遥控链”
  - 最小可用口径只要求 `target_serial_port` 可用，并允许 `feedback_serial_port` 禁用；不启动 `merge_odom`、`wheel_odom`、EKF、电动推杆上抬/后撑按钮测试节点和 mechanism server，但会由 `pose_sender_node` 继续挂出 `/mechanism/send_command` 与 `/mechanism/command_feedback`

## 常用命令

### 1. 默认全链遥控

```bash
./start_r2_teleop.sh
```

说明：

- 默认 `--stack full`
- 默认 `dpad`，按麦克纳姆全向口径输出
- 默认最大线速度为 `0.3 m/s`
- 默认不启动 EKF
- `Dpad 上/下` 控制 `linear.x`，`Dpad 左/右` 控制 `linear.y`
- `X(button[2]) -> +wz`、`B(button[1]) -> -wz` 控制旋转
- `Back(button[6]) / Start(button[7])` 按下沿会直接走 `/mechanism/send_command` 触发 `PUSHROD_EXTEND(0x10) / PUSHROD_RETRACT(0x11)`
- `Y(button[3]) / A(button[0])` 直接走 `/mechanism/send_command` 做电动推杆上抬/后撑联调，按下沿单次触发 `0x0E / 0x0F`，按住不连发；若 MCU 不回 ACK，会按可靠命令规则自动重传并报超时日志

### 2. 启用 EKF 并使用 IMU

```bash
./start_r2_teleop.sh --pose-mode imu
```

说明：

- 会自动传 `start_ekf:=true`
- 最终 `merge_odom` 继续融合 `DM_IMU`

### 3. 启用 EKF 但最终融合不使用 IMU

```bash
./start_r2_teleop.sh --pose-mode no-imu
```

说明：

- 会自动传 `start_ekf:=true use_imu_for_ekf:=false`
- `dm_imu_node`、PoseSender 和底层保护链仍继续读取 IMU

### 4. wheel-only 遥控

```bash
./start_r2_teleop.sh --pose-mode wheel-only
```

说明：

- 会自动传 `start_ekf:=true use_imu_for_ekf:=false start_imu:=false`
- 不会启动 `dm_imu_node`
- `WheelOdom`、`CanOdom`、`PoseSender` 都不再创建 IMU 订阅
- `slip_enable`、`imu_gate_enable`、`latency_comp_enable` 会一起关闭

### 5. 最小 MCU 串口遥控链

```bash
./start_r2_teleop.sh --stack minimal-mcu
```

说明：

- 启动 `pose_sender_node + joy_node + telecontrol + rc26_telecontrol_pushrod_dpad`
- 适合至少只保留目标串口速度下发就能工作的现场
- 若反馈串口也可用，`pose_sender_node` 仍会按端口是否存在分别尝试打开
- 会继续提供 `/mechanism/send_command` 与 `/mechanism/command_feedback`，因此 `Back/Start` 的推杆 ACK 指令仍可工作
- 不会启动电动推杆上抬/后撑按钮测试节点
- 不支持 `--pose-mode`

### 6. 调试参数展开

```bash
./start_r2_teleop.sh --dry-run
./start_r2_teleop.sh --dry-run --stack minimal-mcu
./start_r2_teleop.sh --dry-run --pose-mode wheel-only
./start_r2_teleop.sh --dry-run --stack full --pose-mode no-imu
```

## 串口口径

- `feedback_serial_port`：
  - 负责 `ODOM_DATA` 接收与 `POSE_FEEDBACK`
  - 当前默认 `/dev/ttyUSB0`
- `target_serial_port`：
  - 负责 `POSE_TARGET`、`/mechanism/send_command` 与 `/mechanism/command_feedback`
  - 当前默认 `/dev/ttyUSB1`

统一脚本在 `full` 和 `minimal-mcu` 两个栈下都会自动兼容“只有一个目标 MCU 串口”的现场：

- 若默认 `target_serial_port=/dev/ttyUSB1` 不存在，但 `/dev/ttyUSB0` 存在，脚本会自动把目标串口切到 `/dev/ttyUSB0`
- 若反馈串口缺失、与目标串口重复，或调用者显式传空值，脚本会把 `feedback_serial_port` 降级为 `__disabled__`
- 降级后仍会保留 `POSE_TARGET`、`/mechanism/send_command` 与 `/mechanism/command_feedback`

## 补充说明

- 按 `Ctrl+C` 会同时停止整条遥控链路
- `--stats-log` 会打开 PoseSender 的 1 秒统计日志
- 兼容旧用法：单独传 `--start-ekf` 时，行为仍保持为“启动 EKF 且 EKF 使用 IMU”

如需直接手写 `ros2 launch` 开启“完全不读 IMU 的 wheel-only 口径”，请使用：

```bash
ros2 launch rc26_merge_odom merge_odom.launch.py start_ekf:=true use_imu_for_ekf:=false start_imu:=false
```
