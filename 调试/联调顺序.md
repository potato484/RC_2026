# R2 联调顺序

本页是当前机器人运动主链的唯一联调顺序说明。默认不要跳阶段；上一阶段没过，不进入下一阶段。

## 0. 遥控

目标：确认底盘、手柄、速度指令链已经可控。

当前状态：

- 已验证可以通过遥控器发送指令控制机器人移动

执行：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
./start_r2_teleop.sh
```

通过标准：

- `/cmd_vel` 有持续输出
- 手柄摇杆和按键控制与实际底盘动作一致
- Watchdog 超时后车辆会回零停车

失败回退：

- 回到 [遥控启动](./遥控启动.md)
- 优先检查 `joy_node`、`rc26_telecontrol`、`rc26_merge_odom`

## 1. 建图

目标：确认 Mid-360、Point-LIO、里程计链和 PCD 保存能正常工作。

执行：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
MAKEFLAGS='-j2 -l2' colcon build --executor sequential --parallel-workers 1 \
  --packages-select rc26_mid360_driver rc26_point_lio rc26_odom_interface rc26_sensor_scan rc26_bringup
source "${RC26_WS:-$HOME/RC_2026}/install/setup.bash"
ros2 launch rc26_bringup test_mapping.launch.py
```

通过标准：

- `/state_estimation`、`/cloud_registered`、`/registered_scan` 正常输出
- `/Laser_map` 在初始化完成后能输出初始地图
- 若 Point-LIO YAML 已显式开启 `pcd_save.pcd_save_en`，建图结束后 `src/rc26_point_lio/PCD/` 下能看到导出的 `.pcd`

失败回退：

- 回到 [建图启动](./建图启动.md)
- 先确认 `mid360_driver -> point_lio -> odom_interface -> sensor_scan` 链路

## 2. 定位

目标：在已有先验地图下确认基础定位链稳定，不先开图后端。

执行：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
MAKEFLAGS='-j2 -l2' colcon build --executor sequential --parallel-workers 1 \
  --packages-select rc26_localization rc26_bringup
source "${RC26_WS:-$HOME/RC_2026}/install/setup.bash"
ros2 launch rc26_bringup test_localization_chain.launch.py \
  prior_pcd_file:=${RC26_WS:-$HOME/RC_2026}/src/rc26_point_lio/PCD/scans.pcd
```

通过标准：

- `map -> odom` 持续存在
- `/localization/pose_with_cov` 与 `/localization/diagnostics` 正常输出
- 机器人静止时位姿不明显漂移

失败回退：

- 回到 [定位启动](./定位启动.md)
- 优先检查先验 PCD、`/odom`、`/registered_scan`、`odom -> base_link`

## 3. 重定位

目标：确认定位丢失或初始位姿不一致时，系统能重新锚定回正确地图。

执行：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
source "${RC26_WS:-$HOME/RC_2026}/install/setup.bash"
ros2 launch rc26_bringup test_relocalization.launch.py \
  prior_pcd_file:=${RC26_WS:-$HOME/RC_2026}/src/rc26_point_lio/PCD/scans.pcd
```

测试动作：

- 在已知地图内改变机器人初始摆放位置后重新启动
- 或让机器人离开原可观测区后再回到已知区域

通过标准：

- `/localization/reloc_state` 能反映重定位进度
- `map -> odom` 能恢复到稳定状态
- `/localization/health` 最终回到可用状态

失败回退：

- 回到 [重定位启动](./重定位启动.md)
- 若基础定位本身不稳，先退回 [定位启动](./定位启动.md)

## 4. 回环

目标：确认 `rc26_localization` 图后端闭环能被触发并更新后端状态。

执行：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
source "${RC26_WS:-$HOME/RC_2026}/install/setup.bash"
ros2 launch rc26_bringup test_loop_closure.launch.py \
  prior_pcd_file:=${RC26_WS:-$HOME/RC_2026}/src/rc26_point_lio/PCD/scans.pcd
```

测试动作：

- 让机器人沿可重复路径走回已访问区域
- 在观测条件稳定时观察闭环候选和后端状态变化

通过标准：

- `/localization/loop_closures` 有候选或接受记录
- `/localization/backend_status` 中 `accepted_loop_count`、`last_loop_age_sec` 会更新
- `/localization/route_observability` 不长期卡在高风险

失败回退：

- 回到 [回环启动](./回环启动.md)
- 若图后端之前就不稳定，先退回 [重定位启动](./重定位启动.md)

## 5. 导航

目标：在定位与回环稳定后，确认 `rc26_xhu_nav` 速度输出链路可拉通。

执行：

```bash
cd "${RC26_WS:-$HOME/RC_2026}"
MAKEFLAGS='-j2 -l2' colcon build --executor sequential --parallel-workers 1 \
  --packages-select rc26_interfaces rc26_xhu_nav rc26_bringup
source "${RC26_WS:-$HOME/RC_2026}/install/setup.bash"
ros2 launch rc26_bringup test_navigation.launch.py \
  prior_pcd_file:=${RC26_WS:-$HOME/RC_2026}/src/rc26_point_lio/PCD/scans.pcd
```

通过标准：

- `/xhu_nav/motion_mode_state`、`/xhu_nav/tracking_state`、`/xhu_nav/local_planner_state` 正常更新
- `/cmd_vel` 由 `xhu_motion_runtime_node` 持续输出
- 手动模式切换和 corridor 执行反馈正常

失败回退：

- 回到 [导航启动](./导航启动.md)
- 若定位或图后端状态异常，先退回 [定位启动](./定位启动.md) 或 [回环启动](./回环启动.md)
