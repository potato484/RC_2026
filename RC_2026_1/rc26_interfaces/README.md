# rc26_interfaces - 自定义消息接口模块

## 模块简介

`rc26_interfaces` 是机器人的"通信协议定义库"，专门负责定义各个模块之间通信使用的消息格式和服务接口。想象一下，两个人要交流，需要先约定好使用什么语言、词汇的含义、说话的格式。在机器人系统中，各个模块也需要约定好通信的格式，才能相互理解。这个模块就是定义这些"通信协议"的地方。

## 核心功能

### 消息类型定义

模块定义了自定义的消息类型，用于在各个模块之间传递特定类型的数据。消息类型就像是通信的"信封"，规定了数据的格式和含义。

### 服务类型定义

模块定义了自定义的服务类型，用于模块之间的请求-响应式通信。服务类型就像是"一问一答"的对话模板，规定了问题的格式和回答的格式。

### 类型统一管理

所有自定义的消息和服务类型都集中在这个模块中定义，确保整个项目中使用统一的数据格式。这就像统一使用相同的"语言"，避免因为格式不一致导致的通信问题。

## 定义的消息类型

### NavSafetyMode（导航安全模式消息）

这个消息用于发布导航系统的当前安全模式状态。

**字段说明**：
- **mode**：当前导航模式（无符号8位整数）
  - 0 = 正常模式（NORMAL）：在正常地面上使用，启用跌落保护
  - 1 = 梅林安全模式（MF_SAFE）：在梅林区域附近使用，启用跌落保护
  - 2 = 梅林穿越模式（MF_TRAVERSE）：穿越梅林区域时使用，关闭跌落保护
  - 3 = 梅林退出模式（MF_EXIT）：退出梅林区域时使用，关闭跌落保护
- **stamp**：时间戳，记录模式切换或状态更新的时间
- **reason**：模式切换或状态更新的原因（字符串），比如"进入梅林区域"、"任务超时"等
- **stop_required**：是否需要机器人停止（布尔值），true表示需要停止，false表示可以继续移动
- **timed_out**：是否因为超时而切换模式（布尔值），true表示因为超时自动切换，false表示正常切换

**使用场景**：
- 导航模式管理器发布当前模式状态
- 决策系统订阅模式状态，了解当前导航策略
- 其他需要了解导航模式的模块

## 定义的服务类型

### SetNavMode（设置导航模式服务）

这个服务用于请求切换导航模式。

**请求字段**：
- **mode**：目标导航模式（无符号8位整数），取值0-3，对应四种导航模式
- **timeout**：超时时间（32位浮点数，单位：秒），如果设置为0，使用默认超时时间。超过这个时间如果任务没有完成，会自动切换回安全模式
- **reason**：模式切换的原因（字符串），用于日志记录和调试

**响应字段**：
- **success**：请求是否成功（布尔值），true表示成功，false表示失败
- **message**：响应消息（字符串），如果成功，通常包含成功信息；如果失败，包含失败原因

**使用场景**：
- 决策系统请求切换到穿越模式，以便机器人穿越梅林区域
- 决策系统请求切换回安全模式，确保后续导航安全
- 手动控制界面切换导航模式

## 数据流流向

### 导航模式状态发布流程

```
导航模式管理器
    │
    ├─→ 当前模式状态更新
    │       │
    │       ▼
    │   构造NavSafetyMode消息
    │       │
    │       ▼
    │   发布到nav_safety/state话题
    │       │
    │       ├─→ 决策系统 ← 订阅并接收
    │       │       │
    │       │       ▼
    │       │   根据模式调整决策策略
    │       │
    │       └─→ 其他模块 ← 订阅并接收
    │               │
    │               ▼
    │           根据模式调整行为
```

### 导航模式切换请求流程

```
决策系统
    │
    ├─→ 需要切换导航模式
    │       │
    │       ▼
    │   构造SetNavMode服务请求
    │       │
    │       ├─→ mode: 目标模式
    │       ├─→ timeout: 超时时间
    │       └─→ reason: 切换原因
    │       │
    │       ▼
    │   调用nav_safety/set_mode服务
    │       │
    │       ▼
    │   导航模式管理器 ← 接收请求
    │       │
    │       ├─→ 验证请求有效性
    │       ├─→ 检查机器人状态
    │       ├─→ 执行模式切换
    │       └─→ 返回响应
    │               │
    │               ├─→ success: 是否成功
    │               └─→ message: 响应消息
    │               │
    │               ▼
    │           决策系统 ← 接收响应
    │               │
    │               ▼
    │           根据结果调整行为
```

## 使用场景

### 导航模式管理

在需要切换导航模式时，使用SetNavMode服务发送请求。导航模式管理器接收请求后执行切换，并通过NavSafetyMode消息发布当前状态。决策系统和其他模块可以订阅状态消息，了解当前的导航模式。

### 状态监控

任何需要了解导航模式状态的模块都可以订阅NavSafetyMode消息。比如，可视化工具可以显示当前模式，日志系统可以记录模式切换历史，诊断系统可以检查模式是否正常。

### 安全控制

通过NavSafetyMode消息中的stop_required字段，导航模式管理器可以通知其他模块是否需要停止机器人。这在紧急情况或模式切换时非常重要。

### 超时监控

通过NavSafetyMode消息中的timed_out字段，其他模块可以知道模式是否因为超时而自动切换。这可以用于诊断和调试，了解为什么模式会改变。

## 注意事项

### 消息类型一致性

所有使用这些消息类型的模块必须使用相同版本的定义。如果消息类型定义发生变化，所有相关模块都需要重新编译。确保项目中所有模块都使用相同的接口定义非常重要。

### 服务调用超时

在调用SetNavMode服务时，应该设置合理的超时时间。如果服务调用超时，应该视为失败，并采取相应的处理措施。

### 模式值范围

NavSafetyMode中的mode字段只支持0-3的值，对应四种导航模式。如果使用其他值，可能会导致未定义的行为。

### 字符串字段长度

reason和message字段是字符串类型，理论上可以包含任意长度的文本。但在实际使用中，建议控制长度，避免占用过多资源。

## 技术细节

### ROS2接口定义

这些接口使用ROS2的接口定义语言（IDL）定义。消息类型定义在.msg文件中，服务类型定义在.srv文件中。ROS2会将这些定义编译成特定编程语言的代码。

### 消息序列化

当消息通过网络发送时，ROS2会自动将消息序列化（转换成字节流），然后在接收端反序列化（还原成对象）。这个过程对用户是透明的。

### 服务通信

服务通信是同步的，调用方会等待服务提供方处理请求并返回响应。如果服务提供方没有响应或响应超时，调用方会收到错误。

### 话题通信

话题通信是异步的，发布方发布消息后立即返回，不需要等待订阅方接收。多个订阅方可以同时订阅同一个话题。

## 编译和依赖

这个模块需要编译后才能被其他模块使用。编译后会生成对应编程语言的接口代码，其他模块可以包含这些代码来使用定义的接口。

## 扩展性

如果需要添加新的消息类型或服务类型，应该在这个模块中添加定义。这样可以确保所有模块使用统一的接口定义，避免不一致导致的问题。

## 版本管理

如果接口定义需要修改（比如添加字段、修改字段类型等），需要考虑向后兼容性。不兼容的修改可能导致使用旧版本接口的模块无法正常工作。
