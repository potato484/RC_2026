# RC2026 模块递进测试指令总结

本文档总结从建图→自主导航→攀爬阶梯的递进测试流程和指令，暂不考虑决策部分。

## 测试流程概述

```
建图阶段 (SLAM) 
    ↓
自主导航阶段 (Navigation)
    ↓
攀爬阶梯阶段 (Stair Climbing)
```

---

## 第一阶段：建图测试 (SLAM)

### 目标
建立环境的点云地图，为后续导航提供先验地图。

### 启动指令

#### 方式一：完整建图启动（推荐）
```bash
ros2 launch rc26_bringup bringup.launch.py \
    slam:=true \
    use_rviz:=true
```
**启动的模块**：
- ✅ 里程计链路（mid360_driver + point_lio + rc26_odom_interface + rc26_sensor_scan）
- ✅ 定位模块（建图模式下发布静态 TF：map → odom）
- ✅ 地形分析模块（rc26_terrain）
- ❌ Nav2导航栈（建图模式下不启动）
- ❌ 导航模式管理器（建图模式下不启动）
- ❌ 决策系统（默认启动，可通过 `use_decision:=false` 关闭）

**适用场景**：完整的建图流程，需要地形分析等上层模块配合

#### 方式二：仅启动里程计链路（用于单独测试）
```bash
ros2 launch rc26_bringup odometry.launch.py \
    slam:=true \
    use_rviz:=true
```
**启动的模块**：
- ✅ 里程计链路（mid360_driver + point_lio + rc26_odom_interface + rc26_sensor_scan）
- ✅ 静态TF（base_link → livox_frame）
- ❌ 定位模块（不启动）
- ❌ 地形分析模块（不启动）
- ❌ Nav2导航栈（不启动）
- ❌ 其他上层模块（都不启动）

**适用场景**：单独测试里程计功能，调试传感器数据或坐标转换问题

**简单说**：`bringup.launch.py` = 完整系统；`odometry.launch.py` = 只有最基础的里程计部分

### 启动的模块
1. **硬件驱动层**
   - `mid360_driver`: 激光雷达驱动，发布 `/livox/lidar` 和 `/livox/imu`
2. **里程计链路**
   - `point_lio`: LiDAR-IMU里程计，输出 `/state_estimation` 和 `/cloud_registered`
   - `rc26_odom_interface`: 坐标转换（lidar_odom → odom），输出 `/odom` 和 `/registered_scan`
   - `rc26_sensor_scan`: 发布 TF变换（odom → base_link）和 `/sensor_scan`
3. **定位系统（建图模式）**
   - 发布静态 TF变换（map → odom），保持 TF树完整性

### 验证检查点

#### 1. 硬件驱动检查
```bash
# 检查激光雷达数据
ros2 topic hz /livox/lidar
ros2 topic echo /livox/lidar --once

# 检查IMU数据
ros2 topic hz /livox/imu
ros2 topic echo /livox/imu --once
```
**预期结果**: 有稳定的点云和IMU数据输出，频率正常（通常10Hz或更高）

#### 2. 里程计检查
```bash
# 检查里程计数据
ros2 topic hz /odometry
ros2 topic echo /odometry --once

# 检查配准点云
ros2 topic hz /registered_scan
ros2 topic echo /registered_scan --once

# 检查TF变换
ros2 run tf2_ros tf2_echo odom base_link
```
**预期结果**: 
- 里程计数据正常输出
- 点云数据正常
- TF变换存在且数值合理

#### 3. 建图过程检查
在RViz中查看：
- 实时点云扫描（`/livox/lidar`）
- 配准点云（`/cloud_registered`）
- 地图累积效果（如果Point-LIO发布了地图话题）

### 地图保存
建图完成后，需要保存点云地图（具体保存方法取决于Point-LIO的配置）：
- 点云地图通常保存为 `.pcd` 格式
- 同时需要生成二维地图 `.yaml` 和 `.pgm` 用于Nav2导航

## 第二阶段：自主导航测试 (Navigation)

### 目标
使用已建立的地图进行定位和路径规划，实现自主导航。

### 前置条件
- 已完成建图阶段，具备点云地图（`.pcd`）和二维地图（`.yaml` + `.pgm`）
- 地图文件路径已知

### 启动指令

```bash
ros2 launch rc26_bringup bringup.launch.py \
    slam:=false \
    prior_pcd_file:=/path/to/map.pcd \
    map:=/path/to/map.yaml \
    use_decision:=false \
    use_rviz:=true
```

**参数说明**:
- `slam:=false`: 启用导航模式（关闭建图模式）
- `prior_pcd_file`: 点云地图文件路径（用于定位）
- `map`: 二维地图文件路径（用于Nav2导航）
- `use_decision:=false`: 暂时关闭决策系统（专注于导航测试）

### 启动的模块
1. **硬件驱动层**（同建图阶段）
2. **里程计链路**（同建图阶段）
3. **定位系统（导航模式）**
   - `rc26_localization`: 点云重定位，发布 map → odom 变换
4. **地形感知系统**
   - `rc26_terrain`: 地形分析，识别障碍物和跌落风险，发布 `/terrain_obstacles` 和 `/terrain_drop`
5. **导航系统**
   - `Nav2导航栈`: 路径规划和机器人控制
   - `rc26_omni_controller`: 自定义全向控制器（作为Nav2插件）
6. **导航模式管理器**
   - `rc26_nav_mode_manager`: 管理导航安全模式

### 验证检查点

#### 1. 定位系统检查
```bash
# 检查定位节点是否启动
ros2 node list | grep localization

# 检查map → odom变换
ros2 run tf2_ros tf2_echo map odom

# 在RViz中使用 "2D Pose Estimate" 工具设置初始位姿
# 观察定位是否收敛（查看定位节点日志）
```
**预期结果**:
- 定位节点正常运行
- TF变换正常
- 定位能够收敛（配准误差小）

#### 2. 地形感知检查
```bash
# 检查障碍物点云
ros2 topic hz /terrain_obstacles
ros2 topic echo /terrain_obstacles --once

# 检查跌落风险点云
ros2 topic hz /terrain_drop
ros2 topic echo /terrain_drop --once
```
**预期结果**: 
- 障碍物和跌落风险数据正常发布
- 在RViz中可视化，识别效果正常

#### 3. Nav2导航检查
```bash
# 检查导航服务
ros2 service list | grep nav

# 检查导航节点
ros2 node list | grep nav

# 检查代价地图（在RViz中可视化）
```
**预期结果**:
- 导航服务可用（如 `/navigate_to_pose`）
- 代价地图正常显示
- 全局和局部代价地图都有内容

#### 4. 路径规划测试
在RViz中：
1. 点击 "2D Nav Goal" 工具
2. 在地图上选择一个目标点
3. 观察是否有路径规划结果
4. 观察机器人是否开始移动
```bash
# 检查速度指令
ros2 topic echo /cmd_vel
```
**预期结果**:
- 能够成功规划路径
- 路径合理（避开障碍物）
- 速度指令正常发布

#### 5. 导航模式管理器检查
```bash
# 检查导航模式状态
ros2 topic echo /nav_safety/state

# 检查模式切换服务
ros2 service type /nav_safety/set_mode
ros2 service list | grep nav_safety
```
**预期结果**:
- 当前模式为 `NORMAL`（正常模式）
- 跌落保护层已启用
- 模式切换服务可用

## 第三阶段：攀爬阶梯测试 (Stair Climbing)

### 目标
测试机器人在需要攀爬阶梯或穿越有高度差地形时的导航能力。

### 前置条件
- 已完成自主导航测试，导航系统正常运行
- 机器人已到达需要攀爬的阶梯附近
- 确认阶梯位置和参数

### 测试流程

#### 步骤1: 确认当前导航状态
```bash
# 检查当前导航模式
ros2 topic echo /nav_safety/state

# 确认机器人已停止（攀爬前必须静止）
ros2 topic echo /odometry  # 检查速度
```
**预期结果**: 
- 当前模式为 `NORMAL`
- 机器人处于静止状态（线速度和角速度接近0）

#### 步骤2: 切换到穿越模式 (MF_TRAVERSE)

切换到穿越模式，关闭跌落保护层，允许机器人通过有高度差的地形。

```bash
# 切换到穿越模式
ros2 service call /nav_safety/set_mode \
    rc26_interfaces/srv/SetNavMode \
    "{mode: 2, timeout_sec: 10.0, reason: 'test_stair_climbing'}"
```

**参数说明**:
- `mode: 2`: MF_TRAVERSE（穿越模式）
- `timeout_sec: 10.0`: 超时时间（秒），超时后自动切换回安全模式
- `reason`: 切换原因（可选）

**验证切换成功**:
```bash
# 检查模式是否切换成功
ros2 topic echo /nav_safety/state
```
**预期结果**:
- `mode` 字段变为 `2` (MF_TRAVERSE)
- `drop_layer_enabled` 为 `false`（跌落保护层已关闭）
- `requires_stop` 可能为 `true`（需要停止等待代价地图重建）

#### 步骤3: 等待代价地图重建

切换到穿越模式后，系统会清理并重建代价地图，需要等待完成。

```bash
# 监控障碍物话题，确认有新数据到达（表示地图重建完成）
ros2 topic echo /terrain_obstacles

# 持续监控导航模式状态，直到 requires_stop 变为 false
ros2 topic echo /nav_safety/state
```

**预期结果**:
- 障碍物数据有更新
- `requires_stop` 变为 `false`
- 代价地图已重建完成

#### 步骤4: 规划路径通过阶梯

在RViz中：
1. 点击 "2D Nav Goal" 工具
2. 将目标点设置在阶梯的另一侧
3. 观察路径规划结果

```bash
# 检查路径规划结果
ros2 topic echo /plan

# 检查速度指令
ros2 topic echo /cmd_vel
```

**预期结果**:
- 路径规划成功（路径可能经过阶梯）
- 速度指令正常发布
- 机器人开始移动

#### 步骤5: 监控攀爬过程

```bash
# 持续监控机器人状态
ros2 topic echo /odometry  # 位置和速度
ros2 topic echo /nav_safety/state  # 导航模式状态

# 监控地面高度（如果有相关模块）
ros2 topic echo /base_ground/level  # 楼层信息
ros2 topic echo /base_ground/stair_delta  # 台阶变化
```

**预期结果**:
- 机器人能够移动通过阶梯
- 导航模式保持为穿越模式
- 地面高度信息有变化（如果有相关传感器）

#### 步骤6: 切换回安全模式

完成攀爬后，切换回安全模式，重新启用跌落保护层。

**方式一: 手动切换**
```bash
ros2 service call /nav_safety/set_mode \
    rc26_interfaces/srv/SetNavMode \
    "{mode: 0, timeout_sec: 0.0, reason: 'stair_climbing_completed'}"
```
**参数说明**:
- `mode: 0`: NORMAL（正常模式）
- `timeout_sec: 0.0`: 无需超时

**方式二: 等待超时自动切换**
如果设置了超时时间，系统会在超时后自动切换回安全模式。

**验证切换成功**:
```bash
ros2 topic echo /nav_safety/state
```
**预期结果**:
- `mode` 字段变为 `0` (NORMAL)
- `drop_layer_enabled` 为 `true`（跌落保护层已重新启用）

## 其他导航模式

系统还支持其他导航模式，可在需要时使用：

### MF_SAFE 模式（梅林安全模式）
```bash
ros2 service call /nav_safety/set_mode \
    rc26_interfaces/srv/SetNavMode \
    "{mode: 1, timeout_sec: 0.0, reason: 'merlin_safe_area'}"
```

### MF_EXIT 模式（梅林退出模式）
```bash
ros2 service call /nav_safety/set_mode \
    rc26_interfaces/srv/SetNavMode \
    "{mode: 3, timeout_sec: 5.0, reason: 'exiting_merlin_area'}"
```

## 故障排查

### 建图阶段问题
- **激光雷达无数据**: 检查网络连接、IP配置
- **里程计漂移大**: 检查IMU标定、传感器同步
- **地图质量差**: 调整Point-LIO参数、增加扫描时间

### 导航阶段问题
- **定位不收敛**: 检查初始位姿设置、点云地图是否正确
- **路径规划失败**: 检查目标点是否可达、代价地图是否正常
- **机器人不动**: 检查速度指令是否发布、底盘驱动是否正常

### 攀爬阶段问题
- **模式切换被拒绝**: 检查机器人是否静止、当前模式是否合法
- **代价地图重建慢**: 检查地形感知模块数据更新频率
- **路径规划仍避开阶梯**: 检查跌落保护层是否真正关闭、代价地图是否重建完成

---

## 总结

### 测试流程递进关系
1. **建图阶段**: 建立环境地图，验证传感器和里程计功能
2. **自主导航阶段**: 验证定位和路径规划，实现基本导航能力
3. **攀爬阶梯阶段**: 验证模式切换和特殊地形导航，实现复杂地形通过能力

### 关键依赖关系
- 建图 → 导航: 需要地图文件
- 导航 → 攀爬: 需要在导航系统正常运行基础上进行模式切换
- 模式切换: 需要机器人静止，且需要等待代价地图重建

### 注意事项
1. 每个阶段完成后要充分验证，确保功能正常再进行下一阶段
2. 模式切换时机器人必须静止
3. 攀爬测试需要谨慎，注意安全
4. 测试过程中持续监控系统状态和日志
