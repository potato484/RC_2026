# rc26_terrain 模块功能概述

## 1. 模块介绍
`rc26_terrain` 模块是机器人在复杂地形中安全导航的“双眼”和“安全屏障”。它的核心任务是从 3D 点云数据中提取出关键的语义信息，将原始数据转化为 Nav2 导航栈可以直接理解的“障碍物”或“风险区域”。这有效解决了传统 2D 代价地图（Costmap）无法准确表达台阶、悬崖负障碍等复杂地形特征的问题。此外，该模块还内置了严格的健康监测与失效保护机制（Fail-safe），一旦检测到传感器数据异常或系统链路断裂，会立即主动输出虚拟围栏，强制机器人停车，防止发生意外。

## 2. 接口与配置
为了实现上述功能，模块定义了清晰的输入输出接口及丰富的配置项：

*   **输入**：
    *   **点云数据**：订阅 `input_cloud_topic`（默认 `registered_scan`），接收经过里程计配准的 3D 点云。
    *   **里程计**：订阅 `odom_topic`（默认 `odom`），用于辅助健康监测，并在 TF 失效的极端情况下提供备用的位姿参考。
*   **输出**（均为 `sensor_msgs/PointCloud2`）：
    *   **真障碍层**：`output_obstacles_topic`（默认 `terrain_obstacles`），描述墙壁、柱子等不可跨越的实体障碍。
    *   **跌落风险层**：`output_drop_topic`（默认 `terrain_drop`），描述悬崖边缘、高台阶边缘等可能导致机器人跌落的区域。
    *   **可攀爬层**（调试用）：`output_climbable_topic`，可视化展示算法识别出的可通行台阶特征。
    *   **诊断信息**：通过 `diagnostics_topic` 上报模块的健康状态及降级运行的原因。
*   **关键配置**：
    *   **基础坐标系**：定义 `target_frame`（如 `odom`）和 `base_frame`（如 `base_link`），以及 TF 查询的超时容忍度。
    *   **栅格化参数**：`perception_radius_m`（感知半径）、`grid_resolution_m`（栅格分辨率），以及用于点云预处理的体素大小。
    *   **语义判定阈值**：定义什么高度算障碍 (`h_obstacle_m`)、什么落差算跌落风险 (`h_drop_m`)、以及可攀爬台阶的高度范围 (`h_climb_m`)。
    *   **策略与安全**：包括未知区域（Unknown）的处理策略、迟滞滤波参数、失效保护的触发条件及虚拟围栏的尺寸。

## 3. 核心算法逻辑
为了在计算实时性和环境适应性之间取得平衡，模块采用了一套基于局部概率栅格的分析方法：

1.  **局部栅格构建**：
    *   以机器人为中心维护一个滚动更新的局部栅格地图。为了控制计算量，原始点云首先经过体素下采样。
2.  **鲁棒的高度估计**：
    *   每个栅格单元独立估计其“地面高度”和“顶部高度”。算法使用分位数统计（Quantile）来抵抗离群噪点的影响，并对地面高度应用 EMA（指数移动平均）平滑，有效抑制因传感器噪声导致的地形高度闪烁。
3.  **语义分类**：
    *   **真障碍**：当且仅当栅格内的相对高度差或绝对高度超过设定的障碍物阈值时。
    *   **跌落风险**：检测相邻栅格间的地面高度突变，若落差超过安全阈值，则标记为跌落风险。
    *   **未知区域策略**：支持 `aggressive`（激进，忽略盲区）和 `conservative`（保守，将盲区视为潜在障碍）两种策略，以适应不同的竞赛节奏。

## 4. 稳定性与迟滞设计
为了防止语义识别结果在临界状态下反复跳变（闪烁），模块引入了多级迟滞机制：

1.  **积分迟滞**：
    *   每个栅格的状态判定基于积分分数（Score）。只有当特征持续存在并积累分数超过 `*_on_score` 阈值时才会被激活；反之，只有分数衰减低于 `*_off_score` 时才会清除。这确保了短暂的噪声不会触发错误的障碍物报警。
2.  **时间衰减**：
    *   通过 `stale_time_sec` 和 `decay_time_sec` 管理历史数据，确保过时的栅格信息能及时淡出，避免“幽灵障碍物”长期残留。

## 5. 健康监测与失效保护
考虑到竞赛环境的严苛性，模块将安全性放在首位：

1.  **全链路监控**：
    *   实时监控点云输入、里程计更新频率以及 TF 变换的有效性。一旦任何环节超时（超过设定的 timeout 阈值），立即触发异常处理流程。
2.  **主动防御 (Fail-safe)**：
    *   当进入失效保护模式时，模块会主动生成特定形态的点云来“接管”导航：
        *   **虚拟围栏**：在机器人周围生成一圈致密的虚拟障碍点，迫使 Nav2 规划器立刻停车。
        *   **急停屏障**：在更严重的故障下，输出全向阻挡点云，实施紧急制动。
3.  **输出限流**：
    *   为了防止异常数据导致系统资源耗尽，模块对输出点云进行了严格的 NaN/Inf 清洗，并限制了单帧点云的最大数量。

## 6. 系统集成说明
在使用本模块时，请注意以下上下游契约：

1.  **上游要求**：必须提供高质量的配准点云（推荐在 `odom` 坐标系下）以及稳定的 `odom -> base_link` TF 变换。
2.  **下游适配**：Nav2 的 Costmap 层应配置为订阅本模块输出的 `obstacles` 和 `drop` 话题。建议 Costmap 的 QoS 设置与本模块保持一致（通常为 BestEffort），以确保数据的实时性。
3.  **独立性**：即使系统中有其他里程计来源，本模块仍应独立维护其对感知数据的监控逻辑，作为系统安全的最后一道防线。
