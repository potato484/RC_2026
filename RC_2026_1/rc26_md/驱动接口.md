## 串口驱动接口 

> **极简、透明、自动化**。基于 `SerialDriver` 直调，支持双串口全集成与黑板全反馈映射。

---

## 🚀 核心架构

所有逻辑已合并至 `DecisionNode`。节点启动后自动激活“情报站”逻辑：收到下位机反馈 ID -> 自动更新行为树黑板状态。

- **串口 1 (Odom)**: 负责位姿上报 (`PoseSender`) 与里程计接收 (`WheelOdomReceiver`)。
- **串口 2 (Command)**: 负责指令发送、反馈自动映射与自动心跳。

## 🌲 行为树深度集成

### 1. 发送指令 (onStart)
通过黑板获取 `cmd_serial` 句柄，直接调用驱动接口。**最短示例**：

```cpp
auto serial = config().blackboard->get<std::shared_ptr<SerialDriver>>("cmd_serial");
serial->sendCommand(CommandID::NAV_NORMAL); // 发送导航指令
```

### 2. 读取反馈 (onRunning)
`DecisionNode` 自动将反馈 ID 转换为黑板布尔值。**最短示例**：

```cpp
// 检查特定动作是否完成
if (config().blackboard->get<bool>("grab_tip_done")) {
    return BT::NodeStatus::SUCCESS;
}
```

### 3. 检查重连状态 (onRunning)
当发送指令触发重连时，黑板 `cmd_serial_reconnecting` 自动更新。**最短示例**：

```cpp
// 检查串口是否正在重连
if (config().blackboard->get<bool>("cmd_serial_reconnecting")) {
    // 串口正在重连，等待或执行备用逻辑
    return BT::NodeStatus::RUNNING;
}
```

**重连状态说明**：
- `cmd_serial_reconnecting = true`：发送指令重试失败，正在重连串口
- `cmd_serial_reconnecting = false`：串口正常或重连成功

重连由 `SerialDriver` 内部自动处理，行为树只需查询状态即可。


### 4. 智能导航与模式切换 (SmartWaypointNavigator)

`rc26_decision` 实现了增强型导航框架，支持 **动态参数调整**、**安全模式切换** 和 **多层级控制**。

#### 核心机制
- **静态与动态航点**：支持从 YAML 加载固定点，也支持根据 Merling Anchors 动态生成拓扑点（`WaypointManager`）。
- **参数热切换**：导航开始前，根据目标点配置（`speed_profile`, `tolerance` 等）自动调整 Nav2 控制器参数（如最大速度、目标公差），并在结束后自动恢复。
- **安全模式集成**：与 `nav_safety/set_mode` 服务联动，自动切换安全状态（`MF_SAFE`, `MF_TRAVERSE`, `MF_EXIT`）。
- **双层指令下发**：
  - **MCU**：根据 `mcu.nav_mode` 发送 `NAV_STAIR_UP`/`NAV_STAIR_DOWN` 等特定指令。
  - **Nav2**：发送 `NavigateToPose` 动作目标。

#### 行为树节点 (NavToSmartPoint)
- **输入端口**：`target_name`（YAML 中定义的语义名称，如 `merlin_entry_1`）。
- **功能**：查找航点配置 -> 设置安全模式 -> 调整控制器参数 -> 发送 MCU 指令 -> 执行 Nav2 导航 -> 恢复默认状态。

**最短示例（BehaviorTree XML）**：

```xml
<NavToSmartPoint target_name="merlin_entry_1"/>
```

**YAML 配置示例 (waypoints.yaml)**：

```yaml
static_points:
  merlin_entry_1:
    pose: {x: 1.5, y: 2.0, yaw: 1.57}
    strategy_tag: "fast_approach"
    speed_profile: "FAST"    # 自动调大 v_linear_max
    nav_safety_mode: "MF_SAFE"
    mcu:
      nav_mode: "NORMAL"
      speed_mps: 1.2
    tolerance: {xy: 0.15, yaw: 0.1}
```

**实现细节**：
- `SmartWaypointNavigator` 维护状态机，按序执行：`SetMode` -> `ApplyParams` -> `SendGoal` -> `WaitResult` -> `Cleanup`。
- 支持 `defaults` 机制：首次运行时记录控制器默认参数，任务结束（成功/失败/取消）后强制恢复，防止参数污染。


### 5. 最小闭环示例：先导航，再抓取矛头（MC Area）

> 目标：第一步导航到 MC 区入口（`mc_area_entry`），第二步发送抓取矛头指令，并等待下位机反馈 `grab_tip_done`。

**最短示例（BehaviorTree XML）**：

```xml
<Sequence>
  <NavToSmartPoint target_name="mc_area_entry"/>
  <GrabTip/>
</Sequence>
```

**最短示例（C++，GrabTipAction 实现）**：

```cpp
#include "rc26_serial/serial_driver.hpp"
#include "rc26_serial/protocol.hpp"

BT::NodeStatus GrabTipAction::onStart()
{
    auto serial = config().blackboard->get<std::shared_ptr<SerialDriver>>("cmd_serial");
    serial->sendCommand(CommandID::GRAB_TIP);
    return BT::NodeStatus::RUNNING;
}

BT::NodeStatus GrabTipAction::onRunning()
{
    if (config().blackboard->get<bool>("grab_tip_done")) {
        return BT::NodeStatus::SUCCESS;
    }
    return BT::NodeStatus::RUNNING;
}
```

**联通说明**：
- `DecisionNode` 启动时会把 `cmd_serial` 与 `waypoint_manager` 写入黑板。
- `NavToSmartPoint` 负责根据语义名称查找点位并执行导航，`GrabTip` 负责调用串口驱动。
- 下位机反馈会被 `DecisionNode` 映射成黑板布尔量（例如 `grab_tip_done`），行为树节点只需查询黑板即可判定完成。

## 🧱 base_ground（台阶层级/地面参考系）接口

> 一句话理解：`rc26_base_ground` 会把机器人“现在在第几层台阶”算出来（离散的层级），并发布 `base_ground` 参考系；`rc26_decision` 把这些信息写进行为树黑板，供行为树节点用来判断“上/下台阶是否完成”。

---

## 📡 ROS 接口（rc26_base_ground 输出）

### 发布话题
- `base_ground/level`（`std_msgs/Int32`）：当前绝对层级（0, 1, 2...）
- `base_ground/stair_delta`（`std_msgs/Int8`）：层级变化脉冲（只有变化瞬间才发，比如 +1/-1）
- `base_ground/stable`（`std_msgs/Bool`）：当前是否“稳定”（平地/稳定段更容易为 true）

### TF
- `parent_frame -> base_ground`：`parent_frame` 一般是 `odom` 或 `map`（由 `rc26_base_ground` 启动参数决定）

---

## 🧩 决策层黑板映射（DecisionNode 已内置）

`DecisionNode` 会订阅上面 3 个话题，并把数据写入黑板：
- `current_level`（int32）<- `base_ground/level`
- `stair_delta`（int8）<- `base_ground/stair_delta`
- `base_ground_stable`（bool）<- `base_ground/stable`

对应参数（可改话题名，默认值如下）：
```yaml
rc26_decision:
  ros__parameters:
    base_ground_level_topic: "base_ground/level"
    base_ground_stair_delta_topic: "base_ground/stair_delta"
    base_ground_stable_topic: "base_ground/stable"
```

## 🌲 行为树怎么用（当前实现）

### 1) 行为树节点：`StairClimb` / `StairDescend`
它们的定位是“判定/等待台阶动作完成”，不负责控制底盘去爬楼：
- 第一次运行时记录 `level_start = current_level`
- 之后持续等待：
  - `StairClimb`：当 `current_level >= level_start + 3` 返回 `SUCCESS`，并置 `stair_climb_done = true`
  - `StairDescend`：当 `current_level <= level_start - 3` 返回 `SUCCESS`，并置 `stair_descend_done = true`

当前行为树里（梅林区）已经这样用：
```xml
<!-- RC_2026_1/rc26_decision/behavior_trees/mf_tree.xml -->
<Fallback name="entry_decision">
  <Sequence>
    <CheckKFS grid_id="2" expected_state="AUTO_KFS"/>
    <GrabKFS grid_id="2"/>
  </Sequence>
  <StairClimb name="climb_directly"/>
</Fallback>
...
<StairDescend name="leave_merlin"/>
```

### 2) 推荐用法：把它放在“开始上/下台阶动作”之后
因为 `StairClimb/StairDescend` 只看黑板，不会主动让机器人动，所以常见写法是：
```xml
<Sequence>
  <!-- 这里先放：导航/底盘指令（让机器人真的开始上/下台阶） -->
  <StairClimb/>
</Sequence>
```

```cpp
int32_t level = 0;

config().blackboard->get("current_level", level);

```

## ⚠️ 使用注意
- `stair_delta` 是“脉冲”，只在层级变化瞬间发布；持续状态请用 `current_level`。
- `base_ground` 刚启动会有一小段“标定/稳定窗口”，期间 `level` 可能还没可靠更新；行为树需要允许短暂 `RUNNING`。
- 话题名带不带前导 `/` 都能用，但建议在参数里统一写法，避免命名空间下订阅不到。

## 🔧 如何添加新的底盘控制模式

若需添加新模式（例如 `CRAB_WALK`），需修改以下 4 个文件：

### 1. 协议定义 (`protocol.hpp`)
在 `rc26_serial/include/rc26_serial/protocol.hpp` 中添加指令 ID：
```cpp
enum class CommandID : uint8_t {
    // ...
    NAV_STAIR_DOWN = 0x02,
    NAV_CRAB_WALK  = 0x11,  // <--- 新增
    // ...
};
```

### 2. 内部类型 (`smart_waypoint_types.hpp`)
在 `rc26_decision/include/rc26_decision/navigation/smart_waypoint_types.hpp` 添加枚举：
```cpp
enum class McuNavMode : uint8_t {
    Normal = 0,
    // ...
    CrabWalk = 3, // <--- 新增
};
```

### 3. YAML 解析 (`waypoint_manager.cpp`)
在 `rc26_decision/src/navigation/waypoint_manager.cpp` 的 `parseMcuNavMode` 函数中添加字符串匹配：
```cpp
if (s == "CRAB_WALK" || s == "CrabWalk") {
    return McuNavMode::CrabWalk;
}
```

### 4. 指令转换 (`smart_waypoint_navigator.cpp`)
在 `rc26_decision/src/navigation/smart_waypoint_navigator.cpp` 的 `mcuModeToCommandId` 函数中添加映射：
```cpp
case McuNavMode::CrabWalk:
    return CommandID::NAV_CRAB_WALK;
```

### ✅ 使用方式 (waypoints.yaml)
```yaml
special_point:
  pose: {x: 1.0, y: 0.0, yaw: 0.0}
  mcu:
    nav_mode: "CRAB_WALK"
    speed_mps: 0.5
```
