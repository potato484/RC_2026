# 视觉推理库架构方案 (Vision Inference Library Architecture)

> **目标**：构建一个基于 D455 图像输入与 YOLO 识别的通用视觉推理库。参考现有串口驱动（`SerialDriver`）的集成模式，通过“**DecisionNode 创建实例 → 写入行为树黑板 → BT 节点直接调用**”的方式，实现对视觉推理功能的低耦合、高内聚封装。行为树只需调用简单的控制节点即可完成**启动识别**、**获取结果**及**停止识别**。

---

## 0. 范围、前置条件与可行性评估

### 0.1 范围与输出

- **最小闭环输出**：是否检测到目标（`vision_has_target`）、目标属性（`vision_attr_kind`）、距离（`vision_distance_m`）、时间戳（可选）。
- **可选增强输出**：目标框中心像素/置信度/三维坐标（用于对准与抓取时的偏差计算），以及延迟与健康状态（`vision_ok`、`vision_last_error`）。

### 0.2 前置条件（硬件/ROS/模型）

- **D455 数据流**：需由相机驱动发布彩色、对齐深度与 `camera_info`；若没有“对齐深度”，则无法直接在同一像素上取深度（需要额外坐标系/投影转换，复杂度显著上升）。
- **执行模型约束**：当前 `rc26_decision` 使用单线程 `rclcpp::spin()` + 定时器 tick 行为树，任何 OpenCV/推理等耗时任务都必须放在独立线程，订阅回调应只做“缓存最新帧”。
- **模型与类别一致性**：YOLO ONNX 的 `class_id` 与 `class_names` 顺序必须和训练时一致；“目标属性枚举”与 `class_id` 的映射需要在配置中明确。

### 0.3 可行性结论

- 本文档提出的“Manager 常驻 + 黑板映射 + BT 轻量节点”方案，与现有 `SerialDriver` 的接入模式一致，可直接复用集成方法与工程习惯。
- 主要落地难点集中在：**彩色/深度同步与对齐**、**深度鲁棒性（无效值/噪声）**、**推理性能与线程退出可靠性**。

### 0.4 主要风险与对策（建议在实现时强制落地）

- **彩色/深度不同步**：优先使用 `message_filters`（近似同步）；或采用“时间戳最近匹配 + 容忍窗”的策略。
- **深度噪声/无效值**：ROI 中位数 + 有效点阈值 + 深度范围裁剪；必要时引入连续 N 帧确认与时间滤波。
- **性能不足**：限制最大推理 FPS、输入分辨率；优先把系统跑通，再逐步开启 ORT 优化/GPU 加速。
- **线程退出卡死**：`stop()` 与析构需可重入、可中断并 `join()` 推理线程，避免节点关闭时阻塞。

## 1. 设计理念：复用“极简接口 + 黑板映射”模式

本项目现有的串口驱动集成方式证明了其高效性，视觉库将沿用此架构：

1.  **生命周期管理**：
    - 在 `DecisionNode` 启动时创建 `VisionInferenceManager` 实例。
    - 将实例指针写入行为树黑板：`blackboard->set("vision_manager", vision_manager_);`

2.  **数据反馈机制**：
    - `VisionInferenceManager` 内部维护推理状态和结果。
    - 通过回调函数或直接写入黑板的方式，将关键结果（如“目标属性”、“距离”、“是否识别到”）实时更新到黑板，供 BT 条件节点查询。

3.  **行为树调用**：
    - BT 节点保持“轻量化”，仅在 `onStart/onRunning` 中从黑板获取管理器实例并调用其 API。
    - 示例：`auto vision = config().blackboard->get<std::shared_ptr<VisionInferenceManager>>("vision_manager"); vision->start();`

## 2. 核心架构：分层设计与数据流

### 2.1 模块分层

为确保可扩展性与可维护性，建议采用双层架构：

1.  **推理引擎层 (`YoloEngine`)**
    - **职责**：纯粹的图像处理与模型推理，不依赖 ROS。
    - **功能**：加载模型（ONNX）、预处理（Resize/Normalize）、推理执行、NMS（非极大值抑制）及后处理。
    - **接口**：输入图像数据，输出检测结果列表（Bounding Box, Class ID, Score）。

2.  **管理适配层 (`VisionInferenceManager`)**
    - **职责**：作为 ROS 节点与推理引擎的粘合剂，管理资源与状态。
    - **功能**：
        - 订阅 D455 图像与深度流（处理丢帧与同步）。
        - 维护推理线程，调用 `YoloEngine`。
        - 结合深度图计算目标距离。
        - 将结果映射到行为树黑板。
    - **接口**：提供 `start()`, `stop()`, `getLatestResult()` 等线程安全接口。

### 2.2 数据流与处理逻辑

1.  **输入源**：
    - 彩色图像：默认 `vision_color_topic=/camera/color/image_raw`（建议参数化，避免硬编码）
    - 对齐深度：默认 `vision_depth_topic=/camera/aligned_depth_to_color/image_raw`
    - 相机内参：默认 `vision_info_topic=/camera/color/camera_info`（用于可选的三维坐标计算）
    - QoS：图像类话题建议 `rclcpp::SensorDataQoS()`

2.  **处理流程**：
    - **订阅回调**：仅做数据缓存，采用“最新帧优先”策略（丢弃旧帧），避免阻塞 ROS Executor。
    - **推理线程**：
        - 检查 `running` 状态。
        - 获取最新图像帧 -> `YoloEngine::infer`。
        - 获取对应的对齐深度图，计算目标区域的深度（推荐使用中位数滤波）。
        - 更新内部缓存结果（属性 + 距离 + 时间戳）。
        - 触发回调，刷新黑板数据。

3.  **距离计算策略**：
    - 利用对齐深度图，提取检测框中心区域（如 7x7 像素）。
    - 剔除无效值（0 或 NaN），计算**中位数**作为目标距离。
    - 注意深度图常见编码：`16UC1`（单位 mm）或 `32FC1`（单位 m），实现时需按 `encoding` 统一换算为米。
    - 若有效深度点过少，标记该帧结果无效 (`vision_has_target = false`)。

### 2.3 线程模型与时间同步（关键落地点）

- **线程划分**：
    - 订阅回调：只缓存最新的彩色/深度/内参消息指针（丢弃旧帧），避免阻塞 ROS Executor。
    - 推理线程：等待新帧 -> 预处理/推理 -> 距离/属性后处理 -> 更新结果 -> 触发回调写黑板。
- **同步策略**（由简到强，建议实现时至少做到 1 或 2）：
    1. **首选**：`message_filters` 近似同步彩色与对齐深度（必要时再加入 `camera_info`）。
    2. **备选**：分别缓存最新彩色与深度，推理时按时间戳选择“最近深度帧”，并设置容忍阈值（例如 30ms）。
    3. **兜底**：若深度不可用，则只输出分类/框（不输出距离），并显式置 `vision_has_target=false` 或记录 `vision_last_error` 供上层处理。

### 2.4 启停机制

推荐采用**常驻订阅 + 逻辑开关**模式（类似串口 Open/Close 体验）：

- **Start**：置位 `running` 标志，推理线程开始处理缓存的图像帧。
- **Stop**：复位 `running` 标志，推理线程挂起或空转，停止消耗计算资源。
- **优势**：响应极快，避免频繁创建/销毁 ROS 订阅带来的开销和潜在不稳定性。

### 2.5 多目标选择与结果稳定（建议实现，避免 BT 抖动）

- **多目标选择**：通常业务只需要一个“当前目标”，建议提供策略（按置信度最高/距离最近/指定属性优先）。
- **抗抖动**：可选“连续 N 帧命中才置真”和距离时间滤波（EMA/中位数滑窗），避免 `vision_has_target` 在边界条件下频繁翻转。
- **属性判定回退**：若模型只能输出 class_id，但业务需要 AttributeKind，需定义清晰的映射与 Unknown 回退规则。

## 3. 接口设计

### 3.1 C++ 核心接口 (`VisionInferenceManager`)

```cpp
namespace rc26_vision {

// 目标属性枚举（根据业务需求定义）
enum class AttributeKind {
    Unknown = 0,
    R_R1,      // 红色 R1
    B_R1,      // 蓝色 R1
    Truth,     // 真目标
    False,     // 假目标
};

// 推理结果结构体
struct TargetResult {
    rclcpp::Time stamp;
    AttributeKind attribute = AttributeKind::Unknown;
    double distance_m = 0.0; // 目标距离（米）
    bool valid = false;      // 结果是否有效
};

class VisionInferenceManager {
public:
    using ResultCallback = std::function<void(const TargetResult&)>;

    explicit VisionInferenceManager(rclcpp::Node& node);
    ~VisionInferenceManager();

    // 初始化配置
    bool configure(const std::string& model_path, const std::vector<std::string>& class_names, float conf_thresh);

    // 运行控制
    bool start();
    void stop();
    bool isRunning() const;

    // 数据获取
    TargetResult getLatestResult() const;
    void setResultCallback(ResultCallback cb);

private:
    // ...
};

} // namespace rc26_vision
```

> 实现建议：`start()`/`stop()` 设计为幂等；推理线程使用 `condition_variable` 等待新帧（队列长度=1），析构时必须可靠退出并 `join()`；`TargetResult` 可按需扩展 `score/bbox_center/pos_xyz/latency_ms` 等字段，便于对准与调试。

### 3.2 黑板数据映射

`DecisionNode` 负责将 `VisionInferenceManager` 的状态实时映射到黑板，供 BT 使用：

| 黑板键名 (Key) | 类型 | 说明 |
| :--- | :--- | :--- |
| `vision_manager` | `shared_ptr` | 管理器实例句柄，供 Action 节点调用 |
| `vision_running` | `bool` | 当前推理是否开启 |
| `vision_ok` | `bool` | 系统健康状态（模型加载正常且线程运行中） |
| `vision_has_target` | `bool` | 最近一帧是否检测到有效目标 |
| `vision_attr_kind` | `int` | 目标属性 (枚举值转 int) |
| `vision_distance_m` | `double` | 目标距离 (米) |
| `vision_score` | `double` | 目标置信度（可选） |
| `vision_bbox_cx` | `int` | 目标框中心像素 x（可选） |
| `vision_bbox_cy` | `int` | 目标框中心像素 y（可选） |
| `vision_pos_x_m` | `double` | 目标三维坐标 x（相机坐标系，可选） |
| `vision_pos_y_m` | `double` | 目标三维坐标 y（相机坐标系，可选） |
| `vision_pos_z_m` | `double` | 目标三维坐标 z（相机坐标系，可选，通常等于距离） |
| `vision_last_error` | `string` | 最近一次错误信息（可选，用于诊断） |

### 3.3 参数与配置建议（建议以 ROS2 参数落地）

为了避免“代码里写死话题/阈值/映射”，建议全部以参数提供，并允许在 `rc26_bringup` 的 yaml 中统一配置。

| 参数名 | 类型 | 示例 | 说明 |
| :--- | :--- | :--- | :--- |
| `enable_vision` | `bool` | `true` | 是否启用视觉模块 |
| `vision_config_file` | `string` | `<share>/config/vision_models.yaml` | 模型 Profile 配置 YAML（`vision.default_model / vision.models.*`） |
| `vision_color_topic` | `string` | `/camera/color/image_raw` | 彩色图像话题 |
| `vision_depth_topic` | `string` | `/camera/aligned_depth_to_color/image_raw` | 对齐深度话题 |
| `vision_info_topic` | `string` | `/camera/color/camera_info` | 相机内参话题 |
| `vision_max_fps` | `int` | `15` | 推理最大帧率（限流） |
| `vision_depth_roi` | `int` | `7` | 深度采样 ROI 边长（奇数） |
| `vision_depth_min_valid_count` | `int` | `10` | ROI 内最少有效深度点数 |
| `vision_depth_min_m` | `double` | `0.2` | 深度有效范围下限 |
| `vision_depth_max_m` | `double` | `5.0` | 深度有效范围上限 |

## 4. 行为树集成方案

### 4.1 新增 BT 节点

在 `rc26_decision` 中实现以下节点，实现对视觉功能的完全控制：

1.  **VisionStart (Action)**
    - 功能：调用 `manager->start()`。
    - 返回：成功启动（或已在运行）返回 `SUCCESS`；若未获取到 `vision_manager` 可返回 `FAILURE` 并置 `vision_ok=false`。

2.  **VisionStop (Action)**
    - 功能：调用 `manager->stop()`。
    - 返回：停止（或已停止）返回 `SUCCESS`；同样建议对 “manager 缺失” 做显式失败。

3.  **WaitVisionTarget (Condition / Action)**
    - 功能：等待特定条件的目标出现。
    - 输入端口：
        - `target_attr`：期望的目标属性（可选）。
        - `max_dist`：最大有效距离（可选）。
        - `timeout`：超时时间。
    - 逻辑：读取黑板中的 `vision_has_target`、`vision_attr_kind` 和 `vision_distance_m` 进行判断；未满足条件时返回 `RUNNING`，超时返回 `FAILURE`，满足条件返回 `SUCCESS`。
    - 约定：`target_attr` 建议同时支持枚举名（如 `Truth`）与整数（如 `3`），避免 BT XML 里写 magic number。

### 4.2 BT XML 编排示例

**场景：寻找特定目标并执行动作**

```xml
<Sequence>
    <!-- 1. 开启视觉识别 -->
    <VisionStart/>
    
    <!-- 2. 等待真目标出现，且距离小于 2.0 米，超时 2 秒 -->
    <WaitVisionTarget target_attr="Truth" max_dist="2.0" timeout="2000"/>
    
    <!-- 3. 执行后续业务逻辑（如对准、抓取） -->
    <SubTree ID="AlignAndGrab"/>
    
    <!-- 4. 任务完成，关闭视觉 -->
    <VisionStop/>
</Sequence>
```

## 5. 落地实施建议

### 5.1 开发路径
1.  **创建 `rc26_vision` 包**：
    - 实现 `YoloEngine` (建议优先使用 ONNX Runtime)。
    - 实现 `VisionInferenceManager`。
2.  **集成到 `rc26_decision`**：
    - 在 `DecisionNode` 中实例化 Manager。
    - 注册 BT 节点 (`VisionStart`, `VisionStop`, `WaitVisionTarget`)。
3.  **调试与验证**：
    - 使用 `rqt` 或 `rviz` 配合可选的 Debug Topic (`vision/debug_image`) 验证检测框与距离准确性。
    - 编写简单的 BT XML 验证启停逻辑与黑板数据流。

### 5.2 性能优化
- **丢帧策略**：确保推理线程总是处理最新的图像，队列长度设为 1。
- **按需发布**：Debug 图像仅在调试模式下发布，生产环境默认关闭以节省带宽。
- **线程安全**：确保黑板读写操作的原子性或使用适当的锁机制。

### 5.3 推荐目录结构与依赖（便于工程落地）

建议将 `rc26_vision` 作为“可被 `rc26_decision` 直接链接的库包”，典型结构如下：

```text
rc26_vision/
  include/rc26_vision/
    vision_inference_manager.hpp
    yolo_engine.hpp
  src/
    vision_inference_manager.cpp
    yolo_engine.cpp
  models/                # 或安装到 share/rc26_vision/models
  config/                # 参数/映射示例
```

依赖建议（按需引入）：`rclcpp`、`sensor_msgs`、`image_transport`、`cv_bridge`、`OpenCV`、`onnxruntime`（或后续替换为 GPU/TensorRT 方案）。

### 5.4 验收标准（建议用于拉通联调）

- `VisionStart/VisionStop` 可重复调用且无资源泄漏；退出节点时不阻塞。
- 在 10–15Hz 级别稳定输出黑板数据，BT tick 不被阻塞（CPU 峰值可控）。
- `vision_has_target` 抖动可接受（有稳定策略）；距离在有效范围内稳定且遇到无效深度能正确降级。
