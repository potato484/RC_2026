# 导航点说明（Waypoints）

本文用通俗语言解释：**导航点是什么、从哪里配置、系统如何“用上”这些点、数据链路怎么走、你该改哪些配置**。

---

## 1. 什么是“导航点”？

在本项目里，“导航点”就是一组**预先标定好的地图坐标（map 坐标系下的 x/y/yaw）**，用一个名字做索引（例如 `start_pose`、`climb_start` 等）。

它的作用是：当决策需要机器人去某个位置时，只需要给出“点名”，系统会从配置里查出这个点的坐标，并发给 Nav2 去导航。

> 注意：这里的“导航点”**不是**持续发布到某个 ROS 话题让大家订阅的那种“广播点位”。  
> 本仓库的做法是：**从 YAML 加载到内存，按需取用**；需要导航时才发 Nav2 goal。

---

## 2. 导航点配置在哪里？怎么区分红蓝方？

导航点 YAML 在：
- `RC_2026_1/rc26_decision/config/waypoints/waypoints_blue.yaml`
- `RC_2026_1/rc26_decision/config/waypoints/waypoints_red.yaml`

文件里最常见的是 `static_points`：

- `x / y / theta(yaw)`：这个点在 `map` 坐标系下的位置与朝向
- `nav_profile`：导航“模式/档位”（例如 normal、safe、stair_up…），用于选择 `nav_profiles.yaml` 里的同名 profile
- `speed_profile`：速度档位（SLOW/CREEP/FAST），会映射成控制器参数缩放
- `tolerance`：到点容差（xy/yaw）
- `timeout_sec`：业务层超时（用于取消/失败处理）

> 另外文件里还有 `merlin_config`：用于“梅林区格子拓扑点”的生成（锚点 + 参数），不是每个项目都会用到。

---

## 3. 系统是怎么“使用”导航点的？（核心流程）

### 3.1 启动阶段：加载 YAML

启动 `rc26_decision` 时：
1) 创建 `WaypointManager`  
2) 读取 YAML（默认按 `team` 选择 red/blue 的文件；也可以手动指定 `waypoints_file`）  
3) 把 `WaypointManager` 放进行为树黑板（blackboard），供行为树节点使用

对应代码入口：`RC_2026_1/rc26_decision/src/decision_node.cpp`

### 3.2 运行阶段：按“点名”取点 → 发 Nav2 goal

当行为树里某个节点需要导航时（例如 `NavToSmartPoint`）：
1) 读取输入参数 `target_name`（点名）
2) `WaypointManager::find(target_name)` 查到点位（坐标/容差/档位等）
3) 交给 `SmartWaypointNavigator` 执行导航（内部是一个状态机）

对应代码：`RC_2026_1/rc26_decision/src/navigation/bt_nav_to_smart_point.cpp`

> 现状提醒：当前行为树 XML（`RC_2026_1/rc26_decision/behavior_trees/*.xml`）里还没把 `NavToSmartPoint` 接到主流程里（例如 combat_tree 里还有 TODO）。
> 也就是说：模块已经实现了“点位→导航”的能力，但要在行为树里调用它才会真正跑起来。

## 3.3 示例：从 YAML 点位到一次导航

下面这个示例包含 2 部分：**定义一个点** + **在行为树里按点名导航**。

**(1) 在点位 YAML 里增加一个点**（蓝方示例）：

```yaml
# RC_2026_1/rc26_decision/config/waypoints/waypoints_blue.yaml
static_points:
  combat_entry:
    x: 1.2
    y: -0.8
    theta: 1.57
    nav_profile: "normal"        # 传给 set_nav_mode 的 profile 名
    speed_profile: "FAST"        # FAST/SLOW/CREEP，用于缩放控制器限速
    tolerance: {xy: 0.10, yaw: 0.15}
    timeout_sec: 10.0
```

**(2) 在行为树 XML 里调用导航节点**（端口名是 `target_name`）：

```xml
<NavToSmartPoint target_name="combat_entry"/>
```

> 执行时，系统会：按点名查表 → 调用 `set_nav_mode(profile)` →（可选）调整 controller 参数 → 向 Nav2 action `navigate_to_pose` 发送 goal。

## 4. 数据链路是什么？（从点位到车轮）

把链路拆开看最清楚：

### 4.1 点位（YAML）→ 决策（rc26_decision）

- YAML 点位被 `WaypointManager` 读进内存  
- 行为树/决策逻辑用“点名”取出点位 spec

### 4.2 决策 → 安全模式管理器（rc26_nav_mode_manager）

`SmartWaypointNavigator` 在发 Nav2 goal 之前，会先请求切换 profile：
- service：`set_nav_mode`
- topic：`nav_safety_state`（用于途中监控 stop_required / timed_out）

profile 的配置在：
- `RC_2026_1/rc26_nav_mode_manager/config/nav_profiles.yaml`

一个最小可用的 `nav_profiles.yaml` 示例（只保留常用字段）：

```yaml
# RC_2026_1/rc26_nav_mode_manager/config/nav_profiles.yaml
profiles:
  normal:
    fallback_profile: safe
    watchdog:
      timeout_sec: 0
      stop_required_on_timeout: false
    precheck:
      require_stopped: false
    costmap:
      clear_on_switch: false
    controller:
      v_linear_max: 0.8
      v_angular_max: 1.0

  stair_up:
    fallback_profile: safe
    watchdog:
      timeout_sec: 30.0
      stop_required_on_timeout: true
    precheck:
      require_stopped: true
    costmap:
      clear_on_switch: true
    controller:
      v_linear_max: 0.3
      v_angular_max: 0.3
```

> 导航点里的 `nav_profile: "stair_up"` 就会触发切到这个 profile；profile 内部会决定“是否要求停稳、是否清图、控制器限速、以及 watchdog 超时回退策略”。

### 4.2.1 点位 YAML 与 nav_profiles.yaml 哪些字段“对应”？

这里的“对应”不是指字段名一一相同，而是指**会作用到同一套行为/参数**。

**(1) 唯一直接对应（按名字选中 profile）**
- 点位：`nav_profile: "<name>"`
- Profile：`profiles.<name>: ...`

也就是说，点位里的 `nav_profile` 必须是 `nav_profiles.yaml` 中 `profiles` 的某个键名（如 `normal/safe/stair_up/...`）。

**(2) 同作用域叠加（Profile 先应用，点位再做单点覆盖）**

1) **超时（watchdog）**
- Profile 基线：`profiles.<name>.watchdog.timeout_sec`
- 点位覆盖：`timeout_sec`

点位的 `timeout_sec` 会作为 `set_nav_mode(profile)` 的 `timeout` 入参传入，从而覆盖 profile 的 watchdog 超时；同时也会作为本次导航的业务超时使用。

2) **控制器限速**
- Profile 基线：`profiles.<name>.controller.v_linear_max / v_angular_max`（由 nav_mode_manager 设置到 controller_server 参数）
- 点位覆盖：
  - `speed_profile`：FAST/SLOW/CREEP → 按比例缩放控制器限速（比例由全局参数 `speed_profile_scales.*` 配置）
  - `payload.v_linear_max / payload.v_angular_max`：直接指定控制器限速最终值（优先级最高）

3) **到点容差**
- 点位：`tolerance.xy / tolerance.yaw` → 映射到 `general_goal_checker.xy_goal_tolerance / yaw_goal_tolerance`

**(3) 只有 Profile 有、点位没有的字段**
点位不会直接配置这些字段，但会通过 `nav_profile` 选中并触发它们生效：
- `fallback_profile`
- `precheck.require_stopped`（切换 profile 前是否要求停稳）
- `costmap.clear_on_switch`（切换时是否清图）
- `watchdog.stop_required_on_timeout`（超时是否要求上层停机）

### 4.3 决策 → Nav2

`SmartWaypointNavigator` 通过 Nav2 action client 发目标：
- action 名称默认是：`navigate_to_pose`
- action 类型：`nav2_msgs/action/NavigateToPose`

Nav2 负责规划、避障、控制输出速度 `/cmd_vel`（由 `controller_server` 产生）。

Nav2 参数文件：
- `RC_2026_1/rc26_bringup/config/nav2_params.yaml`

### 4.4 `/cmd_vel` → 串口 → MCU（速度闭环）

本仓库的“把速度下发给 MCU”的典型做法是 `PoseSender`：
- 订阅：`cmd_vel_topic`（默认 `cmd_vel`）
- 把 Twist 的 `(vx, vy, wz)` 打包成串口协议 `POSE_TARGET(0x22)` 发给 MCU

相关代码：
- `RC_2026_1/rc26_merge_odom/src/pose/pose_sender.cpp`

串口协议说明：
- `RC_2026_1/rc26_serial/include/rc26_serial/protocol.hpp`（`POSE_TARGET = 0x22`）

> 遥控/导航抢话题问题：遥控默认发布到 `/cmd_vel_teleop`，避免和 Nav2 的 `/cmd_vel` 打架；需要遥控时应通过参数把 PoseSender 的 `cmd_vel_topic` 切到 `cmd_vel_teleop`。
> 覆盖参数示例：`RC_2026_1/rc26_merge_odom/config/pose_sender_cmd_vel_teleop.yaml`

## 5. 我应该怎么配置？常用改法

### 5.1 改点位

直接编辑：
- `RC_2026_1/rc26_decision/config/waypoints/waypoints_blue.yaml`
- `RC_2026_1/rc26_decision/config/waypoints/waypoints_red.yaml`

重点检查：
- `frame_id` 是否是 `map`
- `x/y/theta` 是否基于 `map -> base_link` 录制

### 5.2 选择红蓝方

`rc26_decision` 有参数 `team`（默认 blue）。当 `waypoints_file` 为空时，会自动加载：
`.../config/waypoints/waypoints_<team>.yaml`

### 5.3 强制指定点位文件

把 `rc26_decision` 的 `waypoints_file` 指到你想用的 YAML 路径即可（适合临时实验/外部目录）。

### 5.4 配置 profile（速度/安全/清图等）

改 `rc26_nav_mode_manager` 的：
- `RC_2026_1/rc26_nav_mode_manager/config/nav_profiles.yaml`

然后在导航点里用：
- `nav_profile: "normal"` / `"safe"` / `"stair_up"` / `"mf_traverse"` 等

## 6. 怎么录点？（推荐工作流）

仓库提供了简单录点脚本：
- `RC_2026_1/rc26_decision/scripts/point_recorder.py`

它会通过 TF 读取 `map -> base_link`，把当前位姿写进 YAML（默认写到用户目录 `~/RC_2026/.rc26/waypoints/`）。

典型步骤（思路）：
1) 确保定位正常（TF 里确实存在 `map -> base_link`）
2) 开脚本进入交互
3) `record <name>` 记录点，`save` 保存
4) 在系统里生效：要么把 `waypoints_file` 指到输出文件，要么把内容合并回包内的 waypoints_red/blue.yaml

## 7. 常见问题（排查清单）

1) **导航不动**：行为树里没有调用导航节点（当前 XML 里确实还没接 `NavToSmartPoint`）。
2) **到点误差大**：点位不是基于 `map` 录的，或 TF/定位漂了。
3) **切 profile 失败**：`set_nav_mode` 服务没起来或命名空间没对上。
4) **速度“打架”**：同时有人发 `/cmd_vel`（比如误把遥控发到 `/cmd_vel`），PoseSender 会把混合速度下发到 MCU。
5) **机器人到点停不住**：调 `tolerance`、`FollowPath.v_*_max` 或 profile 里的限速；确认控制器参数生效。
