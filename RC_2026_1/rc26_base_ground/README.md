# rc26_base_ground - 底盘地面高度估计模块

## 模块简介

`rc26_base_ground` 是机器人的"地面高度感知专家"，专门负责持续监测机器人底盘相对于地面的高度变化，识别机器人是否在不同楼层之间移动，是否在上下台阶。想象一下，人类走路时能够感觉到脚下的高度变化，知道自己在平地、上台阶还是下台阶。这个模块就是机器人的"高度感觉器官"，为决策系统提供关键的地面高度信息。

## 核心功能

### 地面高度跟踪

模块会持续跟踪机器人底盘相对于初始位置的高度变化。就像你在爬楼梯时，能够感觉到自己相对于一楼地面的高度在增加。模块会记录这个高度值，并告诉其他模块"现在机器人在第几层"。

### 楼层识别

模块会将连续的高度空间量化为离散的楼层。比如，如果台阶高度是20厘米，那么0厘米就是0层，20厘米就是1层，40厘米就是2层，以此类推。这就像把连续的高度分成一个个"台阶"，让系统能够清晰地知道"现在在第几层"。

### 台阶变化检测

当机器人从一个楼层移动到另一个楼层时，模块会检测到这个变化，并计算变化的层数。比如，如果从0层上到2层，模块会报告"台阶变化为+2"。如果从2层下到0层，模块会报告"台阶变化为-2"。这个信息对于决策系统非常重要，因为它需要知道机器人是否在上下台阶。

### 稳定性判断

模块会判断机器人当前是否处于稳定状态。如果机器人的高度变化很小，姿态（倾斜角度）也很稳定，模块会认为机器人处于稳定状态。如果机器人在移动或者晃动，模块会认为处于不稳定状态。这个信息对于判断"是否成功到达某个楼层"非常重要。

## 工作原理

### 里程计数据接收

模块订阅里程计话题，持续接收机器人当前的位置和姿态信息。里程计数据就像是机器人的"位置报告"，告诉模块"现在机器人在哪里，朝向哪个方向"。

### 高度提取

模块从里程计数据中提取机器人底盘在垂直方向（Z轴）的高度值。这个高度值表示机器人底盘相对于某个参考坐标系的高度。就像测量你相对于地面的身高一样。

### 稳定性窗口分析

模块维护一个时间窗口，记录最近一段时间内的所有高度和姿态数据。就像用一个小本子记录最近几秒钟内的所有高度测量值。模块会分析这个窗口内的数据，判断机器人是否稳定：
- **高度方差**：计算窗口内所有高度值的方差。如果方差很小，说明高度变化不大，可能是稳定的
- **高度变化率**：计算高度变化的速度。如果变化很慢，说明机器人可能停在某个位置
- **姿态变化率**：计算机器人的横滚（roll）和俯仰（pitch）角度的变化速度。如果这些角度变化很小，说明机器人姿态稳定

如果所有这些指标都满足稳定条件，模块就认为机器人处于稳定状态。

### 初始高度标定

当机器人第一次稳定时，模块会记录这个高度作为"初始高度"（h0）。就像把一楼的地面高度设为0米，其他楼层相对于一楼来计算。这个初始高度会作为后续所有高度计算的参考点。

### 楼层量化

模块将当前高度减去初始高度，得到相对于初始位置的高度差。然后，根据台阶高度参数，将这个高度差量化成楼层数。比如，如果台阶高度是20厘米，当前高度比初始高度高40厘米，那么当前楼层就是2层。

### 楼层变化检测

模块会持续监测当前楼层是否发生变化。如果检测到楼层值持续一段时间（确认时间）都保持在新的值，就认为楼层真的发生了变化，并发布台阶变化信息。这就像确认你真的上了一个台阶，而不是因为传感器抖动导致的误判。

### TF变换发布

模块会发布一个"地面坐标系"（base_ground）的TF变换。这个坐标系的Z坐标等于量化后的地面高度，X和Y坐标与底盘坐标系相同。这样，其他模块就可以通过查询TF树来获取当前的地面高度信息。

    │               │

    │               │
    │               ├─→ 当前楼层计算
    │               │       │

    │               │   发布楼层信息

    │               │       ▼

## 输入输出

### 输入数据

模块需要订阅以下话题：
- **里程计数据**：来自里程计系统，包含机器人当前位置和姿态信息，在里程计坐标系或地图坐标系下

### 输出数据

模块会发布以下话题：
- **楼层信息**：当前楼层数，用整数表示（比如0、1、2等），相对于初始高度计算
- **台阶变化**：楼层变化的数量，用整数表示（比如+1表示上了一个台阶，-1表示下了一个台阶）
- **稳定性状态**：机器人是否处于稳定状态的布尔值，true表示稳定，false表示不稳定

### TF变换

模块会发布以下TF变换：
- **parent_frame → base_ground**：从父坐标系（通常是odom或map）到地面坐标系的变换。地面坐标系的Z坐标等于量化后的地面高度，X和Y与底盘坐标系相同

## 关键参数说明

### 台阶参数

- **台阶高度**：单个台阶的高度（单位：米），比如0.20米表示20厘米。模块使用这个值来量化楼层
- **容差**：高度量化的容差范围（单位：米），比如0.06米。如果当前高度距离某个量化楼层在这个容差范围内，就认为在这个楼层

### 稳定性参数

- **稳定时间窗口**：判断稳定性需要的时间窗口长度（单位：秒），比如0.5秒。模块会分析这个窗口内的数据来判断是否稳定
- **确认时间**：楼层变化确认需要的时间（单位：秒），比如0.3秒。如果楼层值持续这个时间都保持不变，才认为楼层真的变化了
- **高度容差**：稳定判断中高度方差的阈值（单位：米），比如0.06米。如果高度方差小于这个值，认为高度稳定
- **角度变化率限制**：稳定判断中角度变化速度的阈值（单位：弧度每秒），比如0.6。如果横滚和俯仰角度变化速度小于这个值，认为姿态稳定

### 坐标系配置

- **父坐标系**：输入里程计数据的坐标系名称（通常是 `odom` 或 `map`）
- **地面坐标系名称**：输出的地面坐标系名称（通常是 `base_ground`）

### 其他参数

- **TF查询超时**：查询坐标变换的最大等待时间（单位：秒）
- **启用TF发布**：是否发布地面坐标系的TF变换

## 使用场景

### 楼层导航

在有多层楼或台阶的环境中，决策系统需要知道机器人当前在第几层，才能制定正确的导航策略。模块提供准确的楼层信息，帮助决策系统判断"现在需要上台阶还是下台阶"。

### 台阶动作触发

当检测到楼层变化时，决策系统可以触发相应的动作。比如，如果检测到台阶变化为+1，可以触发"上台阶"动作；如果检测到台阶变化为-1，可以触发"下台阶"动作。

### 稳定性检查

在执行某些动作（比如抓取、放置）之前，需要确保机器人处于稳定状态。模块提供的稳定性信息可以帮助决策系统判断"现在可以执行动作"还是"需要等待机器人稳定"。

### 高度感知导航

其他模块可以通过查询TF树获取地面坐标系的位置，从而知道当前的地面高度。这对于需要高度感知的导航算法非常有用。

## 与决策系统的集成

这个模块是决策系统的重要信息源：
- **输入**：接收来自里程计系统的位置和姿态数据
- **处理**：分析高度变化，判断稳定性和楼层
- **输出**：向决策系统提供楼层、台阶变化和稳定性信息

决策系统依赖这个模块的信息来：
- 判断当前楼层，制定相应的任务策略
- 检测台阶变化，触发上台阶或下台阶动作
- 检查稳定性，决定是否可以执行某些精细动作

如果这个模块工作不正常，决策系统可能无法正确判断楼层和台阶状态，导致任务执行失败。

## 注意事项

### 初始标定

模块需要在机器人首次稳定时标定初始高度。如果机器人在标定完成前就移动，初始高度可能不准确。确保机器人启动后在稳定位置停留一段时间，让模块完成初始标定。

### 台阶高度设置

台阶高度参数必须与实际环境匹配。如果设置错误，楼层识别会不准确。比如，如果实际台阶是25厘米，但参数设置为20厘米，模块可能无法正确识别楼层。

### 稳定性判断

稳定性判断需要一定的时间窗口。如果机器人移动很快，可能在模块判断出稳定之前就已经移动了。这可能导致楼层识别延迟或不准确。

### 传感器精度

模块依赖里程计的高度精度。如果里程计的高度精度不高，楼层识别可能不准确。确保上游里程计系统能够提供准确的高度信息。

## 常见问题

### 楼层识别不准确

如果楼层识别不准确，可能的原因包括：
- 台阶高度参数设置不正确
- 里程计高度精度不够
- 容差设置不合适
- 初始高度标定不准确

### 稳定性判断错误

如果稳定性判断经常错误，可能的原因包括：
- 稳定时间窗口设置不合适
- 高度或角度容差设置不合适
- 里程计数据频率太低
- 机器人实际就处于不稳定状态

### 台阶变化检测延迟

如果台阶变化检测延迟较大，可能的原因包括：
- 确认时间设置太长
- 稳定性判断过于严格
- 里程计数据频率太低

## 技术细节

### 稳定性窗口算法

模块使用滑动窗口来存储最近一段时间内的数据。当新数据到达时，会添加到窗口末尾，并移除超出时间窗口的旧数据。然后计算窗口内数据的高度方差、变化率等指标，综合判断是否稳定。

### 楼层量化算法

模块将连续的高度值量化为离散的楼层数：
- 计算相对于初始高度的高度差
- 除以台阶高度，得到楼层数的小数值
- 四舍五入到最近的整数
- 如果当前高度距离某个量化楼层的距离小于容差，就认为在这个楼层

### 楼层变化检测

模块使用状态机来检测楼层变化：
- **稳定状态**：当前楼层没有变化
- **过渡状态**：检测到可能的新楼层，但还需要确认
- 当进入过渡状态时，记录进入时间
- 如果在确认时间内楼层值一直保持在新值，就认为楼层真的变化了
- 如果楼层值在确认时间内又变回原值，就认为这是误判

### 错误处理

模块会处理各种异常情况：
- **时间戳回退**：如果检测到时间戳回退，会清空窗口，重新开始
- **TF查询失败**：如果查询坐标变换失败，会发出警告，但不会影响高度计算（如果里程计数据已经在正确的坐标系下）
- **初始标定前使用**：在初始高度标定完成前，不会发布楼层信息，避免错误数据

## 性能特点

模块设计充分考虑了实时性和准确性：
- **滑动窗口**：高效的内存使用，只存储必要的数据
- **状态机**：清晰的逻辑流程，易于理解和调试
- **容差机制**：对传感器噪声和误差有良好的鲁棒性
- **确认机制**：避免因传感器抖动导致的误判
